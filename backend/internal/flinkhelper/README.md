# flinkhelper

## Overview
The process BeziSync injects into every container of a Flink CDC pipeline
(`bezisync engine flink-cdc jobmanager|taskmanager`, copied in with `bezisync install-self`).
On a TaskManager it builds the pipeline's classpath and `exec`s Flink's TaskManager. On the
JobManager it starts Flink, waits for the TaskManagers, submits the pipeline restoring the
requested saved position, stores the newest completed checkpoint it sees on each poll encrypted
in BeziSync's state database, serves health/status to the controller, and on SIGTERM stops with a savepoint it
stores. The controller (`internal/controller/flinkcdc.go`) reads its `Status`.

## Interface
- `[run.go:RunJobManager]` / `[run.go:RunTaskManager]` — role entry points; `[run.go:InstallSelf]` copies the running binary to `DIR/bezisync`; `[run.go:RESTBase]`.
- `[settings.go:Settings]` / `[settings.go:LoadSettings]` — `settings.json` (`pipeline_id`, `short_id`, connectors, drivers, TaskManagers, `restore`, `restore_after`, `fresh_start`, `allow_non_restored`, state dir, `keep_checkpoints`, health port, stop timeout); container path constants `[settings.go:DefaultConfigDir]` etc.
- `[layout.go:Layout]` / `[layout.go:DefaultLayout]` — where the image keeps Flink (`/opt/flink`, `/opt/flink-cdc/{lib,connectors,drivers}`) and the work dirs; `Prepare` (lib links, conf copy, keystore, console-only log4j), `LibDir`, `ConfDir`, `DynamicProperties` (`flink-conf.yaml` as `-D key=value` pairs), `Classpath`, `Env`, `KeystorePath`; `[layout.go:SecretSettingsFile]`.
- `[jobmanager.go:JobManager]` — the JobManager lifecycle (`Run`, `Status`); `[jobmanager.go:Status]` and the `Phase*` constants (`[jobmanager.go:PhaseRunning]` …) served at `/bz/status`; `[jobmanager.go:StateStore]` and `[jobmanager.go:Launcher]` seams for tests.
- `[jobmanager.go:RenderSecrets]` — fills `${BZ_…}` placeholders in `pipeline.yaml` as quoted YAML scalars, only on lines whose whole value is one (`placeholderLine`); a `$` anywhere else is left as written.
- `[health.go:JobManager.Health]` / `[health.go:JobManager.ServeHealth]` — `/q/health`, `/q/health/ready`, `/q/health/live` (Debezium Server's paths) and `/bz/status`.
- `[rest.go:REST]` / `[rest.go:NewREST]` — Flink REST client: `TaskManagers`, `Jobs`, `Job`, `Checkpoints`, `Exceptions`, `StopWithSavepoint`, `Cancel`, `SubtaskMetrics`, `MetricNames`; `[rest.go:ErrSavepointFailed]`.
- `[store.go:Store]` / `[store.go:OpenStore]` — encrypted saved positions: `Save`, `List`, `LatestAfter`, `Extract`, `Prune`, `Close`; `[store.go:Saved]`, `[store.go:TableName]`, `[store.go:StateSchema]`, `[store.go:MaxStateBytes]`, `[store.go:ErrStateTooLarge]`.

## Invariants
- Settings are checked on load: `short_id` is 12 hex chars, at least one connector, connector/driver names match `^[a-z0-9][a-z0-9-]*$` (they become file paths), `state_dir` absolute; defaults: 1 TaskManager, `/state`, keep 5 checkpoints, health port 8080, 90 s stop timeout (`[settings.go:check]`).
- Connectors load from Flink's classpath (`FLINK_LIB_DIR` = `LibDir`), never per job; a missing Flink, a missing or duplicate `flink-cdc-dist-*.jar`, a missing connector JAR or required driver is an error that says how to fix the image (`[layout.go:Prepare]`), which the JobManager reports as `config_error` with code `image` (`[jobmanager.go:JobManager.Run]`). Every driver JAR in the image is linked, not only the requested ones.
- Other phase/code pairs the controller sees: `config_error`/`jobmanager` when Flink's JobManager does not start (`[jobmanager.go:JobManager.Run]`); `starting`/`state_store` while the state database is unreachable (`[run.go:openStoreRetrying]`); `failed`/`restore` when the requested or latest saved position cannot be loaded (`[jobmanager.go:JobManager.lifecycle]`). If the Flink JobManager process exits, `Run` returns an error and the helper process ends.
- The helper does not allow-list Flink settings: `flink-conf.yaml` and `flink-secrets.conf` are only checked to be `key: value` lines with no whitespace in the key (`[layout.go:settingLines]`); which keys and values are allowed is decided where BeziSync writes them (the engine settings registry and the compiler).
- Secrets never go on a command line: secret Flink settings are appended to the private `config.yaml` from `flink-secrets.conf` (`[layout.go:appendSecretSettings]`), and `pipeline.yaml` secrets are rendered only into a 0600 work-dir file that is removed after the submit (`[jobmanager.go:submit]`). Each substituted value is a JSON-quoted scalar so it cannot add YAML keys (`[jobmanager.go:quoteScalar]`).
- Saved state is tar.gz, sealed with AES-256-GCM (random nonce, the relative path as associated data), its SHA-256 checked on extract; sealed size over `MaxStateBytes` (64 MiB) is refused (`[store.go:Save]`, `[store.go:Extract]`). The key is 32 base64-encoded bytes (`[store.go:OpenStore]`).
- Archive paths must stay under the state dir (`[store.go:validRel]`); extraction rejects any entry type other than directories and regular files, and truncates each file at 4 × `MaxStateBytes` (`[store.go:unarchive]`).
- `restore`: `""` starts fresh, `latest` takes the newest stored state with id above `restore_after` (Start over floor), otherwise a numeric stored id (`[jobmanager.go:restorePoint]`, `[jobmanager.go:latestPoint]`). With `latest` and nothing to restore, the job starts fresh only when `fresh_start` is set (BeziSync planned that start, ADR 0012); otherwise the helper stops with `failed`/`no_position` and submits nothing, at the first start and after a failed job alike (`[jobmanager.go:JobManager.mayStart]`). A restore submits with `-s file://<dir> -cm no_claim`, plus `-n` when `allow_non_restored` is set (`[jobmanager.go:submit]`).
- Each poll stores the newest completed checkpoint once (checkpoints that complete between two polls are not stored; one whose path is outside `state_dir` is skipped; a failed save is reported in `store_error` and skips pruning), then deletes every non-`kept` checkpoint outside the newest `keep_checkpoints` checkpoints (a `kept` one still takes a slot); savepoints are never pruned here (`[jobmanager.go:storeCheckpoint]`, `[store.go:Prune]`).
- Known non-healing failures (destination mismatch/missing, replica identity, transform errors; Oracle's version banner, a renamed or dropped column, ANALYZE refused, the flush table missing, no table found) cancel the job before reporting `failed` (`[jobmanager.go:fatal]`, `[jobmanager.go:watch]`). The schema-registry start-up race (the job restarting or failing while it has either no completed checkpoint or no written record yet) is cancelled and resubmitted at most `maxResubmits` (3) times, then reported `failed` with code `schema_registry` (`[jobmanager.go:schemaRace]`); a job that exhausts Flink's restarts (`failed`/`job_failed`) or is cancelled outside BeziSync (`failed`/`job_cancelled`) is resubmitted from the latest stored state (`[jobmanager.go:JobManager.watch]`), and a failed submit (`failed`/`submit`) is retried from the same point, both with one backoff doubling from 30 s up to 10 min (`[jobmanager.go:lifecycle]`).
- Readiness is UP only when phase is `running`, the job is `RUNNING` and every wanted TaskManager is registered (`[health.go:JobManager.Health]`).
- On SIGTERM a `RUNNING` job is stopped with a canonical savepoint under `state_dir/sp`, `drain: false`, within `stop_timeout_seconds`; on failure the newest checkpoint is stored instead (`[jobmanager.go:stop]`, `[rest.go:StopWithSavepoint]`, polled every 500 ms). The savepoint is stored as kind `savepoint`, reason `stop`, `flink_id` 0.

## Side Effects
- PostgreSQL (state database): `CREATE SCHEMA IF NOT EXISTS debezium_state`, `CREATE TABLE IF NOT EXISTS debezium_state.flink_state_<short_id>`; inserts rows (`[store.go:Save]`) and deletes pruned checkpoints (`[store.go:Prune]`) there. At most 2 connections, 15 s connect timeout, retried every 5 s while unreachable (`[run.go:openStore]`, `[run.go:openStoreRetrying]`).
- Env vars read: `BZ_STATE_DSN`, `BZ_STATE_USER`, `BZ_STATE_PASSWORD`, `BZ_STATE_KEY` (`[run.go:openStore]`), `JAVA_HOME` (`[run.go:execLauncher.Submit]`), every `BZ_*` referenced by `pipeline.yaml`.
- Processes: runs `bin/jobmanager.sh start-foreground` (SIGTERM then kill after 20 s) and the Flink CDC `CliFrontend` client with a 5 min timeout (`[run.go:execLauncher]`); `exec`s `bin/taskmanager.sh start-foreground` (`[run.go:RunTaskManager]`). Flink's scripts and client get `FLINK_HOME`, `FLINK_LIB_DIR`, `FLINK_CONF_DIR` (`[layout.go:Layout.Env]`).
- Files: recreates `WorkDir/lib` (symlinks) and `WorkDir/conf` (image conf copied, secret settings appended to `config.yaml`, `log4j-console.properties`), writes `keystore.p12`, the rendered `pipeline.yaml` (0600, removed), restored state archives under `state_dir`; `InstallSelf` writes `DIR/.bezisync.tmp` (0755) and renames it to `DIR/bezisync`. Reads `ConfigDir/settings.json`, `flink-conf.yaml`, `pipeline.yaml`, the optional `SecretsDir/keystore.p12.b64` and `flink-secrets.conf`, and the image's Flink `conf`.
- Network: HTTP to the local Flink REST API (`127.0.0.1:8081`, 15 s timeout, 8 MiB response cap); listens on `health_port` (`[health.go:JobManager.ServeHealth]`, 5 s header timeout, 2 s shutdown).
- Goroutines: the health server, the job lifecycle loop (waits for TaskManagers polling every 1 s, then watches the job every 5 s by default), a waiter on the JobManager process; logs to stderr with the `bezisync-helper:` prefix (`[jobmanager.go:logf]`).
