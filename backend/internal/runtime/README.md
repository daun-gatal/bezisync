# runtime

## Overview
The drivers for where pipeline workloads run: a Docker Engine (local or remote, optional TLS) and a Kubernetes namespace (in-cluster, kubeconfig, or GKE/EKS bearer tokens minted in process). Drivers are idempotent and level-based: `Apply` makes the runtime match a `Workload` (replacing it when the config hash changes) and `Observe` reports what is there, so the [controller](../controller/README.md) and the [agent](../agent/README.md) call them every tick. Drivers are built from runtime rows by `services.BuildDriver`; the agent-backed driver (`services.AgentDriver`) lives in [services](../services/README.md), not here.

## Interface
- `[runtime.go:Driver]` — `Apply`, `Delete`, `Observe`, `Logs`, `HTTPGet`, `Test`, `ListWorkloads`, `Capacity`; `[runtime.go:ComponentLogs]` adds `LogsOf` for Flink CDC components (`jobmanager`, `taskmanager-<n>`, `tunnel`).
- `[runtime.go:Workload]` — the desired workload; its JSON tags are the agent wire protocol; helpers `IsFlink`, `StopGrace` (0 → 30 s), `Health` (0 → 8080), `ResourceName` (`bz-<id>`), `Normalize`. `[runtime.go:FlinkTopology]` is a Flink CDC cluster (JobManager, TaskManagers, helper image, config files, state size). Engine settings are validated and rendered outside this package: drivers receive the result (`Workload.Properties`, `FlinkTopology.Config` with `settings.json`, `flink-conf.yaml`, `pipeline.yaml`) and never interpret it.
- `[runtime.go:Observation]`, `[runtime.go:TestResult]`, phase constants (`[runtime.go:PhaseRunning]` …), labels `[runtime.go:Label]`, `[runtime.go:ManagedBy]`, `[runtime.go:Owner]`, `[runtime.go:RoleLabel]`, Flink paths (`[runtime.go:FlinkOptDir]`, `[runtime.go:FlinkUID]`), `[runtime.go:FeatureFlinkCDC]`, `[runtime.go:FeatureReadonlyDestinationChecks]` (ADR 0016: an agent without it gets no Iceberg, JDBC, StarRocks/Doris/OceanBase or Elasticsearch check).
- Placement profiles (Kubernetes): `[placement.go:Placement]` (node selector, `[placement.go:Toleration]`s, priority class, pod labels) travels in `Workload.Placement`; `[placement.go:ValidatePlacement]`, `[placement.go:Placement.Accepts]` (does a `[placement.go:NodeInfo]` with its `[placement.go:Taint]`s fit), `[placement.go:NodesOf]` (the `nodes` a capacity report lists, at most `[placement.go:MaxReportedNodes]`), `[placement.go:MaxPlacementProfiles]`, `[placement.go:FeaturePlacement]` (agents that apply placement report it).
- `[runtime.go:Error]` / `[runtime.go:Errorf]` — runtime failures whose message is safe to show users.
- `[runtime.go:JVMEnv]` — workload env plus `JAVA_OPTS` (`-Xmx<heap> -XX:+ExitOnOutOfMemoryError`), `JMX_EXPORTER_PORT=9404`, `ENABLE_DEBEZIUM_SCRIPTING=true`; `[runtime.go:Architectures]` normalizes `x86_64`/`aarch64`.
- `[docker.go:DockerDriver]` / `[docker.go:NewDocker]` — one container `bz-<id>` per pipeline (plus `bz-<id>-tunnel`); `[docker.go:DockerTLS]` (PEM `CA`, `Cert`, `Key`, `Verify`) is its TLS argument; helpers `[docker.go:CPUNano]`, `[docker.go:MemBytes]`, `[docker.go:ParseDockerTime]`, `[docker.go:DefaultPullTimeout]`.
- `[docker_flink.go:DockerDriver.applyFlink]` / `[docker_flink.go:DockerDriver.recreateFlink]` — Flink CDC on Docker: private network `bz-<id>-net`, `-opt` and tmpfs `-state` volumes, JobManager `bz-<id>`, TaskManagers, optional tunnel; `[docker_flink.go:DockerDriver.LogsOf]` reads one component (`taskmanager-<n>` for n 1–64).
- `[kubernetes.go:KubernetesDriver]` / `[kubernetes.go:NewKubernetes]` / `[kubernetes.go:NewKubernetesFromClient]` — Debezium: one Deployment + ConfigMap + Secrets `bz-<id>`, `bz-<id>-files` per pipeline; `[kubernetes_flink.go:KubernetesDriver.LogsOf]` reads `jobmanager`, `taskmanager-<n>` (n-th pod by age) and `tunnel`; `[kubernetes.go:TokenRESTConfig]` with a `[kubernetes.go:TokenSource]`; `[kubernetes.go:QuantityCPU]`, `[kubernetes.go:QuantityMem]`, `[kubernetes.go:TunnelProbeCommand]`.
- `[kubernetes_flink.go:FlinkJobManagerHost]`, `[kubernetes_flink.go:FlinkRPCPort]`, `[kubernetes_flink.go:FlinkBlobPort]` — Flink CDC on Kubernetes (JobManager and TaskManager Deployments, `bz-<id>-jm` Service).
- `[cloudauth.go:GKETokenSource]`, `[cloudauth.go:EKSToken]`, `[cloudauth.go:EKSTokenSource]`, `[cloudauth.go:EKSTokenLifetime]` — managed-Kubernetes tokens without exec plugins.

## Invariants
- Workloads are found by labels: `Label` = short id, `ManagedBy` = `bezisync`, and `Owner` = runtime id when set (`[docker.go:labelsWithOwner]`, `[kubernetes.go:KubernetesDriver.labels]`), so agents sharing a host or namespace only list and prune their own (`ListWorkloads(owner)`).
- Docker replaces a container only when its `app.bezisync.io/config-hash` label differs, and only after every image it needs is on the daemon (`[docker.go:DockerDriver.Apply]`); downloads run in the background once per ref, bounded by the pull timeout, and a failed pull is reported for `pullRetryAfter` (2 min) before retrying (`[docker.go:DockerDriver.ensureImage]`).
- Docker Flink CDC is replaced when the exact container set (JobManager, N TaskManagers, optional tunnel) does not all carry the config hash (`[docker_flink.go:DockerDriver.flinkCurrent]`): images first, then an ordered stop, then on a later pass containers and both volumes are recreated, so the tmpfs state is lost and only the position stored by the JobManager survives (`[docker_flink.go:DockerDriver.recreateFlink]`); tunnel, JobManager and TaskManagers then start in that order.
- Kubernetes rolls the pod by the config-hash pod annotation with a `Recreate` strategy; `Running=false` scales to 0 replicas (`[kubernetes.go:KubernetesDriver.Apply]`).
- Hardening: Docker containers get `no-new-privileges`; Flink CDC containers also drop all capabilities, run read-only with a private `/tmp` (`[docker_flink.go:DockerDriver.createFlinkContainer]`), secrets files 0600 (`[docker_flink.go:flinkTar]`). Kubernetes Debezium pods run as uid 185, non-root, all capabilities dropped, no privilege escalation, `RuntimeDefault` seccomp, no service links; Kubernetes Flink CDC pods run as uid/gid 9999 (`FlinkUID`, the helper copy as 10001) with a read-only root filesystem and size-limited emptyDirs, `/state` in memory (`[kubernetes_flink.go:KubernetesDriver.flinkDeployment]`). The Docker Flink CDC tunnel is also capability-free and read-only (`[docker_flink.go:DockerDriver.flinkTunnel]`); the Docker helper copy runs as root with no network and no capabilities (`[docker_flink.go:DockerDriver.installHelper]`). On Kubernetes the SSH tunnel is a native sidecar (`ssh-tunnel`) on every pod, Flink CDC pods included, running as uid 10001 (`[kubernetes.go:tunnelSidecar]`). Kubernetes main containers get a memory limit equal to their request and no CPU limit; the `ssh-tunnel` sidecar requests 64Mi with a 128Mi limit and the Flink CDC `install-helper` init container 64Mi with a 512Mi limit (the page cache of the copied binary counts against it); quantities go through `resource.MustParse`, so `Apply` panics on an empty or invalid CPU, memory or state size instead of returning an error (`[kubernetes.go:KubernetesDriver.Apply]`, `[kubernetes_flink.go:KubernetesDriver.flinkDeployment]`).
- Flink CDC stop order: the JobManager first within `Workload.StopGrace` (default 30 s) so it saves its position, then TaskManagers and tunnel; on Docker this runs in the background and `Observe` reports it (`[docker_flink.go:DockerDriver.startStop]`), on Kubernetes the JobManager is scaled to 0 and TaskManagers are touched only once its pod is gone (`[kubernetes_flink.go:KubernetesDriver.applyFlink]`, `[kubernetes_flink.go:KubernetesDriver.jobManagerQuiet]`), keeping no state between calls; pods get `TerminationGracePeriodSeconds` = grace + 10, and `Delete` waits up to that period + 30 s (`StopGrace` + 40 s) for the JobManager pod to go, then deletes every object even if it is still there (`[kubernetes_flink.go:KubernetesDriver.deleteFlink]`). On Docker, `Delete` is synchronous: it waits for a background stop already running, or else stops inline (JobManager with grace + 30 s, then each TaskManager and the tunnel with 10 + 30 s each), and only then removes the containers, both volumes and `bz-<id>-net` (`[docker_flink.go:DockerDriver.deleteFlink]`). A Debezium container on Docker stops with a fixed 30 s timeout (its tunnel 10 s), not `StopGrace` (`[docker.go:DockerDriver.stop]`), when `Running=false`; when its config hash changes or it is deleted, it and its tunnel are force-removed with no graceful stop (`[docker.go:DockerDriver.remove]`, `[docker.go:DockerDriver.Apply]`, `[docker.go:DockerDriver.Delete]`); a Debezium pod on Kubernetes likewise has a fixed 30 s termination grace (`[kubernetes.go:KubernetesDriver.Apply]`).
- Secrets: on Kubernetes the workload env (which carries secrets) lives in Secret `bz-<id>` and files in `bz-<id>-files`, never in the ConfigMap; Debezium's Secret holds `JVMEnv(w)`. For Flink CDC the env goes to the JobManager only, on Kubernetes (`[kubernetes_flink.go:KubernetesDriver.flinkDeployment]`, where each tunnel sidecar takes only `BZ_SSH_KEY` from the Secret) and on Docker (`[docker_flink.go:DockerDriver.recreateFlink]`). Docker file modes: Debezium secret files 0440 uid 185, `application.properties` 0444 (`[docker.go:tarMany]`, `[docker.go:tarFile]`).
- Health/metrics are read without a network path: Docker runs `curl` in the container (`[docker.go:DockerDriver.HTTPGet]`), Kubernetes uses the API server's pod proxy (`[kubernetes.go:KubernetesDriver.HTTPGet]`).
- `[kubernetes.go:KubernetesDriver.Test]` needs create on deployments/configmaps/secrets, list pods, get pods/log and pods/proxy; permission to create Services only decides `flink_cdc` in the details (Flink CDC needs a JobManager Service).
- Placement values are taken literally, never expanded (`${` and `{{` are refused), and a profile can never set BeziSync's own pod labels (`[placement.go:ValidatePlacement]`). The Kubernetes driver applies a profile to every Deployment of the pipeline (`[placement.go:applyPlacement]`). An agent without `FeaturePlacement` would ignore it, so preflight refuses an agent that has reported a version without that feature; an agent runtime that has never polled is not refused (`services/placement.go`).
- A Kubernetes workload whose Deployment has no pod is pending with `[kubernetes.go:ReasonNoPod]`, or, when its ReplicaSet reported `ReplicaFailure` (a ResourceQuota exceeded, an admission webhook), with `[kubernetes.go:ReasonRefusedPrefix]` and Kubernetes' message (300 characters at most; `[kubernetes.go:noPodReason]`); a Flink CDC cluster whose TaskManager Deployment is refused says so in the reason (`TaskManagers: …`) while the JobManager reports none.
- Docker capacity reports the host as `node_cpu_max`/`node_memory_max` and no `nodes` list (`[docker.go:DockerDriver.Capacity]`). Kubernetes capacity reports the largest schedulable node (`node_cpu_max`, `node_memory_max`), the `nodes` list used for placement and packing, and the namespace's ResourceQuota headroom (`quota`, `quota_cpu_free`, `quota_memory_free`; `[kubernetes.go:KubernetesDriver.quota]`). Nothing is reported when quotas can't be read, and `quota: false` means the namespace has none.
- Bearer tokens are refreshed 120 s before expiry (`[kubernetes.go:refreshMargin]`); `TokenRESTConfig` mints the first token immediately so errors surface at once. Credential errors expose only an error class or type name (`[cloudauth.go:errName]`, `[cloudauth.go:EKSToken]`); EKS URLs are presigned for 60 s (`[cloudauth.go:addExpires]`).

## Side Effects
- Docker Engine API: create/start/stop/remove containers, copy `application.properties` and secret files in, image pulls, networks and volumes (Flink CDC), a short-lived `bz-<id>-install` container that copies the helper into the `-opt` volume (`[docker_flink.go:HelperInstallTimeout]`, 2 min, `[docker_flink.go:DockerDriver.installHelper]`), `docker exec curl`. Every call but image pulls, Flink CDC stops and the helper-install `ContainerWait` goes through the client with a 30 s request timeout (`[docker.go:requestTimeout]`); those three use the untimed client under their own deadline.
- Kubernetes API: Secrets, ConfigMaps, Deployments, Services, SelfSubjectAccessReviews, pod lists, pod logs and pod proxy; node and ResourceQuota reads for `Capacity`. Flink CDC `Delete` blocks, polling every 2 s (`[kubernetes_flink.go:flinkPoll]`), until the JobManager pod is gone or its deadline passes. On Docker, Flink CDC `Delete` blocks too, for the ordered stop.
- Cloud: Google OAuth token endpoint (GKE), AWS STS presign (EKS, signed locally; `sts.<region>.amazonaws.com`).
- Goroutines: background image pulls and Flink CDC stops on Docker, detached from the caller's cancellation (`context.WithoutCancel`).
- Env: Docker client `client.FromEnv` when no host is set; Kubernetes default kubeconfig loading rules; AWS/Google default credential chains when no key is given.
