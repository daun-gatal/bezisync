# connectors

## Overview
The connector protocol and every source and sink type BeziSync supports. Each file
implements `Source` or `Sink` for one type (connection checks, discovery, Debezium properties,
Flink CDC blocks, preparing and cleaning up what BeziSync owns on the source or destination,
signals, canary, read-back) and registers itself in `init`. `descriptors.json` holds each
type's descriptor (title, presets, capability flags, capture/sink caps) and its config and
secret JSON Schemas, which the UI renders and `schemaval` validates. Services, the compiler,
the controller and agents call connectors only with already-resolved (decrypted) connections.

## Interface
- Protocol: `[connectors.go:Connector]`, `[connectors.go:Source]`, `[connectors.go:Sink]`; defaults `[connectors.go:BaseSource]` / `[connectors.go:BaseSink]` (no-op prepare/cleanup/forget, `Probe` returns nil, no secret files, `ErrNotSupported` for signals, canary, Tail; default `RoutePattern`/`TopicPattern` on `<prefix>.<schema>.<table>`); `[connectors.go:ErrNotSupported]` / `[connectors.go:IsNotSupported]`.
- Optional interfaces: `[oracle_flinkchecks.go:FlinkSourceChecker]` (a source's own Flink CDC preflight checks, given `[oracle_flinkchecks.go:FlinkCheckFacts]`; Oracle's: version banner, ANALYZE rights and locked statistics, the CDB-root flush table, `[oracle_flinkchecks.go:FlinkDebeziumOnlyChecks]` lists the Oracle source checks only Debezium needs), `[connectors.go:SourceFiler]`, `[connectors.go:ManagedTopics]`, `[connectors.go:Namer]`, `[sinkcaps.go:DestinationNamer]`, `[sinkcaps.go:PipelineChecker]`, `[sinkcaps.go:DeliveryDelayer]`, `[sinkcaps.go:SinkReleaser]`, `[flinkcdc.go:FlinkSource]`, `[flinkcdc.go:FlinkSink]`.
- Inputs/outputs: `[connectors.go:Resolved]` (decrypted connection, `Linked` connections), `[connectors.go:CompileContext]` (`Prefix` = `bz_<short id>`, `Destination`), `[connectors.go:ArtifactResult]`, `[connectors.go:SourceImpact]` / `[connectors.go:TimeWindowImpact]`, `[connectors.go:Discovery]` / `[connectors.go:NewDiscovery]` / `[connectors.go:TableInfo]` / `[connectors.go:Column]`, `[connectors.go:TailRecord]`.
- Registry and descriptors: `[connectors.go:Register]`, `[connectors.go:Get]`, `[connectors.go:GetSource]`, `[connectors.go:GetSink]`, `[connectors.go:Describe]`, `[connectors.go:Descriptors]`, `[connectors.go:Descriptor]`, `[connectors.go:CaptureCaps]` (`DebeziumMode`), `[connectors.go:TransformCaps]` (`CanMask`), `[connectors.go:CanarySources]`.
- Sink capabilities: `[sinkcaps.go:SinkCaps]` (`CheckNaming`, `CheckDestinations`, `CheckTransforms`, `Options`, `EventFormat`), `[sinkcaps.go:NamingRules]`, `[sinkcaps.go:UnwrapRule]`, `[sinkcaps.go:SinkImage]`, `[sinkcaps.go:SinkOptions]`, `[sinkcaps.go:SinkImageFor]`, `[sinkcaps.go:InSinkImageFamily]`, `[sinkcaps.go:HealthPort]`, `[sinkcaps.go:DeliveryDelay]`, `[sinkcaps.go:SinkDestination]`, `[sinkcaps.go:GetSinkPipelineChecker]` / `[sinkcaps.go:PipelineFacts]`, `[sinkcaps.go:ImageRepository]`, `[sinkcaps.go:ResourceRank]`, `[sinkcaps.go:DefaultNaming]`, `[sinkcaps.go:DefaultHealthPort]`.
- Network and SSH: `[connectors.go:NetworkCheck]` (SSRF-guarded TCP probe → `<code>_blocked|_unreachable|_reachable`), `[ssh.go:SSHOf]`, `[ssh.go:Tunnel]` (short-lived local forward), `[ssh.go:Serve]` / `[ssh.go:ServeOn]` (the `bezisync tunnel` sidecar), `[ssh.go:SSHChecks]`, `[ssh.go:TunnelPort]`, `[ssh.go:SSHConfig]`, `[ssh.go:TunnelError]`.
- Flink CDC: `[flinkcdc.go:FlinkBlock]`, `[flinkcdc.go:FlinkOptions]`, `[flinkcdc.go:FlinkEndpoint]`, `[flinkcdc.go:FlinkTableNames]`, `[flinkcdc.go:MyServerIDRange]`; source blocks for MySQL, PostgreSQL, SQL Server in `flinkcdc.go` and Oracle in `oracle_flink.go` (`[oracle_flink.go:FlinkReadsOracleBanner]`, the version banners Flink CDC's Oracle reader can read; `[oracle_flink.go:OraFlushTable]`); `[flinkcdc.go:FlinkSourceIgnores]` (raw source options a Flink reader would ignore: Oracle's `jdbc.properties.*`), Iceberg in `iceberg_flink.go`, StarRocks/Doris/Fluss in their files. Iceberg `partition_by` (both engines): `[iceberg_partition.go:IcebergPartitionBy]` (table → `[iceberg_partition.go:PartitionField]`s, compiled into `partition.key` per destination) and `[iceberg_partition.go:TablePartitioning]` (a live table's spec, for the `iceberg_partition_existing` check). `FlinkSource.FlinkTableID` names a spec table's Flink CDC events (MySQL, PostgreSQL and Oracle the table as given, SQL Server with the database) for routes and transforms (`[flinkcdc.go:FlinkSource]`).
- Source limits for settings checks: `[connections.go:ConnectionCounter]` (PostgreSQL and MySQL report allowed and open connections; other sources are Unknown); `[postgres.go:PGCapacity]` / `[postgres.go:ParsePGCapacity]` read the `pg_capacity` check (replication slots and WAL senders used and allowed).
- Helpers: `[helpers.go:ValidateConfig]` / `[helpers.go:ValidationError]`, `[helpers.go:ConfigExpressions]` / `[helpers.go:RefuseConfigExpressions]` (settings holding `${`, refused on save and at compile), config readers `[connectors.go:Str]` / `OptStr` / `Int` / `Bool` / `[connectors.go:PyStr]`, `[connectors.go:JavaRegexLiteral]`, `[connectors.go:TopicSafe]`, `[connectors.go:HumanSeconds]`, `[connectors.go:LooksLikePII]` / `[connectors.go:PIIHints]`, quoting `[postgres.go:QuoteIdent]` / `[oracle.go:OraIdent]`, `[postgres.go:Salt]` / `[postgres.go:ColumnRules]` (masking), `[postgres.go:PyDumps]` (signal payloads), `[postgres.go:PgOperationalError]`, `[mysql.go:MyServerID]`, `[kafka.go:ParseBootstrap]` / `[kafka.go:KafkaClientProps]`, `[mongodb.go:MongoConnectionString]`; driver error wrappers `[mysql.go:MyOperationalError]`, `[sqlserver.go:MsError]`, `[oracle.go:OraOperationalError]`; secret-file constants `[pubsub.go:SecretDir]` (`/debezium/secrets`, re-exported by the compiler) and `[pubsub.go:PubSubKeyFile]`; `[pubsub.go:PubSubCheckTimeout]` (10 s, tests shorten it).
- Injected hook: `[mysql.go:OffsetsReader]` reads a pipeline's stored Debezium offsets; `internal/services` sets it (avoids an import cycle) and MySQL, SQL Server, Oracle, CockroachDB, Vitess and Spanner use it in `Probe` (source impact); when unset those fields stay unknown.
- Sources: `[postgres.go:postgresSource]`, `[mysql.go:mysqlSource]` (+ MariaDB preset), `[sqlserver.go:sqlserverSource]`, `[mongodb.go:mongoSource]`, `[oracle.go:oracleSource]`, `[cockroachdb.go:cockroachSource]`, `[vitess.go:vitessSource]`, `[spanner.go:spannerSource]`.
- Sinks: `[kafka.go:kafkaSink]`, `[http.go:httpSink]`, `[pubsub.go:pubsubSink]`, `[kinesis.go:kinesisSink]`, `[redis.go:redisSink]`, `[nats.go:natsSink]`, `[iceberg.go:icebergSink]`, `[jdbc.go:jdbcSink]`, `[sqs.go:sqsSink]`, `[sns.go:snsSink]`, `[eventhubs.go:eventHubsSink]`, `[pulsar.go:pulsarSink]`; Flink CDC-only `[starrocks.go:starrocksSink]`, `[doris.go:dorisSink]` (shared `[olap.go:olapSink]`), `[fluss.go:flussSink]`.

## Invariants
- Every type is registered under `kind/type` from its file's `init` and must have a matching `descriptors.json` entry; a malformed descriptor file panics at start-up (`[connectors.go:Register]`, `[connectors.go:init]`). A new config field is added to the descriptor schema and read in the connector; config is validated with Pydantic semantics through `[helpers.go:ValidateConfig]`.
- `Check` returns a `checks.Report`; an `error` means an unexpected failure, not a failed check (`[connectors.go:Connector]`). Anything that would make a deploy fail is `Status: Fail, Blocking: true`, and every emitted code needs a `checks/catalog.json` entry (enforced by `internal/checks` tests).
- Connection checks reach hosts through `ssrf.TCPProbe` (`[connectors.go:NetworkCheck]`, 5 s default timeout), or the bastion first when `ssh_host` is set (`[ssh.go:SSHChecks]`). Every later dial holds the guard too, on every path (`Discover`, `Prepare`, `Cleanup`, `Signal`, `WriteCanary`, `Probe`, `Tail`, `PrepareSink`/`CleanupSink`), including addresses a server advertises ([ADR 0004](../../../docs/adr/0004-ssrf-on-every-dial.md)): `[dial.go:DialContext]` is the SSRF guard. `[ssh.go:Tunnel]` returns the dialer of one connection: the guard, or for a tunnelled one `[dial.go:tunnelDialer]`, which reaches that connection's own forward and nothing else on loopback (no connection can use another's tunnel). pgx (`[postgres.go:pgConnect]`, CockroachDB, JDBC), the MySQL driver (MySQL, Vitess, `[olap.go:olapConfig.open]`, JDBC), SQL Server, go-ora (`[oracle.go:oraConnect]`), MongoDB and NATS take it as their dialer; Kafka and Redis take `[dial.go:tlsDialer]`, which speaks TLS itself; Pub/Sub and Spanner emulator hosts take it as a gRPC dialer (`[dial.go:grpcDial]`). The HTTP sink check, Iceberg (REST and Glue), Pulsar admin use `ssrf.HTTPClient`; AWS clients (SQS, SNS, Kinesis, Iceberg) load the SDK configuration first and then take the guarded client (`[dial.go:GuardAWS]`), so the credential chain still reaches instance and pod metadata. The control plane dials an SSH bastion through the guard (`[ssh.go:dialSSH]` takes the dialer; the pipeline's sidecar passes a plain one). Event Hubs can't take a dialer: `[eventhubs.go:eventHubsGuard]` checks a connection string's endpoint before each client, which leaves a DNS answer that changes in between uncovered.
- SSH: user and private key are both required (`[ssh.go:SSHOf]`); a pinned host key is enforced with `FixedHostKey`, otherwise any key is accepted and the check warns (`[ssh.go:dialSSH]`, `[ssh.go:SSHChecks]`). The sidecar reconnects with backoff from 1 s up to 30 s (`[ssh.go:ServeOn]`).
- Identifiers in generated SQL are quoted with the dialect quoter (`[postgres.go:QuoteIdent]`, `[mysql.go:myQ]`, `[sqlserver.go:msQ]`, `[oracle.go:OraIdent]`, `[olap.go:olapQuote]`); BeziSync's own objects are named from the pipeline short id (`signal_<id>`, `canary_<id>`, slot/publication `bz_<id>`) under a `bezisync` schema/database (`[postgres.go:pgManagedSchema]`, `[mysql.go:myManagedDB]`, `[sqlserver.go:msManagedSchema]`), and the compiler filters their topics from the destination.
- Flink CDC table names must match `^[A-Za-z0-9_]+$` for both schema and table (`[flinkcdc.go:FlinkTableNames]`); Flink option values that are secrets are `${BZ_…}` placeholders with the value in `FlinkBlock.Env` (`[flinkcdc.go:FlinkBlock]`). StarRocks/Doris database names obey the same pattern (`[olap.go:cfg]`). Oracle on Flink CDC (ADR 0006): table names must be upper case (`[oracle_flink.go:oraFlinkName]`); the JDBC URL takes only a checked host, port and service (`[oracle_flink.go:oraFlinkURL]`, 422 `flink_oracle_service`); with a PDB, `database` is the CDB, `jdbc.url` the PDB's service and `debezium.database.pdb.name` the PDB (`[oracle_flink.go:FlinkSource]`).
- Oracle Prepare/Cleanup read `CompileContext.Engine`: on Flink CDC no signal or canary table; with a PDB, Prepare keeps `<user>.LOG_MINING_FLUSH` with exactly one row in the CDB root (created if missing, ORA-00955 tolerated, the row re-added when gone) and Cleanup drops nothing (the table is shared by every pipeline mining as that user) (`[oracle.go:Prepare]`, `[oracle_flink.go:prepareFlush]`, `[oracle.go:Cleanup]`). Debezium pipelines are unchanged.
- Source impact fields a source cannot measure stay nil (unknown, never fine); time-window sources are at risk at 80% of retention and lost past it (`[connectors.go:TimeWindowImpact]`).
- Sink capability defaults: naming `cdc.{schema}.{table}`, pattern `^[A-Za-z0-9._-]+$`, max 249, formats json/avro/protobuf/cloudevents, outbox allowed (`[sinkcaps.go:defaultSinkCaps]`); rendered names are checked only when the descriptor states its rules and the sink is not single-destination (`[sinkcaps.go:CheckDestinations]`); a single-format sink forces that format (`[sinkcaps.go:EventFormat]`); sinks without an options schema ignore stored options (`[sinkcaps.go:Options]`).
- PostgreSQL cleanup waits up to 60 s for the slot to go inactive and never drops an active slot; it also drops inactive leftover `bz_<id>_*` slots from Flink CDC (`[postgres.go:Cleanup]`). `ForgetPosition` refuses while the slot is active (`[postgres.go:ForgetPosition]`).
- Spanner never alters or drops a change stream the user brought (`stream_mode: existing`) (`[spanner.go:Cleanup]`); Fluss tables are never dropped (`[fluss.go:CleanupSink]`).
- Iceberg `partition_by` compiles on both engines (ADR 0005): Flink CDC's `partition.key` per destination, Debezium's `debezium.sink.iceberg.partition-by.<topic>` (`[iceberg.go:icebergPartitions]`, `[iceberg.go:debeziumPartitionBy]`: `bucket(c\,N)`, column first) keyed by the event's destination after routes (`[iceberg.go:debeziumDestinationFields]`): a listed table's fields, else the automatic default (`[iceberg_partition.go:debeziumAutomatic]`) when the tables sent there agree (none when they don't); unrouted specs keep their `config_hash`. `[iceberg_partition.go:IcebergPartitionBy]` allows only captured tables, up to four fields each (descriptor `maxItems`), `bucket[N]` with N 1–1024, `truncate[N]` with N ≥ 1, no number on any other transform, no field twice; tables routed to one destination must ask for the same partitioning (`[iceberg_partition.go:icebergPartitionKey]`). Preflight blocks a partition column the table does not write or whose written kind its transform does not take (`[iceberg_partition.go:writtenColumns]`: the engine's columns and `domain.PartitionKind`; `domain.PartitionTransforms` is Iceberg's table: no bucket of a boolean or a float) (`iceberg_partition_column`) and an existing table partitioned differently (`iceberg_partition_existing`) (`[iceberg_partition.go:partitionChecks]`). Only `catalog.ErrNoSuchTable` counts as a table to create: another catalog error, or a source that couldn't be read, makes the check a warning, never a pass. `[iceberg_partition.go:partitionKeyChecks]` (`iceberg_partition_key`, ADR 0005 R5) blocks partitioning an upserted table by a column outside the columns its upserts delete by (`[iceberg_partition.go:equalityFields]`: Flink CDC's key under its written names; Debezium's key columns the written row still carries), for Partition by and for Debezium's automatic default (what each destination gets after routes), and an existing table whose own spec is off its live identifier fields (`[iceberg_partition.go:livePartitionRisk]`: may already hold duplicates). On Flink CDC an existing table without identifier fields is blocked (`iceberg_flink_keyless_table`): 3.7.0 writes deletes and update before-images into it as rows. On Debezium `[iceberg_partition.go:icebergKeyColumnChecks]` (`iceberg_key_columns`) blocks a key column renamed or left out of the row (the identity narrows) and warns when all are. A catalog that doesn't open is passed as `[iceberg_partition.go:unreachableCatalog]`, so the table checks warn.
- The StarRocks/Doris MySQL-protocol client always connects with TLS off (`TLSConfig = "false"`), so the FE password and check and `Tail` traffic cross the network in plain text (`[olap.go:open]`); this is an accepted risk, see the [threat model](../../../docs/security/threat-model.md#residual-risks-and-operator-responsibilities) ("Unencrypted Flink CDC destinations").
- Masked-column hashes use SHA-256 with a salt derived from the pipeline id (`[postgres.go:Salt]`).

- Oracle `Probe` on Flink CDC reports only the archive's retention window and never a loss: the pipeline's SCN is inside its encrypted saved state (`[oracle.go:oraFlinkImpact]`).

## Side Effects
- Oracle on Flink CDC: Prepare creates `<user>.LOG_MINING_FLUSH` (one row) in the CDB root of a multitenant database and Cleanup leaves it (`[oracle_flink.go:prepareFlush]`); its preflight queries `V$VERSION`, `SESSION_PRIVS`, `ALL_TAB_STATISTICS`, `USER_TABLES` and `USER_TS_QUOTAS` (`[oracle_flinkchecks.go:FlinkChecks]`).
- Network: connections to user databases, brokers and cloud APIs (pgx, MySQL, SQL Server, go-ora, MongoDB, Spanner, Kafka/franz-go, AWS SDK, Pub/Sub, Event Hubs, Redis, NATS, Pulsar admin REST, Iceberg REST/Glue, StarRocks/Doris over MySQL protocol); SSH to bastions with a 30 s keepalive goroutine and per-connection forward goroutines (`[ssh.go:keepalive]`, `[ssh.go:forward]`); local listeners on `127.0.0.1:0` (checks) or `TunnelPort` 15432 (sidecar).
- Source writes (Prepare/Cleanup/Signal/WriteCanary/ForgetPosition): PostgreSQL `bezisync` schema, `heartbeat` (row deleted on cleanup), `signal_<id>`, `canary_<id>` tables, replication slot and publication drops (Debezium creates them); CockroachDB `bezisync` schema with `signal_<id>` / `canary_<id>` only; MySQL `bezisync` database, `heartbeat`, `signal_<id>`, `canary_<id>` tables; SQL Server `bezisync.signal_<id>` with CDC enabled/disabled on it; MongoDB `signal_<id>` collection; Oracle `BZ_*` signal/canary tables with supplemental logging (`DROP … PURGE` on cleanup); Spanner change stream `bz_<id>` create/alter/drop and coordination Kafka topic deletion (also on `ForgetPosition`). Only PostgreSQL, CockroachDB, MySQL and Oracle write a canary. Canary writes delete canary rows older than a day.
- Destination writes (PrepareSink/CleanupSink/ReleaseSink/Check): Kafka, Pub/Sub and Pulsar topics and Kinesis streams created on prepare only when `create_topics`/`create_streams` is set, and every destination deleted on cleanup (which runs only when a delete asks to drop destinations), whoever created it; NATS JetStream stream created/updated on prepare (no cleanup); Redis streams deleted on cleanup; SNS topics created on prepare (when `create_topics`) with a BeziSync preview SQS queue subscribed to each, topics deleted on cleanup and preview queues unsubscribed and deleted by `ReleaseSink`; JDBC/StarRocks/Doris `DROP TABLE` on cleanup; StarRocks/Doris checks run `CREATE DATABASE IF NOT EXISTS` and create/drop a `bezisync_check_*` probe table (`[olap.go:check]`); Iceberg namespace created on prepare and tables dropped on cleanup; Fluss tables are reported `retained`.
- Files: PostgreSQL and CockroachDB write a CA certificate to a temp file for the connection and remove it (`[postgres.go:pgConnect]`, `[cockroachdb.go:crdbConnect]`).
- Env/config read: `config.Get().IcebergImage` (`[sinkcaps.go:sinkImageOverride]`); `BEZISYNC_SSRF_ALLOW_CIDRS` indirectly through `ssrf`.
- Logging: the tunnel sidecar logs connect/reconnect lines via `logging.Logger("bezisync.tunnel")` (no secrets).
