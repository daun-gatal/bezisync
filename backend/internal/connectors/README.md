# connectors

## Overview
The connector protocol and every source and sink type BeziSync supports. Each file
implements `Source` or `Sink` for one type (connection checks, discovery, Debezium properties,
Flink CDC blocks, preparing and cleaning up what BeziSync owns on the source or destination,
signals, canary, read-back) and registers itself in `init`. `descriptors.json` holds each
type's descriptor (title, presets, capability flags, capture/sink caps) and its config and
secret JSON Schemas, which the UI renders and `schemaval` validates. Services, the compiler,
the controller and agents call connectors only with already-resolved (decrypted) connections.

## Invariants
- Every type is registered under `kind/type` from its file's `init` and must have a matching `descriptors.json` entry; a malformed descriptor file panics at start-up (`[connectors.go:Register]`, `[connectors.go:init]`). A new config field is added to the descriptor schema and read in the connector; config is validated with Pydantic semantics through `[helpers.go:ValidateConfig]`.
- `Check` returns a `checks.Report`; an `error` means an unexpected failure, not a failed check (`[connectors.go:Connector]`). Anything that would make a deploy fail is `Status: Fail, Blocking: true`, and every emitted code needs a `checks/catalog.json` entry (enforced by `internal/checks` tests).
- Connection checks reach hosts through `ssrf.TCPProbe` (`[connectors.go:NetworkCheck]`, 5 s default timeout), or the bastion first when `ssh_host` is set (`[ssh.go:SSHChecks]`). Iceberg (REST and Glue), Pulsar admin, SQS and SNS HTTP calls use `ssrf.HTTPClient` (`[iceberg.go:icebergSink]`, `[pulsar.go:pulsarHTTP]`, `[sqs.go:awsClientConfig]`). The HTTP sink check probes the endpoint with `NetworkCheck` and then sends its `OPTIONS` request through a plain `http.Client` (redirects not followed) (`[http.go:httpSink]`), and the Kinesis client uses a plain `http.Client` with no SSRF check of a custom `endpoint` (`[kinesis.go:kinesisClient]`); a Pub/Sub `emulator_host` is dialled over insecure gRPC with no SSRF check at all (`[pubsub.go:pubsubPublisher]`); and `dialSSH` dials the bastion with a plain `net.Dialer` after the probe (`[ssh.go:dialSSH]`) — known issue, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues).
- SSH: user and private key are both required (`[ssh.go:SSHOf]`); a pinned host key is enforced with `FixedHostKey`, otherwise any key is accepted and the check warns (`[ssh.go:dialSSH]`, `[ssh.go:SSHChecks]`). The sidecar reconnects with backoff from 1 s up to 30 s (`[ssh.go:ServeOn]`).
- Identifiers in generated SQL are quoted with the dialect quoter (`[postgres.go:QuoteIdent]`, `[mysql.go:myQ]`, `[sqlserver.go:msQ]`, `[oracle.go:OraIdent]`, `[olap.go:olapQuote]`); BeziSync's own objects are named from the pipeline short id (`signal_<id>`, `canary_<id>`, slot/publication `bz_<id>`) under a `bezisync` schema/database (`[postgres.go:pgManagedSchema]`, `[mysql.go:myManagedDB]`, `[sqlserver.go:msManagedSchema]`), and the compiler filters their topics from the destination.
- Flink CDC table names must match `^[A-Za-z0-9_]+$` for both schema and table (`[flinkcdc.go:FlinkTableNames]`); Flink option values that are secrets are `${BZ_…}` placeholders with the value in `FlinkBlock.Env` (`[flinkcdc.go:FlinkBlock]`). StarRocks/Doris database names obey the same pattern (`[olap.go:cfg]`).
- Source impact fields a source cannot measure stay nil (unknown, never fine); time-window sources are at risk at 80% of retention and lost past it (`[connectors.go:TimeWindowImpact]`).
- Sink capability defaults: naming `cdc.{schema}.{table}`, pattern `^[A-Za-z0-9._-]+$`, max 249, formats json/avro/protobuf/cloudevents, outbox allowed (`[sinkcaps.go:defaultSinkCaps]`); rendered names are checked only when the descriptor states its rules and the sink is not single-destination (`[sinkcaps.go:CheckDestinations]`); a single-format sink forces that format (`[sinkcaps.go:EventFormat]`); sinks without an options schema ignore stored options (`[sinkcaps.go:Options]`).
- PostgreSQL cleanup waits up to 60 s for the slot to go inactive and never drops an active slot; it also drops inactive leftover `bz_<id>_*` slots from Flink CDC (`[postgres.go:Cleanup]`). `ForgetPosition` refuses while the slot is active (`[postgres.go:ForgetPosition]`).
- Spanner never alters or drops a change stream the user brought (`stream_mode: existing`) (`[spanner.go:Cleanup]`); Fluss tables are never dropped (`[fluss.go:CleanupSink]`).
- Masked-column hashes use SHA-256 with a salt derived from the pipeline id (`[postgres.go:Salt]`).

## Side Effects
- Network: connections to user databases, brokers and cloud APIs (pgx, MySQL, SQL Server, go-ora, MongoDB, Spanner, Kafka/franz-go, AWS SDK, Pub/Sub, Event Hubs, Redis, NATS, Pulsar admin REST, Iceberg REST/Glue, StarRocks/Doris over MySQL protocol); SSH to bastions with a 30 s keepalive goroutine and per-connection forward goroutines (`[ssh.go:keepalive]`, `[ssh.go:forward]`); local listeners on `127.0.0.1:0` (checks) or `TunnelPort` 15432 (sidecar).
- Source writes (Prepare/Cleanup/Signal/WriteCanary/ForgetPosition): PostgreSQL `bezisync` schema, `heartbeat` (row deleted on cleanup), `signal_<id>`, `canary_<id>` tables, replication slot and publication drops (Debezium creates them); CockroachDB `bezisync` schema with `signal_<id>` / `canary_<id>` only; MySQL `bezisync` database, `heartbeat`, `signal_<id>`, `canary_<id>` tables; SQL Server `bezisync.signal_<id>` with CDC enabled/disabled on it; MongoDB `signal_<id>` collection; Oracle `BZ_*` signal/canary tables with supplemental logging (`DROP … PURGE` on cleanup); Spanner change stream `bz_<id>` create/alter/drop and coordination Kafka topic deletion (also on `ForgetPosition`). Only PostgreSQL, CockroachDB, MySQL and Oracle write a canary. Canary writes delete canary rows older than a day.
- Destination writes (PrepareSink/CleanupSink/ReleaseSink/Check): Kafka, Pub/Sub and Pulsar topics and Kinesis streams created on prepare only when `create_topics`/`create_streams` is set, and every destination deleted on cleanup (which runs only when a delete asks to drop destinations), whoever created it; NATS JetStream stream created/updated on prepare (no cleanup); Redis streams deleted on cleanup; SNS topics created on prepare (when `create_topics`) with a BeziSync preview SQS queue subscribed to each, topics deleted on cleanup and preview queues unsubscribed and deleted by `ReleaseSink`; JDBC/StarRocks/Doris `DROP TABLE` on cleanup; StarRocks/Doris checks run `CREATE DATABASE IF NOT EXISTS` and create/drop a `bezisync_check_*` probe table (`[olap.go:check]`); Iceberg namespace created on prepare and tables dropped on cleanup; Fluss tables are reported `retained`.
- Files: PostgreSQL and CockroachDB write a CA certificate to a temp file for the connection and remove it (`[postgres.go:pgConnect]`, `[cockroachdb.go:crdbConnect]`).
- Env/config read: `config.Get().IcebergImage` (`[sinkcaps.go:sinkImageOverride]`); `BEZISYNC_SSRF_ALLOW_CIDRS` indirectly through `ssrf`.
- Logging: the tunnel sidecar logs connect/reconnect lines via `logging.Logger("bezisync.tunnel")` (no secrets).
