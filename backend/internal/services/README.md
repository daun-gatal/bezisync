# services

## Overview
The business logic behind the API handlers, the MCP tools, the CLI and the controller: pipelines (versions, preflight, deploy, pause/resume, delete, offsets), connections and their secrets, external secret-store references, runtimes and the agent-backed driver, approvals, alerts and notifications, audit, the image catalog, Flink CDC secrets and saved positions, manifests, copy between projects, SSO, MCP settings and OAuth, telemetry and key rotation. Handlers in `internal/api` stay thin and call in here; the [controller](../controller/README.md) uses the same functions; the [agent](../agent/README.md) reuses `BuildDriver` and `RunCheck`. Functions take a `db.Querier`, so callers choose the transaction; the exceptions are `AgentDriver` (it uses the pool, `db.MustPool`) and the state-database helpers in `offsets.go` and `flinkcdc.go` (their own connections).

## Invariants
- Authorization is the caller's job except where checked here: `[approvals.go:RequestApproval]` requires `auth.PipelineDeploy`, `[approvals.go:Approve]`/`Reject` require `auth.PipelineApprove`, nobody approves their own request (`own_change_request`, 403), a rejection needs a comment (422 `comment_required`), and only the requester or an approver cancels (`[approvals.go:CancelChangeRequest]`). A new request supersedes the pipeline's pending one; `Approve` deploys through `Deploy`, so preflight runs again. `[copy.go:CanCopySecrets]` is Admin-only. Project lookups (`[pipelines.go:GetPipeline]`) return 404 for other projects' rows.
- Every mutation records an event via `[audit.go:Record]`; controller and system events pass `NotAudit: true`. Feedback text stays out of the audit details (`[feedback.go:SubmitFeedback]`).
- Secrets are write-only: `[connections.go:MergeSecrets]` replaces given keys, removes `null`/`""`, keeps omitted ones; `[connections.go:EncryptOrNil]` stores nothing for empty secrets; responses expose field names only (`[connections.go:SecretFieldsSet]`). `[connections.go:Resolve]` fails with `secret_missing` when a required secret was never entered and `secret_ref_unresolved` (422) when a store read fails; messages name field and store, never a value. Store values are cached 60 s per store id + version + path/key (`[connections.go:ResolveRefs]`), dropped by `ForgetStore`.
- Check reports are scrubbed of every secret value of the connection and its links before they leave (`[connections.go:RunCheck]`, `[connections.go:ScrubReport]`: `Message` and `Technical`; values shorter than 4 runes are not redacted, `[connections.go:Redact]`).
- Versions: the caller's own unsealed draft is amended in place (anyone else's edit starts a new version); `[pipelines.go:SealVersion]` freezes a version on deploy or approval request and refuses (409 `version_changed`) if it was saved after its checks. `[pipelines.go:UpdatePipeline]` answers 412 `version_conflict` on a stale version; a deployed pipeline can't be renamed or change destination, and changes runtime only while paused (409).
- Deploy: `[pipelines.go:CheckDeployable]` blocks on failed preflight (409 `preflight_failed`) unless a force reason is given, the project allows force (`force_not_allowed`, 403), and no `config`, `runtime` or `policy` check failed. `[pipelines.go:Deploy]` writes desired state only (deployed version and image, `desired_state=running`, lifecycle `deploying`), audits `pipeline.deployed` or `pipeline.deployed_forced`, and queues a `snapshot` job (20 s delay) for tables added to an already-deployed pipeline when the source supports incremental snapshots.
- Jobs are created `queued` with `MaxAttempts: 5` (`[pipelines.go:Enqueue]`); `[pipelines.go:DeletePipeline]` soft-deletes and queues `cleanup`; `[pipelines.go:Restart]` needs a running pipeline. `[pipelines.go:ResetOffsets]` needs a paused pipeline whose workload has stopped; it drops the offsets, clears `last_lsn`/`position_regressed`, and for `skip_to_now` also forgets the source position (`snapshot_override = no_data`). `[alerts.go:EvaluateProject]` seeds missing default rules, opens an alert `pending`, fires it after the rule's `ForSeconds`, and resolves it when the condition clears; firing and resolving (of a notified alert) record `alert.fired`/`alert.resolved` (`NotAudit`), notify the project's inbox and queue a `notify` job for the rule's channels and, with `NotifyOwner`, an owner email. `[alerts.go:RunNotifyJob]` is idempotent per target and alert state and returns `Retry` while any target fails.
- Outbound alert posts accept only http(s) URLs and check the host with `ssrf.ResolveChecked`, then send through a plain `http.Client` (10 s timeout) that resolves again and follows redirects (`[alerts.go:postJSON]`) — known issue, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues); webhooks are signed `x-bezisync-signature: sha256=<HMAC>` when a signing secret is set. Email goes to the configured SMTP server (15 s timeout, optional STARTTLS).
- Agent runtimes: desired workloads are stored encrypted in `agent_workloads` and rewritten only when config hash, running flag or pull settings change (`[runtimes.go:AgentDriver.Apply]`); a Flink CDC workload is refused for an agent that has reported without the `flink_cdc` feature. Health, metrics and `/bz/status` come from the agent's last report; other reads are requests. Agent requests store their args encrypted (they may carry resolved secrets) polled every 400 ms and deleted after the answer or timeout (check 60 s, logs 12 s, `http_get` its timeout + 6 s) (`[runtimes.go:AgentDriver.request]`). No poll for `AgentOfflineAfter` (30 s) makes the runtime unreachable. Direct drivers are cached per runtime id + version (`[runtimes.go:DriverFor]`).
- OAuth: PKCE S256 only, authorization requests valid 10 min, codes one-time and valid 1 min, access tokens 1 h, grants for the approved number of days, refresh rotation with reuse revoking the grant (audited `mcp.agent_revoked`); codes and tokens stored hashed; races resolved with conditional `UPDATE … RETURNING` (`[oauth.go:Refresh]`, `[oauth.go:ExchangeCode]`).
- Sign-in lockout guards: password sign-in stays in force while no provider is on (`[sso.go:PasswordLogin]`); turning it off needs a tested provider and an Admin who signed in with SSO (`[sso.go:SetPasswordLogin]`); the last enabled provider can't be turned off while passwords are off (`[sso.go:GuardLastProvider]`).
- Project policies come from `[pipelines.go:PoliciesOf]` (`domain.LoadPolicies`); stored policies that fail to parse fall back to `DefaultPolicies()`, which allows everything — known issue, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues).
- Inbox entries skip users who muted the kind (`[inbox.go:Notify]`); feedback is rate-limited per user (`ratelimit.Feedback`) and notifies every active Admin.
- MCP is off by default; tools without an entry keep their default (destructive off) (`[mcp.go:MCPSettings]`).
- Pagination is keyset over (time, id), limit clamped to 1…200, cursor `base64url(json([isoformat, id]))` (`[pagination.go:EncodeCursor]`).
- Metrics retention: raw samples older than 24 h roll into 1-minute rows, data past `MetricsRetentionDays` is deleted (`[metrics.go:EnforceMetricRetention]`).
- `[bootstrap.go:Bootstrap]` runs only when no users exist and `BEZISYNC_BOOTSTRAP_ADMIN_PASSWORD` is set; `[bootstrap.go:EnsureSandbox]` only once, when the sandbox settings are present.
- `[keys.go:RotateKeys]` re-encrypts every encrypted column not under the current master key (connections, runtimes, secret stores, alert channels, agent workloads, SSO providers, pipeline engine secrets) plus SAML keys.

## Side Effects
- DB writes: `events`, `pipelines`, `pipeline_versions`, `change_requests`, `jobs`, `connections` (incl. `last_check` from `CheckAndStore`), `secret_stores`, `runtimes` (sandbox), `agent_workloads`, `agent_requests`, `alerts`, `alert_rules` (default rules seeded on evaluation), `alert_channels` (last delivery/error), `notifications`, `metric_samples` (rollup and deletes), `feedback`, `users` and `memberships` (SSO, bootstrap), `projects`, `pipeline_templates`, `sso_requests`, `sso_replays`, `oauth_clients`/`oauth_requests`/`oauth_grants`, `instance_state` (MCP settings, sign-in settings, telemetry, SAML keys); `[keys.go:RotateKeys]` rewrites every encrypted column it lists.
- State database (separate connections): reads and drops `offsets_<id>` / `history_<id>` (`[offsets.go:ClearOffsets]`), reads, copies and deletes `flink_state_<id>` saved positions.
- Network: connector checks, discovery, previews (sources and sinks), secret-store reads (Vault, AWS, GCP, Kubernetes), Docker/Kubernetes APIs via drivers, alert delivery (Slack, webhook, PagerDuty, SMTP), weekly telemetry POST to `TelemetryURL` when enabled (10 s timeout), OIDC/SAML providers.
- Process state: driver cache and secret-store value cache (in memory); `ratelimit.Feedback` per user.
- Env via `config.Get()` (bootstrap admin, sandbox, SMTP, telemetry, default images, metric retention); logs via `bezisync.services.*` loggers.
