# services

## Overview
The business logic behind the API handlers, the MCP tools, the CLI and the controller: pipelines (versions, preflight, deploy, pause/resume, delete, offsets), connections and their secrets, external secret-store references, runtimes and the agent-backed driver, approvals, alerts and notifications, audit, the image catalog, Flink CDC secrets and saved positions, manifests, copy between projects, SSO, MCP settings and OAuth, telemetry and key rotation. Handlers in `internal/api` stay thin and call in here; the [controller](../controller/README.md) uses the same functions; the [agent](../agent/README.md) reuses `BuildDriver` and `RunCheck`. Functions take a `db.Querier`, so callers choose the transaction; the exceptions are `AgentDriver` (it uses the pool, `db.MustPool`), `Preflight`'s runtime check and its capacity refresh (`[pipelines.go:useFreshCapacity]` writes on the pool, never in the caller's transaction, to avoid a lock-order deadlock with the controller) and the state-database helpers in `offsets.go` and `flinkcdc.go` (their own connections).

## Invariants
- Authorization is the caller's job except where checked here: `[approvals.go:RequestApproval]` requires `auth.PipelineDeploy`, `[approvals.go:Approve]`/`Reject` require `auth.PipelineApprove`, nobody approves their own request (`own_change_request`, 403), a rejection needs a comment (422 `comment_required`), and only the requester or an approver cancels (`[approvals.go:CancelChangeRequest]`). A new request supersedes the pipeline's pending one; `Approve` deploys through `Deploy`, so preflight runs again. `[copy.go:CanCopySecrets]` is Admin-only. Project lookups (`[pipelines.go:GetPipeline]`) return 404 for other projects' rows.
- Every mutation records an event via `[audit.go:Record]`; controller and system events pass `NotAudit: true`. Feedback text stays out of the audit details (`[feedback.go:SubmitFeedback]`).
- Secrets are write-only: `[connections.go:MergeSecrets]` replaces given keys, removes `null`/`""`, keeps omitted ones; `[connections.go:EncryptOrNil]` stores nothing for empty secrets; responses expose field names only (`[connections.go:SecretFieldsSet]`). `[connections.go:Resolve]` fails with `secret_missing` when a required secret was never entered and `secret_ref_unresolved` (422) when a store read fails; messages name field and store, never a value. Store values are cached 60 s per store id + version + path/key (`[connections.go:ResolveRefs]`), dropped by `ForgetStore`.
- Check reports are scrubbed of every secret value of the connection and its links before they leave (`[connections.go:RunCheck]`, `[connections.go:ScrubReport]`: `Message` and `Technical`; values shorter than 4 runes are not redacted, `[connections.go:Redact]`).
- Versions: the caller's own unsealed draft is amended in place (anyone else's edit starts a new version); `[pipelines.go:SealVersion]` freezes a version on deploy or approval request and refuses (409 `version_changed`) if it was saved after its checks. `[pipelines.go:UpdatePipeline]` answers 412 `version_conflict` on a stale version; a deployed pipeline can't be renamed (`rename_after_deploy`), change destination (`sink_after_deploy`) or change engine (`engine_after_deploy`), and changes runtime only while paused (`pipeline_running`), all 409. Labels given to `UpdatePipeline` that differ from the stored ones must pass `domain.LabelsValid` (422 at `body.labels`); unchanged ones are stored as they are.
- Deploy: `[pipelines.go:CheckDeployable]` blocks on failed preflight (409 `preflight_failed`) unless a force reason is given, the project allows force (`force_not_allowed`, 403), and no `config`, `runtime` or `policy` check failed. `[pipelines.go:Deploy]` writes desired state only (deployed version and image, `desired_state=running`, lifecycle `deploying`), drops the `snapshot_override` artifact (so a `skip_to_now` override lasts until the next deploy), audits `pipeline.deployed` or `pipeline.deployed_forced`, and queues a `snapshot` job (20 s delay) for tables added to an already-deployed pipeline when the source supports incremental snapshots.
- Settings: saving refuses tuning outside the registry (`[tuning.go:ValidateTuning]`), new or changed advanced keys that `compiler.ClassifyAdvanced` refuses (`[pipelines.go:RefuseNewAdvanced]`), and new or changed values outside a project setting limit (`[settinglimits.go:RefuseSettingLimits]`). Limits Admins save are validated strictly; stored ones decode leniently. Pins are applied to the spec preflight checks and written into an unsealed version by `[pipelines.go:writePins]` in `CheckDeployable` (a sealed version is refused with `pinned_setting`); the compiler never reads limits. Only limits on the pipeline's own engine apply and keys the registry dropped are ignored (`[settinglimits.go:LimitsFor]`); a save checks only new or changed values, while preflight's blocking `policy_setting_limit` check covers every value, including ones saved before the limit.
- Checks and recommendations in `settingchecks.go` read only this run's evidence (the image's release, live connection counts, discovery's size estimates). Without it they are Unknown or absent, never a pass. Connection counts are never read through an agent.
- Flink CDC on a source that can't copy added tables (`engine.Caps.AddTables` false: Oracle, ADR 0006): `flink_tables_added` blocks a deploy that adds tables (`domain.SummarizeChange` against the deployed version) while a saved position is left, or when that can't be read (`[cluster.go:flinkTablesAddedCheck]`, config section); such a deploy stores the newest saved-position id as `flink_tables_floor` (`[cluster.go:recordTablesFloor]`), and `RestoreSavedPosition` refuses a position at or below it with 409 `position_before_tables` (`[cluster.go:restoreBelowFloor]`). ADR 0012/0013: `flink_columns_changed` passes for a version that changes the columns a running or paused pipeline writes while a saved position is left (`[flinklayout.go:columnChanges]`: `[flinklayout.go:producedChanges]` on `compiler.FlinkProduced` of the version in `flink_written` — else the deployed one — and the new version, the live source columns for both), saying it switches columns at the position, and warns when the positions can't be read; `flink_destination_columns` plans that switch, or a start with nothing left to restore, read-only (`[flinklayout.go:planLayout]`: every destination table read through its `connectors.FlinkColumns`; at a switch a source column in neither `flink_columns` nor its destination table is left out, `[flinklayout.go:knownColumns]`) — blocking on a problem (`domain.PlanFlinkLayout`), an unreadable table or Paimon columns to add by hand, a warning for a destination BeziSync can't read (Fluss), a pass that names the columns it will add and the tables it pins (`[flinklayout.go:flinkLayoutChecks]`, config section). `Deploy` records the version it replaces as `flink_written` when none is recorded (`[pipelines.go:Deploy]`). `EnsureFlinkStartPlanned` (the controller, before each compile, once per deployed version and restore floor, only when the pipeline should run): with a saved position left and `flink_written` the deployed version (or unrecorded), it resumes unchanged; when `flink_written` is another version whose columns differ it switches (ADR 0013): plans as below, adds the columns tables lack and reads them back (`[flinklayout.go:applyLayoutPlan]`), stores `flink_layout` with `generation` + 1 and the floor kept, `flink_columns`, and records `pipeline.columns_switched`; before a start without a saved position it plans again, stores `flink_layout` (pinned destinations, the newest saved id as `floor`, the generation kept), `flink_columns`, and `flink_fresh_start`, and records `pipeline.layout_planned`; every plan records the deployed version in `flink_written`; a problem is a 409 `flink_destination_columns` and the new version isn't applied; with the state database unreadable it plans on a later pass. `RestoreSavedPosition` copies the position's `generation` (adding the column to an older table first). `RestoreSavedPosition` refuses a position at or below `flink_layout.floor` with 409 `position_before_layout` (`[flinklayout.go:restoreBeforeLayout]`). `flink_oracle_version` goes to the config section too (`[pipelines.go:flinkConfigChecks]`): a forced deploy can't skip either. On Flink CDC pipelines the source report leaves out the Oracle checks only Debezium needs (`connectors.FlinkDebeziumOnlyChecks`).
- A Flink CDC custom cluster is packed once, at deploy, and stored as the `flink_shape` artifact for the spec's hash, so a running pipeline's config hash never follows the nodes (`[cluster.go:FlinkSizeOf]`). After the copy it shrinks only on evidence (streaming, then a save after `streaming_since`); a streaming shape that fails before saving reverts, and after `MaxShrinkFailures` (3) shrinking is turned off (`[shrink.go:FlinkPhaseStep]`), which the `cluster_shrink_failed` alert rule reports. Under the project's `shrink_after_copy: suggest` policy it is only marked ready, and `[shrink.go:ShrinkCluster]` (a running pipeline, else 409 `not_running`/`not_ready`) shrinks it on request. Start over with a copy, and restoring a position before `copy_done_save`, grow it back (`[cluster.go:GrowBack]`). Audits the controller causes set `AuditEvent.Actor` to `controller`.
- Preflight uses the capacity the runtime test just returned (`[pipelines.go:useFreshCapacity]`), compares what a redeploy adds (`[pipelines.go:runningNeed]`), blocks over the namespace quota the Kubernetes driver reports, and is Unknown without capacity. Project resource limits count the peak footprint (`[footprint.go:FootprintOf]`).
- Placement profiles exist only on Kubernetes runtimes (422 `placement_profiles`), and one a pipeline's current or deployed version names can't be removed (409 `placement_in_use`) (`[placement.go:ValidateProfiles]`). The profile is resolved at deploy and stored for the spec's hash, so editing a profile reaches a running pipeline only at its next deploy (`[placement.go:PlacementOf]`).
- Manifest plans (`[manifests.go:ApplyManifest]`) report each raw property's class, never its value, and list as `Breaking` a setting change that makes the pipeline start over, a naming or format change and tables no longer captured.
- `[images.go:ChangeImage]` handles each pipeline on its own and returns a per-pipeline `UpgradeResult` (a problem from one pipeline's savepoint does not fail the batch). It skips Flink CDC pipelines (they have their own image); with `deploy` it refuses a live pipeline with undeployed changes; it refuses a pipeline that a blocking `[version_effects.go:VersionEffects]` entry names, and moves renamed settings. A pipeline already on the target image is redeployed only when its resolved default changed since its deploy. Where the project requires approval, the deploy goes through `RequestApproval` instead of `Deploy`.
- Jobs are created `queued` with `MaxAttempts: 5` (`[pipelines.go:Enqueue]`); `[pipelines.go:DeletePipeline]` soft-deletes and queues `cleanup`; `[pipelines.go:Restart]` needs a running pipeline. `[pipelines.go:ResetOffsets]` needs a paused pipeline whose workload has stopped; it drops the offsets, clears `last_lsn`/`position_regressed`, and for `skip_to_now` also forgets the source position (`snapshot_override = no_data`; `resnapshot` deletes the override); `resnapshot` is refused (422 `snapshot_unsupported`) when the source can't copy existing rows, and `from_time` is Flink CDC only (`engine_unsupported`). On Flink CDC a reset or `[flinkcdc.go:RestoreSavedPosition]` needs a paused pipeline whose cluster is gone or stopped (409 `still_running`); a reset sets every saved position aside and stores a startup mode (`from_time` only where the source supports it and in the past), and on PostgreSQL also moves the replication slot. Set-aside positions and savepoints beyond the newest 10 expire after `[flinkcdc.go:SavedPositionRetention]` (7 days) unless kept (`[flinkcdc.go:ExpireSavedPositions]`). `[alerts.go:EvaluateProject]` seeds missing default rules, opens an alert `pending`, fires it after the rule's `ForSeconds`, and resolves it when the condition clears; firing and resolving (of a notified alert) record `alert.fired`/`alert.resolved` (`NotAudit`), notify the project's inbox and queue a `notify` job for the rule's channels and, with `NotifyOwner`, an owner email. `[alerts.go:RunNotifyJob]` is idempotent per target and alert state and returns `Retry` while any target fails.
- Outbound alert posts accept only http(s) URLs and check the host with `ssrf.ResolveChecked`, then send through `ssrf.HTTPClient` (10 s timeout), so every dial, redirects included, is checked again (`[alerts.go:postJSON]`); webhooks are signed `x-bezisync-signature: sha256=<HMAC>` when a signing secret is set. Email goes to the configured SMTP server (15 s timeout, optional STARTTLS).
- Agent runtimes: desired workloads are stored encrypted in `agent_workloads` and rewritten only when config hash, running flag or pull settings change (`[runtimes.go:AgentDriver.Apply]`); a Flink CDC workload is refused for an agent that has reported without the `flink_cdc` feature. Health, metrics and `/bz/status` come from the agent's last report; other reads are requests. Agent requests store their args encrypted (they may carry resolved secrets) polled every 400 ms and deleted after the answer or timeout (check 60 s, logs 12 s, `http_get` its timeout + 6 s) (`[runtimes.go:AgentDriver.request]`). No poll for `AgentOfflineAfter` (30 s) makes the runtime unreachable. Direct drivers are cached per runtime id + version (`[runtimes.go:DriverFor]`).
- OAuth: PKCE S256 only, authorization requests valid 10 min, codes one-time and valid 1 min, access tokens 1 h, grants for the approved number of days, refresh rotation with reuse revoking the grant (audited `mcp.agent_revoked`); codes and tokens stored hashed; races resolved with conditional `UPDATE … RETURNING` (`[oauth.go:Refresh]`, `[oauth.go:ExchangeCode]`).
- Sign-in lockout guards: password sign-in stays in force while no provider is on (`[sso.go:PasswordLogin]`); turning it off needs a tested provider and an Admin who signed in with SSO (`[sso.go:SetPasswordLogin]`); the last enabled provider can't be turned off while passwords are off (`[sso.go:GuardLastProvider]`).
- Project policies come from `[pipelines.go:PoliciesOf]` (`domain.LoadPolicies`); policies that fail to parse are `Unreadable` (ADR 0002): `PoliciesOf` logs a warning, `[pipelines.go:UnreadablePolicies]` (409 `policy_unreadable`) refuses a `PATCH` that changes the spec and, through `RefuseSettingLimits`, a create or manifest apply; `PolicyChecks` returns only the unreadable check; the copy plan lists it for every item. Reads (reconcile, approvals, setting limits) use the loaded values.
- Inbox entries skip users who muted the kind (`[inbox.go:Notify]`); feedback is rate-limited per user (`ratelimit.Feedback`) and notifies every active Admin.
- MCP is off by default; tools without an entry keep their default (destructive off) (`[mcp.go:MCPSettings]`).
- Pagination is keyset over (time, id), limit clamped to 1…200, cursor `base64url(json([isoformat, id]))` (`[pagination.go:EncodeCursor]`).
- Metrics retention: raw samples older than 24 h roll into 1-minute rows, data past `MetricsRetentionDays` is deleted (`[metrics.go:EnforceMetricRetention]`).
- `[bootstrap.go:Bootstrap]` runs only when no users exist and `BEZISYNC_BOOTSTRAP_ADMIN_PASSWORD` is set; `[bootstrap.go:EnsureSandbox]` only once, when the sandbox settings are present.
- `[keys.go:RotateKeys]` re-encrypts every encrypted column not under the current master key (connections, runtimes, secret stores, alert channels, agent workloads, SSO providers, pipeline engine secrets) plus SAML keys.

## Side Effects
- DB writes: `events`, `pipelines` (incl. the `flink_shape` and `placement` artifacts Deploy and the controller store), `runtimes.placement_profiles`, `pipeline_versions`, `change_requests`, `jobs`, `connections` (incl. `last_check` from `CheckAndStore`), `secret_stores`, `runtimes` (sandbox; `capacity` refreshed by preflight on the pool), `agent_workloads`, `agent_requests`, `alerts`, `alert_rules` (default rules seeded on evaluation), `alert_channels` (last delivery/error), `notifications`, `metric_samples` (rollup and deletes), `feedback`, `users` and `memberships` (SSO, bootstrap), `projects`, `pipeline_templates`, `sso_requests`, `sso_replays`, `oauth_clients`/`oauth_requests`/`oauth_grants`, `instance_state` (MCP settings, sign-in settings, telemetry, SAML keys); `[keys.go:RotateKeys]` rewrites every encrypted column it lists.
- State database (separate connections): reads and drops `offsets_<id>` / `history_<id>` (`[offsets.go:ClearOffsets]`), reads, copies and deletes `flink_state_<id>` saved positions.
- Network: connector checks, discovery, previews (sources and sinks), secret-store reads (Vault, AWS, GCP, Kubernetes), Docker/Kubernetes APIs via drivers, alert delivery (Slack, webhook, PagerDuty, SMTP), weekly telemetry POST to `TelemetryURL` when enabled (10 s timeout), OIDC/SAML providers.
- Process state: driver cache and secret-store value cache (in memory); `ratelimit.Feedback` per user.
- Env via `config.Get()` (bootstrap admin, sandbox, SMTP, telemetry, default images, metric retention); logs via `bezisync.services.*` loggers.
