# compiler

## Overview
Turns a pipeline spec plus its resolved source and sink connections into a runnable workload.
For Debezium that is `application.properties` (secrets only as `${ENV}` references) plus the
env that carries them, secret files, resources and an optional SSH tunnel; for Flink CDC it is
`pipeline.yaml`, `flink-conf.yaml` and `settings.json` for `flinkhelper`. The same functions
back deploys, the Review step and exports. It applies the sink capabilities and transform
checks from `connectors` and the engine tables from `engine`; it reads only process
configuration (`config.Get()`), no database or network.

## Interface
- `[compiler.go:Compile]` — Debezium Server compile; `image ""` means `DebeziumDefaultImage`.
- `[compiler.go:Compiled]` — the workload (`Properties`, `Env`, `Image`, `Resources`, `Destinations`, `Artifacts`, `Files`, `Tunnel`, `HealthPort`, `Flink`, `Managed`, `Placement`); `Render`, `ConfigHash`, `RedactedEnv`; `[compiler.go:FromFlink]` wraps a Flink compile for shared callers.
- `[compiler.go:RenderProperties]` — Java properties rendering (sorted, escaped, generated header).
- `[compiler.go:StateStore]` — JDBC offset (and schema-history) store properties for the state database.
- `[compiler.go:Resources]` / `[compiler.go:Resource]` — Debezium `small`/`medium`/`large` presets; `[compiler.go:ResourceFor]` is the container request for a preset or a custom size (heap from `domain.HeapMiB`, batch and queue from the nearest preset); `[compiler.go:ManagedPatterns]` — keys `spec.advanced` may not set; shared constants `[compiler.go:StateSchema]`, `[compiler.go:MetricsPort]`, `[compiler.go:SecretDir]`, `[compiler.go:HTTPPort]`.
- Advanced (raw) properties: `[advanced.go:ClassifyAdvanced]` / `[advanced.go:AdvancedRefusals]` (Debezium) and `[flinkadvanced.go:ClassifyFlinkAdvanced]` / `[flinkadvanced.go:FlinkAdvancedRefusals]` (Flink CDC pass-through prefixes) return an `[advanced.go:AdvancedVerdict]` (`Refused`) of class `[advanced.go:AdvancedClass]` (allowed, invalid, credential, forbidden, modelled, owned). `Compiled.Managed` is the set of keys BeziSync compiled, which no advanced key may change.
- `[snapshot.go:SnapshotProps]` — snapshot properties in the source's own mode names from its `capture` caps; none for a source with no snapshot modes (Spanner).
- `[transforms.go:FilterCondition]` — Groovy expression for a typed row/operation filter.
- `[flinkcdc.go:CompileFlink]` / `[flinkcdc.go:FlinkInput]` / `[flinkcdc.go:FlinkCompiled]` — Flink CDC compile (`ConfigHash`, `Config`, `Topology`); `[flinkcdc.go:FlinkStopGrace]` / `[flinkcdc.go:FlinkStopTimeout]`.
- Test fixtures: `testdata/flink/` holds golden Flink outputs (`UPDATE_GOLDEN=1` rewrites them).

## Invariants
- `application.properties` never holds a secret value; credentials travel in `Env` (`BZ_STATE_USER`/`BZ_STATE_PASSWORD`, `BZ_SSH_KEY`, connector env) and `Files` (`[compiler.go:StateStore]`, `[compiler.go:Compile]`). `RedactedEnv` masks every value (`[compiler.go:RedactedEnv]`).
- A source or destination connection (or one it links to) whose settings hold `${` is refused before anything compiles, on both engines (422 `connection_config`, `[compiler.go:noConfigExpressions]`): Debezium Server and the Flink CDC helper would read it as a variable naming another secret.
- At compile, `spec.advanced` keys must start with `debezium.` or `quarkus.` and must not match `ManagedPatterns` (identity, state, credentials, sink type, producer auth, HTTP port, the whole transform/predicate chain); violations are one 422 `managed_property` (`[compiler.go:validateAdvanced]`). `[advanced.go:ClassifyAdvanced]` is the stricter judge of a raw key: saving refuses keys it adds or changes, preflight refuses the rest and adopt keeps only allowed ones. It refuses keys over 255 characters or not shaped `^[a-z][a-zA-Z0-9_-]*(\.[a-zA-Z0-9_-]+)+$`, values over 4096 characters or holding `${` or control characters, credential-named keys, wizard-modelled and forbidden `debezium.source.*` options, unsafe JDBC `driver.*`/`database.*` options, `debezium.sink.*` keys whose last part names a destination (url, topic, bucket, …) or that contain `.ssl.`/`.security.`, every `debezium.format.*`, `debezium.transforms*`, `debezium.predicates*` and `quarkus.*` key, anything outside `debezium.source.`/`debezium.sink.`, and keys in `ManagedPatterns` or `Managed`. So a `quarkus.*` key compiles but is always refused on save and at preflight. Extend its tables rather than adding a second list; the one exception is `services`, which also refuses new `debezium.source.driver.*` keys on save for sources without JDBC (`mongodb`, `spanner`) (`[../services/pipelines.go:DriverPropertyRefusal]`). Advanced keys are merged last, after BeziSync's keys and `spec.tuning`, except `tombstones.on.delete=false` for `NoTombstones` sinks, which is re-applied after (`[compiler.go:Compile]`).
- `spec.tuning` is resolved against the engine registry (`[tuning.go:tuningSettings]`): every key must be a registry setting for this engine, source and destination, in a scope tuning holds, with a valid value. A tuned key BeziSync also compiles must be `Derived`, or compile fails with 422 `tuning` (`[tuning.go:ownedByBeziSync]`). Tuned keys are applied after BeziSync's own keys and before advanced ones.
- The Debezium transform chain is always `bzmeta` (drops heartbeats and BeziSync's own `bezisync.*` tables except `canary_*`, plus a source's `ManagedTopics`), then the spec steps, then `bzroute`, then one `bzmerge<N>` RegexRouter per `route` target (sorted) (`[compiler.go:Compile]`, `[transforms.go:stepProps]`, `[transforms.go:routeProps]`). Some steps are not chain entries: `route` compiles after `bzroute`, `truncate` becomes `debezium.source.column.truncate.to.<N>.chars` (PostgreSQL and MySQL only, `domain.TruncateSources`), `computed` is refused (Flink CDC only), and `soft_delete` forces the unwrap step to `delete.tombstone.handling.mode=rewrite` (adding one with `op`, `source.ts_ms` where the step sits when there is none) (`[sinkcaps.go:withSoftDelete]`). A destination that requires the event shape appends its unwrap at the end (`[sinkcaps.go:withSinkUnwrap]`), except when a `soft_delete` is followed by a field step (stage 2): the unwrap then goes where the `soft_delete` is, so the field step reads rows; every other chain keeps its `config_hash` (`TestSoftDeleteBeforeFieldStepsOnIceberg`).
- Debezium destinations and naming: a source that names topics by connector (`connectors.Namer`) gets `debezium.source.name` set to the prefix; with `Policies.DeliveryCanary` on and a source that `SupportsCanary`, the canary table is added to `Destinations`; a sink that implements `connectors.DestinationNamer` then rewrites every destination (`[compiler.go:Compile]`).
- A `route` step may not send a table onto the destination of a table that is not routed there (422 `destination_collision`, both engines) (`[compiler.go:Compile]`, `[flinkcdc.go:CompileFlink]`).
- Typed filters quote every field and literal as single-quoted Groovy strings, so input never becomes code (`[transforms.go:groovyString]`); untyped filters and `custom` steps pass the user's condition/class/properties through unchanged (`[transforms.go:stepProps]`).
- `ConfigHash` must stay byte-identical to the Python implementation (`pyjson.Dumps` of properties, env, image, resources, files, tunnel; first 16 hex chars of SHA-256) (`[compiler.go:ConfigHash]`). A `Placement` profile is folded in only when set, so pipelines without one keep their hash; `Managed` is not hashed. Flink's hash covers pipeline, conf, settings, env, files, image, size and tunnel (`[flinkcdc.go:ConfigHash]`).
- Compile fails with 422 when no table is selected, a sink option/naming/transform/format rule fails, a registry URL is missing for avro/protobuf, the SSH fields are incomplete, the snapshot mode is not offered, a value format or key-column choice is not offered by the source, a script filter has no condition, or a typed filter uses column rules on a source without `RowFilters` (`[compiler.go:Compile]`, `[snapshot.go:SnapshotProps]`, `[transforms.go:stepProps]`, `[transforms.go:sourceOptions]`). A source and sink may not mount the same secret file or (Flink) set the same env var; those are plain errors, not 422s.
- The sink's capabilities shape the workload: an `unwrap` step the sink needs is merged into the user's step or appended (`[sinkcaps.go:withSinkUnwrap]`), and `NoTombstones` / `TimePrecision` sinks get `tombstones.on.delete=false` and a readable `time.precision.mode` unless the user chose a non-default mode (`[sinkcaps.go:sinkSourceProps]`).
- Flink CDC compile refuses: no registered image (`engine_unavailable`), a pair without `FlinkSource`/`FlinkSink`, a naming choice the sink refuses, table names Flink CDC can't address (`flink_table_name`, `connectors.FlinkTableNames`), refused advanced keys as one `managed_property` (`[flinkadvanced.go:ClassifyFlinkAdvanced]`: only `source.jdbc.properties.`, `source.debezium.`, `sink.sink.properties.`, `sink.table.create.properties.` and `sink.table.properties.` pass through, and within them unsafe or credential-named JDBC options, `source.debezium.*` keys `ClassifyAdvanced` refuses, `sink.catalog.properties.*`, `sink.hadoop.conf.*`, Iceberg `sink.table.properties.{format-version,location,write.*.path}`, credential-named sink options and keys BeziSync already set are refused), a `pipeline.*` tuning key BeziSync already sets (`tuning`), a custom cluster whose shape was not resolved (`flink_cluster`), value formats, a copy delay/window, a snapshot mode with no Flink startup mode, a start-from-time on sources other than `mysql`/`sqlserver`, raw source options the source's Flink reader would ignore (`connectors.FlinkSourceIgnores`), Debezium 1.9 keys that load classes, move the schema history or open sessions to other hosts (`source.debezium.database.history*`, `rac.nodes`, `database.connection.adapter`: `[flinkadvanced.go:debezium19Forbidden]`, every Flink source), Flink settings outside the catalogue, destination name collisions, masks (`mask_unsupported`), script filters and outbox/flatten/custom steps, a soft delete whose `__op` column a table already has, a computed column whose name a table already has and does not exclude, or two added columns with the same name (`transform_field_conflict`), an operation filter that keeps only one of insert/snapshot, column choices when the deployed columns are unknown, an excluded column that is not among the deployed columns or is a key column (`column_unknown`), and destinations with `NoDefaults` unless new columns are held (`[flinkcdc.go:CompileFlink]`, `[flinkcdc.go:startupOptions]`, `[flinktransforms.go:flinkTransforms]`, `[flinktransforms.go:flinkFilter]`). An unknown preset falls back to `small`; a custom cluster uses the resolved shape in `FlinkInput.Cluster` (`services.FlinkSizeOf`).
- Flink transforms quote names as back-quoted identifiers and values as SQL literals (`[flinktransforms.go:sqlIdent]`, `[flinktransforms.go:sqlString]`); computed columns come from a fixed function set with picked arguments, never user SQL (`[flinktransforms.go:computedSQL]`); `pipeline.yaml` values are JSON-quoted scalars except bare `${BZ_…}` placeholders, which the helper fills (`[flinktransforms.go:yamlScalar]`).
- `flink-conf.yaml` puts BeziSync's own keys (RPC/blob ports, REST bound to `127.0.0.1`, memory, slots, parallelism, checkpoint dirs, `classloader.resolve-order: parent-first`, internal mutual TLS with the pipeline keystore) before the catalogue keys and rejects line breaks in any value (`[flinkcdc.go:flinkConf]`). Keystore passwords go only into the secret settings file, never `flink-conf.yaml` (`[flinkcdc.go:CompileFlink]`).
- Flink `settings.json` always restores `latest` above `RestoreAfter`, keeps 5 checkpoints, uses `runtime.FlinkStateDir`, health port `HTTPPort` and `FlinkStopTimeout` (`[flinkcdc.go:CompileFlink]`).

## Side Effects
- Reads process configuration via `config.Get()`: `ConnectorStateDatabaseURL` (state database URL, whose credentials are copied into `Env`), `AgentImage` (tunnel image), `DebeziumDefaultImage` (`[compiler.go:StateStore]`, `[flinkcdc.go:flinkStateEnv]`). Otherwise none.
