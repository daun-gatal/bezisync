# domain

## Overview
The pure product rules, with no database or network access: health derivation, the pipeline
spec (parsing, validation, canonical dump and hash), transform steps, project policies,
personal-data checks, transform previews, maintenance windows, schema diffs and the
`kind: Pipeline` manifest. Services, the controller, the compiler and the API call it; it
returns values and `checks.Check` results and never performs I/O.

## Interface
- Health: `[health.go:Derive]` / `[health.go:DeriveInput]` / `[health.go:Verdict]` / `[health.go:Reason]` — one lifecycle + health verdict from observations; `[health.go:ParseMetrics]` / `[health.go:Metrics]` read Debezium JMX values; `[health.go:Diagnose]` maps known log lines to reasons; `[health.go:DeployGrace]` (5 min). Lifecycle/health constants `LifecycleDraft` … `HealthUnknown`. Python-compatible text helpers: `FormatFixed`, `HumanBytes`, `Truncate`, `SplitLines`, `PyStrip`, `PyFloat`.
- Spec: `[spec.go:PipelineSpec]` and its parts (`SourceSpec`, `SinkSpec`, `SnapshotSpec`, `Transform`, `Policies`, `ColumnRules`); `[spec.go:ParseSpec]` validates submitted/stored JSON into a spec; `[spec.go:MustSpec]` for stored versions; `[spec.go:DefaultSpec]`; `[spec.go:PipelineSpec.Dump]` (ordered canonical form); `[spec.go:SpecHash]`; `[spec.go:SummarizeChange]`; `[spec.go:SnapshotModes]`. `tuning` (registry settings, dumped only when set) and `placement` (a runtime placement profile) are spec fields.
- Settings changes: `[spec.go:SettingChanges]` / `[spec.go:SettingChange]` (each changed setting with its `engine.Impact`), `[spec.go:SummarizeSettings]` / `[spec.go:SettingsChange]` (typed, Flink and advanced keys and the heaviest impact, reported next to `ChangeSummary`), `[spec.go:HeaviestImpact]`.
- Flink CDC choices: `[flinkcdc.go:FlinkCDCSpec]`, `[flinkcdc.go:FlinkCDCSpec.Effective]` (fills defaults from `DefaultFlinkCDCSpec`). A custom cluster is `[cluster.go:FlinkCluster]`: a `[cluster.go:SlotSize]` per slot and a parallelism, or `[cluster.go:ManualTaskManagers]`; read by `[cluster.go:ParseCluster]`.
- Sizes: `[resources.go:ResourcePresets]` / `[resources.go:ResourceAmount]` (the presets in numbers; `Within` compares with a limit), `[resources.go:CustomResources]` (a Debezium custom size), `[resources.go:ParseCPU]` / `[resources.go:ParseMemory]` (canonical forms) with their `Any` and `Format` variants, `[resources.go:HeapMiB]`, `[resources.go:Policies.Amount]`.
- Transforms: `[transforms.go:TransformTypes]`, `[transforms.go:Transform.Scripted]`, `[transforms.go:ScriptedSteps]`, `[transforms.go:ScriptedClasses]`, `[transforms.go:Transform.Stage]`, `[transforms.go:BuiltInTransformTypes]`, `[transforms.go:StepLabel]`; route steps: `[transforms.go:GlobMatch]`, `[transforms.go:RouteTargets]`; `[spec.go:Route]`; truncate steps: `[spec.go:Truncation]`, `[transforms.go:TruncateSources]` (Debezium sources; Flink CDC truncates on any); `[transforms.go:SoftDeleteField]` (per engine), `[transforms.go:FlinkSoftDeleteField]` (`__bz_op` on StarRocks, which reserves `__op`: ADR 0012); filter steps: `[transforms.go:FilterOperations]`, `[transforms.go:FilterOps]`; computed columns (Flink CDC): `[computed.go:ComputedFunctions]`, `[computed.go:ComputedArg]`, `[computed.go:ComputedInputs]`, `[computed.go:KindFits]`, `[computed.go:DatePatterns]`; findings for the captured tables on an engine: `[findings.go:TransformFindings]`, `[findings.go:TransformChecks]`; Flink CDC primary keys (ADR 0010): `[keys.go:FlinkKey]` (`[keys.go:FlinkKeyColumn]`, `[keys.go:FlinkKeyError]`), `[keys.go:FlinkRenames]`, `[keys.go:StepColumns]`, `[keys.go:FlinkKeyProblems]`, `[keys.go:ComputedKeyProblem]`, `[keys.go:FlinkKeyWarnings]` (`transform_key_column_nullable`, only when the key doesn't hold the whole primary key: `[keys.go:keepsPrimaryKey]`), `[keys.go:KeyColumnSQL]`, `[keys.go:KeyKinds]`; Iceberg partitioning (ADR 0005): `[partition.go:PartitionTransforms]` (transform → written kinds, Iceberg's table), `[partition.go:PartitionFits]`, `[partition.go:PartitionKind]` (the kind an engine writes for a source column), `[partition.go:SourceTimestampField]`. Flink CDC column layout (ADR 0012): `[flinklayout.go:PlanFlinkLayout]` (`[flinklayout.go:FlinkColumn]`, `[flinklayout.go:DestColumn]`, `[flinklayout.go:LayoutColumn]`, `[flinklayout.go:LayoutPlan]`, `[flinklayout.go:LayoutTarget]`), `[flinklayout.go:FlinkTypeFits]`, `[flinklayout.go:FlinkTypeOfKind]`, `[flinklayout.go:IcebergFlinkType]`, `[flinklayout.go:PaimonFlinkType]`.
- Policies: `[policies.go:ProjectPolicies]`, `[policies.go:DefaultPolicies]`, `[policies.go:ParsePolicies]`, `[policies.go:LoadPolicies]`, `[policies.go:SaveViolations]`, `[policies.go:EvaluatePolicies]` / `[policies.go:EvaluatePoliciesOn]`, `[policies.go:EngineViolation]`; per-setting limits `[policies.go:SettingLimit]` (min, max, choices, pin, hide) and per-pipeline `[policies.go:ResourceLimits]` (CPU, memory, parallelism; `Amounts`); `[policies.go:ProjectPolicies.ShrinkAuto]` (`shrink_after_copy`); `[policies.go:AskAdmin]` is the default fix text of a policy failure.
- Personal data: `[personal.go:PersonalDataChecks]` / `[personal.go:DataColumn]`.
- Preview: `[preview.go:Preview]` / `[preview.go:PreviewInput]` / `[preview.go:PreviewResult]` — runs the steps on a sample event of one table; `[preview.go:ColumnKind]`.
- Windows: `[windows.go:ParseWindow]`, `[windows.go:WindowContains]`, `[windows.go:WindowNextStart]` (`"HH:MM-HH:MM"`, UTC, may wrap midnight).
- Schema drift: `[schema.go:Schema]`, `[schema.go:DiffSchema]`, `[schema.go:Change]`.
- Manifest: `[manifest.go:ParseDocuments]`, `[manifest.go:FromDocument]` (→ `[manifest.go:ParsedPipeline]`, or a `[manifest.go:ManifestError]` listing field errors), `[manifest.go:ToDocument]`, `[manifest.go:ToYAML]`, `[manifest.go:SpecDiff]`, `[manifest.go:APIVersion]` (`bezisync.io/v1`).

## Invariants
- `[partition.go:PartitionTransforms]` and `[partition.go:PartitionKind]` are mirrored by the wizard (`wizard/PartitionBy.tsx`); both are tested against `backend/testdata/partition_kinds.json`, so a change to one side fails until the other and the vectors follow.
- Health is evidence-based: an undeployed pipeline, an unreachable runtime, missing metrics or a missing health answer are `unknown`, never `healthy` (`[health.go:derive]`). `[health.go:DeriveInput]` carries no evidence timestamps, so any metrics with a positive health answer count as fresh: the caller keeps stale evidence out by passing nil. A paused pipeline is `unknown`, or `at_risk` when the source reports a risk. A fresh deploy (or a Flink CDC restart) gets `[health.go:DeployGrace]` before it counts as failed.
- A running pipeline is `lagging` when it is more than the latency target behind the source (default 60 s) or its queue has less than 10% left (`[health.go:derive]`).
- `[spec.go:SpecHash]` is sha256 of `pyjson.DumpsCompact` of the canonical dump; the dump shape and key order must not change, or stored hashes stop matching.
- Spec validation limits: at most 30 steps, 20 rules, 50 renames, 30 custom properties and 10 key columns (`[transforms.go:maxSteps]` …); tables must look like `schema.table` and be unique (`[spec.go:tableRe]`).
- Custom sizes are canonical: CPU in quarters (0.25–8) and memory in 256 MiB steps (512Mi–16Gi) (`[resources.go:ParseCPU]`, `[resources.go:ParseMemory]`). `resources: custom` needs exactly one shape, `policies.custom_resources` (Debezium) or `flink_cdc.cluster` (Flink CDC), never both, and either one is refused without `resources: custom` (`[spec.go:ParseSpec]`).
- `tuning` keys must be registry-shaped names (`[spec.go:tuningKeyRe]`, at most 255 characters) and values at most 256 characters, on one line, without `${`; which keys an engine accepts is checked by the services against `engine.SettingsFor`. `placement` is a DNS-label name (`[spec.go:placementRe]`).
- Route and truncate steps: a captured table matched by more than one route is refused; route patterns are `schema.table` with `*` (`[transforms.go:routeMatchRe]`); truncate lengths are 1–65535 and a column is truncated at most once (`[transforms.go:decodeTruncate]`), never a masked or left-out one, and only on a captured table (`[transforms.go:validateTransforms]`).
- A Flink CDC key (`spec.keys`, ADR 0010) names a source column by its source name (written under its renamed name) or a column a step adds to the table (an added field, a computed column) by its own name; a source column the table writes wins, then the new name a rename gives one (that column), then a step column of the name (`[keys.go:FlinkKey]`; with the columns unknown every name is taken as it is, through the renames). `[findings.go:TransformFindings]` on `flink-cdc` blocks a key column the table doesn't write (`transform_key_column_unknown`) and one that can't key rows (`transform_key_column_unfit`, `[keys.go:FlinkKeyProblems]`: a cut source column; a computed column that `[keys.go:ComputedKeyProblem]` refuses — not text or a whole number as the compile reads it, reading a column that can be NULL (unknown nullability counts as NULL), a form that can give an empty value, not deterministic —; and, on a table with a primary key, a key with a step column that leaves part of it out); on Debezium the message-key finding is unchanged (`transform_key_column_missing`). The wizard mirrors which typed functions qualify (`backend/testdata/key_columns.json`, `TestKeyColumnVectors`).
- A computed column is a typed function or an expression of `internal/expr` (ADR 0008), never text passed through: inputs are the source table's own columns (before renames), never masked or left-out ones; text arguments are at most 200 characters (`[computed.go:maxComputedText]`). An expression (computed column or Flink CDC filter, `[spec.go:Transform]` `Expression`) is stored as its canonical text (`[expression.go:decodeExpression]`); a typed function compiles through the same renderer (`[expression.go:ComputedTree]`, `[expression.go:ComputedSQL]`), whose list the frontend mirrors (`backend/testdata/computed_functions.json`, `TestComputedFunctionVectors`). `[expression.go:ExpressionEnv]` gives an expression the table's columns with Flink CDC's kinds; `transform_expression` (`[expression.go:expressionFindings]`, `[expression.go:typedExpressionFindings]`) blocks a column the table lacks, a kind a function doesn't take, mixed kinds, and a column named like a time function.
- Values that reach `application.properties` must not contain `${` or control characters, so Debezium Server cannot expand a secret into events (`[transforms.go:noExpression]`).
- Steps that run user-written scripts (filter conditions, `ScriptedClasses`, any `language` property) fail preflight unless the project policy `allow_scripted_transforms` is on (`[transforms.go:Transform.Scripted]`, `[policies.go:EvaluatePoliciesOn]`).
- Policy fields added after the Python releases (`allow_scripted_transforms` … `setting_limits`) are dumped only when set, so stored policies and their recorded dumps stay byte-identical (`[policies.go:ProjectPolicies.Dump]`). Resource limits can't go below the smallest preset (`[policies.go:MinLimitCPU]` 0.5 CPU, `[policies.go:MinLimitMemory]` 768 MiB). `shrink_after_copy` defaults to `auto` (`[policies.go:ProjectPolicies.ShrinkAuto]`).
- Nil policy lists mean "any"; policy failures are blocking (`[policies.go:policyFail]`). Beyond runtimes, source/sink types, snapshot modes, the resource preset and pipelines per source, policies gate engines (`allowed_engines`), built-in step types (`allowed_transforms`) and `custom` steps (`allow_custom_transforms`, `[transforms.go:transformPolicyChecks]`), and `advanced` raw properties (`allow_advanced_properties`). Setting limits and resource limits are checked on save and in preflight by the services.
- Stored policies that fail to parse fail closed (`[policies.go:LoadPolicies]`, [ADR 0002](../../../docs/adr/0002-policies-fail-closed.md)): `Unreadable` with `Problems` (field and message, no values), the fields that parsed kept, the failed ones strictest (`[]` allow-lists, not `nil`); `SaveViolations`, `EvaluatePoliciesOn` and `EngineViolation` then return only `[policies.go:UnreadableCheck]` (`policy_unreadable`). `Dump` adds `unreadable` and `problems` only then, and `ParsePolicies` ignores both.
- Personal data: a column that cannot be masked but is set to mask is a blocking failure; unprotected PII columns and rules naming missing columns are warnings; unreadable tables give `pii_unknown` (`[personal.go:PersonalDataChecks]`).
- Manifests must have `apiVersion: bezisync.io/v1` and `kind: Pipeline` (`[manifest.go:FromDocument]`); YAML is read and written through `pyyaml` so exports stay byte-identical to the Python releases.

- A start without a saved position writes, into a destination table that exists, the table's columns in the table's order on a positional destination (a column the spec no longer writes kept empty, typed from the table; a new one appended), and on a by-name one the spec's order with what the table lacks added; it refuses (a problem naming the column) to empty a key, partition or NOT NULL column, a type it can't map, a new column of unknown type, a new key column, or a written type that doesn't fit the table's (`[flinklayout.go:PlanFlinkLayout]`, `[flinklayout.go:FlinkTypeFits]`). `Pinned` is set only when the order differs from what the spec compiles to.
