# api

## Overview
Package `api` is the versioned REST API (mounted under `/api/v1`), the system routes
(`/healthz`, `/readyz`, `/metrics`, docs) and the OAuth discovery documents. Handlers aim to be thin:
they authenticate with [`auth`](../auth/README.md), validate with `val` in FastAPI-compatible shapes
via [`httpapi`](../httpapi/README.md), and call `internal/services`; errors are
[`problem`](../problem/README.md) values. The embedded `openapi.json` is the contract the frontend
client is generated from. The MCP endpoint ([`mcpserver`](../mcpserver/README.md)) is mounted here
and calls this same router in process. Some handlers still run SQL and domain logic inline (projects, members,
users, connections, policies, the agent poll, `schema/review`, SSO kind validation in `sso_kinds.go`).

## Interface
- `[api.go:Router]` — builds the API process handler: middleware, optional CORS, system routes, every `/api/v1` route group, `POST /api/v1/mcp`, OAuth discovery.
- `[api.go:OpenAPI]` — the embedded `openapi.json`; `[system.go:systemRoutes]` also serves it at `/api/v1/openapi.json` with Swagger UI at `/api/docs`, plus `/healthz`, `/readyz` (503 `database_unavailable` when `select 1` fails), `/metrics`, and the unauthenticated `/api/v1/system/info` (version, environment, default image, telemetry flag) and `/api/v1/system/licenses`; `/api/v1/system/telemetry` is Admin-only.
- Route groups, one file per resource:
  - `[auth.go:authRoutes]` (`POST /auth/login`, `POST /auth/logout`, `GET`/`PATCH /auth/me`: name, `ui_mode`, `muted_notifications`), `[auth.go:tokenRoutes]` (personal API tokens: `GET|POST /auth/tokens`, `DELETE /auth/tokens/{token_id}`; the `bzt_` secret is returned only in the create response, `[auth.go:TokenRead]`), `[auth.go:ssoRoutes]` (unauthenticated `/auth/providers`, `/auth/oidc/login` — SAML providers start here too — and `/auth/oidc/callback`), `[auth.go:samlRoutes]` (SP metadata, ACS).
  - `[sso_providers.go:ssoProviderRoutes]` (`GET|PUT /auth/settings`, `/sso-providers` CRUD + `/{provider_id}/test`; Admin) with per-kind config parsing and validation in `sso_kinds.go` (`[sso_kinds.go:resolveKind]`, `[sso_kinds.go:testProvider]`).
  - `[projects.go:projectRoutes]` (projects, members, `GET …/events`, `GET …/audit:export` as CSV or JSONL), `[users.go:userRoutes]` (people and per-project access; Admin).
  - `[connections.go:connectionRoutes]` (connector types, CRUD, `…/check`, `connections:check` for a draft, `…/discover`, `…/usage`), `[secret_stores.go:secretStoreRoutes]` (CRUD, test, and the picker routes `…/secrets`, `…/keys`, `…/check-ref`, which return paths and key names, never values), `[copy.go:copyRoutes]` (`POST …/connections:copy`, `POST …/secret-stores/{store_id}/copy` to another project), `[runtimes.go:runtimeRoutes]` (runtime kinds, CRUD, `…/agent-token` rotation, `…/test`, `runtimes:test` for a draft). `…/test` calls the runtime and rewrites its test result and capacity, so it needs `runtime.manage` (404 for a runtime outside the project first).
  - `[pipelines.go:pipelineRoutes]` (CRUD, versions, preflight, deploy, pause/resume/restart, `cluster:shrink`, config, logs, events, snapshots (no engine check — known issue, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues) (10)), metrics, offsets + `offsets/reset`, positions + `positions/{position_id}/restore`, diff, schema + `schema/review`), `[manifests.go:manifestRoutes]` (per-pipeline manifest, `pipelines:export`, `pipelines:apply`, `pipelines:adopt`, `…/promote`), `[transforms.go:transformRoutes]` (`POST …/transforms:preview`, `pipeline.view`, pure, at most `[transforms.go:maxPreviewColumns]` columns), `[images.go:imageRoutes]` (`GET …/debezium-images`, `debezium-images:effects`, `debezium-images:apply`), `[templates.go:templateRoutes]` (list on `pipeline.view`; publish/edit/delete on `project.manage`; tables are stripped by `[templates.go:stripTables]`), `[approvals.go:approvalRoutes]` (change requests list/approve/reject/cancel, `GET|PUT …/policies`, `POST …/policies/setting-limits:impact` for `project.manage`).
  - `[settings.go:settingsRoutes]` (`pipeline.view`): `GET …/pipelines/{id}/settings` (`services.PipelineSettings`), `POST …/settings:classify` (pure, at most `[settings.go:maxClassify]` keys, values never echoed) and `POST …/cluster:pack` (`services.PreviewCluster`; 422 `engine_settings` unless the pipeline runs on Flink CDC). `POST …/cluster:shrink` (`pipeline.operate`) is in `pipelineRoutes`; `POST …/debezium-images:effects` (`services.ImageEffects`) is in `imageRoutes`.
  - `[alerts.go:alertRoutes]` (alerts + acknowledge, rules, channels + test, per-user notifications), `[stream.go:streamRoutes]` (SSE), `[catalog.go:catalogRoutes]` (`/engines` with availability, default image, supported sources/sinks and each engine's registry settings, plus the size presets for Flink CDC only; the per-engine image catalog `/debezium-catalog?engine=`, `[catalog.go:catalogEngine]`), `[feedback.go:feedbackRoutes]` (`POST …/feedback` for any project member; Admin list/resolve), `[agent.go:agentRoutes]` (`POST /agent/poll`).
  - `[mcp.go:mcpRoutes]` (MCP info/settings/tools/clients/grants, OAuth consent, and through `[mcp.go:oauthProtocolRoutes]` `/oauth/register|authorize|token|revoke`) and `[mcp.go:oauthDiscoveryRoutes]` (RFC 8414 / 9728 documents).
- Response shapes (ordered JSON fields), e.g. `[auth.go:MeRead]`, `[projects.go:ProjectRead]`, `[projects.go:MemberRead]`, `[projects.go:EventRead]`, `[pipelines.go:PipelineRead]`, `[pipelines.go:SchemaRead]`, `[connections.go:ConnectionRead]`, `[secret_stores.go:StoreRead]`, `[runtimes.go:RuntimeRead]` (with `placement_profiles`), `[pipelines.go:FootprintRead]` (a pipeline's peak `footprint`), `[alerts.go:ChannelRead]`, `[templates.go:TemplateRead]`, `[approvals.go:ChangeRequestRead]`, `[users.go:UserAdminRead]`, `[sso_providers.go:SSOProviderRead]`, `[feedback.go:FeedbackRead]`, `[mcp.go:MCPSettingsRead]`, `[projects.go:Page]`.
- Constants: `[agent.go:AgentPollSeconds]` (2), `[projects.go:SlugRe]` (slug grammar).
- Shared handler helpers: `[api.go:principal]`, `[api.go:superuser]`, `[api.go:project]`, `[api.go:pathID]`, `[pipelines.go:pipelineAction]`, `[pipelines.go:viewPipeline]`, `[api.go:body]` / `[api.go:optBody]`, `[api.go:paginate]`, `[api.go:tx]` / `[api.go:dryTx]`, `[connections.go:parseIfMatch]`, `[connections.go:requireManage]`, `[auth.go:interactive]`, `[auth.go:safeNext]`, `[api.go:obj]`.

## Invariants
- Project routes resolve `{project_id}` with `[api.go:project]` (unknown and unauthorised are both 404) and then ask for a `Perm` via `Require`; never a role name. Admin-only routes use `[api.go:superuser]` (users, `POST`/`DELETE /projects`, SSO providers, Debezium catalog writes, MCP settings/tools/clients and `GET /mcp/grants?all=true`, feedback list/resolve, telemetry).
- Most pipeline mutations go through `[pipelines.go:pipelineAction]`: path id, project, permission, then the change and the re-read in one transaction. `PATCH` and `deploy` validate the body first but still report an authentication/project failure before a validation error.
- Versioned edits (`PATCH` of pipelines, connections, runtimes, secret stores, templates and SSO providers) require `If-Match` with the edited version: missing is 428 `precondition_required`, malformed 400 `bad_if_match` (`[connections.go:parseIfMatch]`), stale 412 `version_conflict`. `PUT …/policies` and alert rule/channel edits take no `If-Match` (last write wins).
- Pipeline permissions (`[pipelines.go:pipelineRoutes]`): reads, versions, preflight, config, metrics, offsets, positions, diff and schema need `pipeline.view`; create and `PATCH` `pipeline.edit`; deploy and `DELETE` `pipeline.deploy`; pause/resume/restart, `cluster:shrink`, snapshots and `schema/review` `pipeline.operate`; events (destination preview) `pipeline.preview_data`; `offsets/reset` and position restore `offsets.reset` with `confirm` equal to the pipeline name (422 `confirmation_mismatch`). Labels follow `domain.LabelsValid` (at most 20, slug keys, values ≤ 63) on create (`[pipelines.go:labelsOf]`) and, when they change, on `PATCH` (422 at `body.labels`); labels a pipeline already holds save unchanged.
- `debezium-images:apply` needs `pipeline.edit`, plus `pipeline.deploy` when `deploy` is true (the default), and takes 1–200 pipeline ids (`[images.go:uuidList]`).
- Secrets are write-only: connection, runtime, secret-store and alert-channel reads return only `secret_fields_set` (and secret refs) and `[sso_providers.go:SSOProviderRead]` has no secret field; a `PATCH` merges sent secrets into the stored ones with `services.MergeSecrets` and re-encrypts them, and audit details carry field names only (`[connections.go:ConnectionRead]`, `[runtimes.go:RuntimeRead]`, `[secret_stores.go:StoreRead]`, `[alerts.go:ChannelRead]`). A runtime agent token is shown once, with its install command, on create or rotation (`[runtimes.go:installCommand]`). Secret-store pickers and `check-ref` never return a value (`[secret_stores.go:StoreSecrets]`, `[secret_stores.go:SecretKeys]`).
- Secret stores are tested on create and on `PATCH`; the result is saved in `last_test`, and only a request with `test_first: true` (default `false`) is refused when the test fails (422 `store_test_failed`, nothing saved). A store still referenced by connections cannot be deleted (409 `secret_store_in_use`) (`[secret_stores.go:secretStoreRoutes]`).
- Secret-store permissions: list needs `connection.view`; create, `PATCH` and `DELETE` `project.manage`; test and the pickers (`…/secrets`, `…/keys`, `…/check-ref`) `connection.manage`. Copying to another project (`[copy.go:copyRoutes]`) needs `connection.manage` in both projects, plus `project.manage` (403 `admins_only`) to copy saved secrets or secret stores.
- Runtimes: changing a runtime's config while any of its pipelines is desired `running` is 409 `runtime_busy`, while placement profiles change without a pause; `DELETE` is 409 `runtime_in_use` while live pipelines remain (`[runtimes.go:runtimeRoutes]`).
- Connections: deleting one used by pipelines or linked connections is 409 `connection_in_use` (`connection_in_history` for deleted pipelines), and managed connections also need `project.manage` (`[connections.go:requireManage]`).
- `PUT …/policies` validates only new or changed setting limits, so a stored limit the registry later dropped is kept, while `setting-limits:impact` validates every submitted limit (`[approvals.go:approvalRoutes]`).
- Users: an Admin cannot demote or deactivate themselves, and the last active Admin cannot be removed (409 `last_superuser`, `[users.go:ensureOtherSuperuser]`); deactivation ends the person's sessions.
- API-token management, OAuth consent, `PUT /mcp/settings` and `PATCH|DELETE /mcp/clients/{client_id}` need a signed-in session; a token-authenticated request is 403 `session_required` (`[auth.go:interactive]`). `POST …/feedback` refuses API tokens with the same code through its own check (`[feedback.go:feedbackRoutes]`).
- Project permissions (`[projects.go:projectRoutes]`, `[approvals.go:approvalRoutes]`): `PATCH /projects/{id}` and `PUT …/policies` need `project.manage`; `PUT|DELETE …/members` `member.manage`; `GET …/audit:export` and `GET …/events?audit_only=true` `audit.view`. `PUT …/members` with an unknown email creates an active user with the given `initial_password` (12–1024 characters) or a random one.
- Deploy creates a change request (202) instead of deploying when the project requires approval (`[pipelines.go:pipelineRoutes]`).
- `DELETE /pipelines/{id}` needs `pipeline.deploy`, and MCP `delete_pipeline` asks for the same.
- `DELETE /projects/{id}` is refused with 409 `project_not_empty` while it has live pipelines, then with 409 `project_busy` while a `cleanup` job is `queued` or `running`, and `DELETE /runtimes/{id}` (409 `runtime_cleanup_pending`) while any job of its pipelines is; a job left `running` by a crashed controller is never reclaimed, so both stay blocked — known issue, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues) (`[projects.go:projectRoutes]`, `[runtimes.go:runtimeRoutes]`).
- Writes run inside `[api.go:tx]`; `dry_run` requests run the same code in a transaction that is rolled back (`[api.go:dryTx]`). Audit events are written with `services.Record` here or in the called service.
- Paged lists (`GET …/events`, `GET /users`, and the Admin feedback list in its service) use keyset pagination through `services.PageSQL` with the limit clamped by `services.ClampLimit` (`[api.go:paginate]`). Other lists are plain arrays: projects, members, connections, runtimes, pipelines (by name, silently capped at 500, `[pipelines.go:pipelineRoutes]`), and change requests (newest 200).
- Login: password sign-in can be turned off (403 `password_login_disabled`); attempts are limited per client address + lower-cased email (`ratelimit.Login`) and the counter resets on success; any failure is the same 401 `invalid_credentials` (`[auth.go:authRoutes]`).
- Connection checks (`…/check`, `connections:check`) are limited per user (`ratelimit.Check`); `…/discover` has no limit. OAuth register and token requests are limited per client address (`[connections.go:connectionRoutes]`, `[mcp.go:oauthProtocolRoutes]`).
- Post-sign-in redirects only go to same-site paths: leading `/`, not `//`, no backslash, else `/` (`[auth.go:safeNext]`). SSO sign-in failures from the IdP exchange (`oidc`/`samlsp` errors) redirect to `/login?error=…`; an unknown or disabled provider is JSON 404 `sso_disabled` and a malformed `next` or callback query value a JSON 422 (`[auth.go:ssoRoutes]`).
- SAML: the ACS body is capped at `4*samlsp.MaxMetadata+4096`; the response is verified and marked used in its own transaction before the user is synced, so a later failure cannot make it reusable; the relay cookie is `SameSite=None` only when cookies are Secure (`[auth.go:samlRoutes]`, `[auth.go:samlRelayCookie]`).
- OAuth (MCP agents): only public clients with PKCE; an authorize request or code exchange naming another `resource` is `invalid_target`; authorize errors go back to the agent's redirect URI only once the client and that URI are known, else to `/oauth/consent?error=…`; a refused token request still commits what the error path wrote (reuse revocation) (`[mcp.go:oauthProtocolRoutes]`). Register, token and revoke bodies are capped at 64 KiB. While MCP or agent sign-in is off (`[mcp.go:oauthEnabled]`), `POST /oauth/register` and the `/.well-known/…` documents (`[mcp.go:oauthDiscoveryRoutes]`) are 404 `oauth_disabled`, `GET /oauth/authorize` redirects to `/oauth/consent?error=…`, `POST /oauth/token` is 400 `invalid_client`, consent approval is 409 `oauth_disabled`, and `POST /oauth/revoke` still revokes. Approving a consent request for a pending client needs an Admin with `allow_agent` (409 `agent_pending`), and `days` cannot exceed the configured maximum (422 `too_long`).
- `POST /agent/poll` authenticates with a `bza_` runtime agent token (rehashed after key rotation), requires `mode = agent` and a matching kind, and returns decrypted workload specs and pending requests only for that runtime; Flink CDC workloads are withheld from agents that do not report the feature. A bad token is 401 `invalid_agent_token` and a kind mismatch 409 `agent_kind_mismatch`. The body is validated before the token, so a malformed poll is 422 even without a token (`[agent.go:agentRoutes]`).
- `/metrics` is 404 unless `BEZISYNC_METRICS_TOKEN` is set, and then needs that bearer token (constant-time compare) (`[system.go:prometheus]`).
- The SSE stream checks `pipeline.view` once when it opens (`[stream.go:streamRoutes]`).
- Routes and `openapi.json` must agree (`TestRoutesMatchOpenAPI`); change both together and run `make openapi`.

## Side Effects
- DB writes, directly or via services: `users`, `user_sessions` (via `auth`; deleted on deactivation), `api_tokens` (hash + 10-character prefix only), `memberships`, `projects` (incl. `policies`), `connections` (incl. `last_check`), `secret_stores`, `runtimes` (agent heartbeat/state, capacity, agent token hash, `last_test`), `agent_requests` (results), `sso_providers` (incl. `last_test`), `instance_state` (SAML SP keys on first metadata request), `alert_channels` (`last_delivery_at` / `last_error`), `notifications` (read-all), `schema_changes` and `pipelines.status` (`schema/review`), OAuth tables, and every resource the routes manage. Audit events via `services.Record`, e.g. `auth.login`, `token.*`, `project.*`, `member.*`, `connection.*`, `runtime.*`, `secret_store.*`, `template.*`, `alert_rule.*`, `alert_channel.*`, `sso_provider.*`, `user.*`, `mcp.client_*`, `debezium_image.*`, `pipelines.applied`, `pipeline.promoted`, `pipeline.snapshot_requested`, `pipeline.schema_reviewed`, `pipeline.image_changed`, `project.policies_updated`.
- Jobs: `POST …/snapshots` enqueues a `snapshot` job (`services.Enqueue`) after checking only the source's `capture.Incremental` and that the tables are captured, with no engine check, so a Flink CDC pipeline is accepted too (`[pipelines.go:pipelineRoutes]`) — known issue, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues) (10).
- The agent poll returns decrypted `agent_workloads` specs and `agent_requests` arguments to the polling agent (`[agent.go:agentRoutes]`).
- Cookies: `bz_session` / `bz_csrf` (via `auth`), `bz_oidc` (path `/api/v1/auth/oidc`), `bz_saml` (path ACS).
- Outbound calls through services and the SSRF guard: connection checks and discovery, runtime tests (Docker/Kubernetes drivers), secret-store tests and listings, alert channel test deliveries (`services.Deliver`), runtime logs and destination tails (pipeline logs and events), IdP discovery/token/userinfo (`oidc`); not every connector or alert path keeps the guard on the final request, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues) (1). SAML metadata fetches and SSO provider tests are made here with `ssrf.HTTPClient` (10 s) (`[sso_kinds.go:fetchMetadata]`, `[sso_kinds.go:testProvider]`).
- Process state: in-memory rate limiters; each open SSE stream keeps its request goroutine and queries `pipelines` on a 2 s poll ticker, with a 15 s ping ticker (`[stream.go:streamPoll]`, `[stream.go:streamPing]`). `GET /system/telemetry` persists the install id on first use.
- Reads `config.Get()`: `CORSOrigins`, `CookieSecure`, `PublicURL`, `AgentURL`, `AgentImage`, `AgentChart`, `AgentChartVersion` (agent install command), `MetricsToken`, `Environment`, `AllowPlainHTTP`, telemetry settings, `Lab`. Logs via `slog` (e.g. `bezisync.api.stream`).
