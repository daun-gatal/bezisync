# lib

## Overview
The web UI's data and domain layer: the typed API client, the session and project context, one TanStack Query hook module per API area, and pure helpers (formatting, status, errors, secret references). Screens in `features/` and the shell in `app/` mostly use these hooks; some feature files (for example `features/settings/RuntimesSection.tsx`, `features/account/TokensSection.tsx`, `features/mcp/mcp.ts`) call `[api.ts:client]` + `[api.ts:unwrap]` directly, so every request still goes through one client.

## Interface
- `[api.ts:client]` — the `openapi-fetch` client typed by `[api-schema.ts:paths]`; `[api.ts:unwrap]` turns a result into data or throws `[api.ts:ApiError]` (wrapping a `[api.ts:Problem]`); `[api.ts:problemMessage]`, `[api.ts:readCookie]`, `[api.ts:setUnauthorizedHandler]`, `[api.ts:Schemas]` (the component schemas).
- `[api-schema.ts:paths]`, `[api-schema.ts:components]`, `[api-schema.ts:operations]` — generated from `frontend/openapi.json`; never edited by hand.
- `[session.tsx:useMeQuery]` (`[session.tsx:meKey]`), `[session.tsx:useProviders]`, `[session.tsx:useLogin]`, `[session.tsx:useLogout]`, `[session.tsx:useUpdateMe]` — the signed-in person and sign-in options.
- `[session.tsx:ProjectProvider]` / `[session.tsx:useProject]` — the current project, `can(permission)` and `expert` mode for everything inside a project route.
- API-area hooks: `[pipelines.ts:usePipelines]` / `[pipelines.ts:usePipeline]` and the rest of `pipelines.ts` (create/`[pipelines.ts:useUpdatePipeline]`, preflight, deploy, lifecycle, `[pipelines.ts:useShrinkCluster]` (a custom Flink CDC cluster's `cluster:shrink` to its streaming shape), delete, snapshots, versions, config, logs, events, activity, metrics, offsets and saved positions, diff, change-request decisions, schema review); `[connections.ts:useConnections]` with `[connections.ts:useConnectorTypes]`, the create/update/delete/check mutations, `[connections.ts:useDraftCheck]`, `[connections.ts:useDiscovery]` and the capability helpers `[connections.ts:sinkCapsOf]` / `[connections.ts:captureOf]` (`[connections.ts:TYPE_LABEL]`); `[alerts.ts:useAlerts]`, `[alerts.ts:useAcknowledge]`, rules and channels (`[alerts.ts:useRules]`, `[alerts.ts:useChannels]`, `[alerts.ts:useChannelKinds]`, `[alerts.ts:useTestChannel]`, …), `[alerts.ts:useInbox]` / `[alerts.ts:useReadAll]`; `[debezium.ts:useCatalog]` / `[debezium.ts:useDebeziumImages]` (with `[debezium.ts:imageByPipeline]`, `[debezium.ts:shortImage]`); `[engines.ts:useEngines]` / `[engines.ts:useEngineCatalog]`; `[policies.ts:usePolicies]`; `[templates.ts:useTemplates]` (create, delete, `[templates.ts:templateSummary]`); `[copy.ts:useCopyTargets]` / `[copy.ts:useCopyConnections]` (`[copy.ts:savedSecrets]`, `[copy.ts:missingLabel]`); `[secretRefs.ts:useSecretStores]`, `[secretRefs.ts:useStoreSecrets]`, `[secretRefs.ts:useSecretKeys]`, `[secretRefs.ts:useRefCheck]`; `[transforms.ts:useTransformPreview]`; `[about.ts:useSystemInfo]` (plus `[about.ts:REPO_URL]`, `[about.ts:WEB_LICENSES_URL]`, `[about.ts:SERVER_LICENSES_URL]`); `[useAlertCount.ts:useAlertCount]` (firing alerts among the open ones).
- `[paging.ts:useCursorPages]` — pages a cursor-paged endpoint at the viewer's page size.
- `[useLiveUpdates.ts:useLiveUpdates]` — the project's server-sent event stream, refreshing pipeline queries.
- Pipeline status: `[status.tsx:statusOf]`, `[status.tsx:isStale]`, `[status.tsx:HealthBadge]`, `[status.tsx:LifecycleBadge]`, `[status.tsx:needsAttention]`, `[status.tsx:pipelineTone]`, `[status.tsx:fleetGroup]` (`[status.tsx:FLEET]`), `[status.tsx:snapshotProgress]`, the label tables `[status.tsx:LIFECYCLE]` / `[status.tsx:HEALTH]`.
- Errors: `[errors.ts:describeError]` (what happened, why, what to do, request ID), `[errors.ts:isRetryable]`, `[errors.ts:wrongPassword]`.
- Engines: `[engines.ts:engineGate]`, `[engines.ts:runs]`, `[engines.ts:engineChoices]`, `[engines.ts:pickEngine]`, `[engines.ts:flinkChoices]` (`[engines.ts:FlinkChoices]`, `[engines.ts:FlinkCluster]`), `[engines.ts:flinkSpecBlock]`, `[engines.ts:ENGINE_TITLE]`, `[engines.ts:ENGINE_PITCH]`.
- Settings: `[settings.ts:Setting]` and `[settings.ts:Impact]` (the server registry's types), `[settings.ts:IMPACT]` / `[settings.ts:IMPACT_ORDER]` / `[settings.ts:heaviest]`, `[settings.ts:STAGES]`, `[settings.ts:tuningSettings]`, `[settings.ts:settingError]` / `[settings.ts:canonicalSetting]` (mirror `engine.CheckSetting` / `CanonicalSetting`), `[settings.ts:jsonbSorted]`, `[settings.ts:useClassify]`.

## Invariants
- Every API call goes through `[api.ts:client]` + `[api.ts:unwrap]` (the event stream in `[useLiveUpdates.ts:useLiveUpdates]` is the one exception): the `csrf` middleware adds `x-csrf-token` from the `bz_csrf` cookie on POST, PUT, PATCH and DELETE, and failures become `[api.ts:ApiError]` (a fetch that throws becomes status 0 `network_error`).
- A 401 calls the handler set with `[api.ts:setUnauthorizedHandler]`, except for URLs ending in `/auth/login` or `/auth/me`, so a failed sign-in or the initial session probe never triggers the expiry flow. The `/auth/me` test ignores the method, so a 401 on `PATCH /auth/me` (`[session.tsx:useUpdateMe]`: Guided/Expert mode, notification settings) does not open the sign-in dialog either — known issue, see [ARCHITECTURE.md › Known issues](../../../ARCHITECTURE.md#known-issues).
- `api-schema.ts` is regenerated with `make openapi` after any backend API change (`bun run check:api` fails on drift).
- `[session.tsx:useProject]` throws outside a `[session.tsx:ProjectProvider]`; `can` is exactly membership in `project.permissions`.
- Updates are conditional: `[pipelines.ts:useUpdatePipeline]` and `[connections.ts:useUpdateConnection]` send `If-Match: "<version>"` with the version the caller read, so the server refuses a save over someone else's change. Pipeline mutations put the returned pipeline in its query and invalidate the list and that pipeline's `versions`, `config` and `diff` (`[pipelines.ts:useInvalidate]`), because a save may rewrite the draft version in place.
- Health is evidence-based: `[status.tsx:isStale]` treats the status of a deployed pipeline that is not paused, deleted or a draft as stale once its `as_of` is older than `[status.tsx:STALE_AFTER_MS]` (60 s) — a status with no `as_of` is never stale, and the badge then shows its `health` value — and `[status.tsx:HealthBadge]` shows Stale (grey) before any health value; an unknown health falls back to Unknown.
- `[secretRefs.ts:parseRef]` uses the same `ref+<store>://<path>#<key>` grammar as the backend's `internal/secrets` ParseRef; keep them in step.
- `[feedback.ts:FEEDBACK_KINDS]` mirrors the backend's feedback kinds and `[feedback.ts:MAX_FEEDBACK]` is 5000.
- `[policies.ts:allows]` treats a null or missing list as "everything allowed"; `[policies.ts:sizeAllowed]` compares against `[policies.ts:SIZES]` order.
- `[settings.ts:settingError]` and `[settings.ts:canonicalSetting]` must agree with the backend's `engine.CheckSetting` and `CanonicalSetting`; the server re-checks every save. Maps the wizard compares with a stored spec are put in JSONB key order first (`[settings.ts:jsonbSorted]`), or a draft looks changed forever and keeps saving.
- Clusters are packed by the server (`[cluster.ts:usePackCluster]`), never in the browser, so the preview matches what a deploy packs. `[cluster.ts:streamingError]` and `[cluster.ts:manualError]` mirror the backend's `domain` `decodeCluster`, and the size choices (`[cluster.ts:SLOT_CPUS]` …) its bounds in `domain/cluster.go`; `[engines.ts:flinkSpecBlock]` writes the block in the order the server dumps it (`dumpFlinkCDC`, `flink_conf` keys in JSONB order) so autosave settles.
- `[settings.ts:tuningSettings]` mirrors the backend's `engine.SettingsFor` and `TuningScopes` (a Flink CDC pipeline's engine-scope settings live in `flink_conf`, not `tuning`); `[engines.ts:runs]` and `[engines.ts:pickEngine]` mirror `engine.Supports` and `services.ChooseEngine`.
- `[settings.ts:useClassify]` and `[cluster.ts:usePackCluster]` ask the server only after their input has been unchanged for 300 ms (`useDebounced` on a JSON string) and keep the previous answer while a new one loads.
- `[paging.ts:useCursorPages]` restarts from the newest page when its key or page size changes, and only the newest page polls.
- Local storage access is wrapped so blocked storage never throws (`[tour.ts:readTourSeen]`; `[theme.ts:readTheme]` via `components/ui/hooks`).

## Side Effects
- HTTP to `/api/v1/**` (same-origin, cookies) through `[api.ts:client]`; reads the `bz_csrf` cookie. Two reads are POSTs run as queries: `settings:classify` (`[settings.ts:useClassify]`) and `cluster:pack` (`[cluster.ts:usePackCluster]`).
- Polling via `refetchInterval`: pipelines 5 s (2 s while deploying, deleting or snapshotting, `[pipelines.ts:usePipeline]`) and 5–30 s for other pipeline views, alerts 10 s, inbox 15 s, Debezium images 10 s.
- `[useLiveUpdates.ts:useLiveUpdates]` opens an `EventSource` on `/api/v1/projects/{id}/stream` (with credentials), invalidates the project's `pipelines` list and the named `pipeline` on each `pipeline` event, and closes it on unmount.
- `localStorage`: `bz.theme` (`[theme.ts:THEME_KEY]`), `bz.tour.seen` (`tour.ts`); `[theme.ts:setTheme]` sets or removes `data-theme` on `<html>` and dispatches a `bz:theme` window event.
- `[session.tsx:useLogout]` clears the whole query cache and navigates to `/login` with `window.location.assign`, whether or not the logout request succeeded.
