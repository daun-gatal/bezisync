# pipelines

## Overview
Everything about pipelines in the browser: the list (`/p/$projectSlug/pipelines`), the wizard that creates and edits a draft (`/pipelines/new`), and one pipeline's page (`/pipelines/$pipelineId`). This directory holds the pages, the import/upgrade dialogs and the client-side spec model (`spec.ts`) every step and tab reads; the wizard steps, pipeline-page tabs and Transform step live in the subdirectories. Server state comes from `lib/pipelines.ts`.

## Interface
- `[PipelinesPage.tsx:PipelinesPage]` — the list with fleet-health filter (`[FleetHealth.tsx:FleetHealth]`), search/paging and the `?debezium=` image filter in the URL, an Engine column (Flink CDC rows show — for the Debezium image), multi-select Change Debezium version, Apply YAML and Adopt.
- `[NewPipelinePage.tsx:NewPipelinePage]` — the wizard shell: picks the step from `?step=`/`?draft=`, saves the current step before moving, asks before leaving with unsaved changes, and offers to keep or delete a draft created in this tab.
- `[PipelinePage.tsx:PipelinePage]` — header with health/lifecycle, one primary action by state, operate menu (pause/resume/restart), a "Change" menu into the wizard (`tables`, `sink`, `transform`, `review`) for a non-draft pipeline with `pipeline.edit`, Delete, approval banner, and the tabs from [page](./page/README.md).
- `[ImportDialogs.tsx:ApplyYamlDialog]` / `[ImportDialogs.tsx:AdoptDialog]` — apply `kind: Pipeline` YAML (preview, then apply, optionally deploy) and adopt an existing Debezium Server's properties (the draft is created from the server's import `plan`: typed settings in `tuning`, masked and excluded columns mapped) as a draft; `DiffLines`, `ApplyResults`, `[ImportDialogs.tsx:ImportBuckets]` render results.
- `[ChangeDebeziumDialog.tsx:ChangeDebeziumDialog]` — set the Debezium image (or the default) for one or more pipelines, optionally deploying, after showing what the move changes in their settings (`debezium-images:effects`; a blocking effect is shown red).
- `[spec.ts:fullSpec]` / `[spec.ts:FullSpec]` / `[spec.ts:specForEngine]` / `[spec.ts:tuningFor]` — the spec with every default filled (typed engine settings in `tuning`, `placement`, `custom_resources` kept as given), and stripped to one engine's settings; `TransformStep` and related types; `stageOf`, `withShape`, `pruneToTables`; naming (`destinationFor`, `namingError`, `sinkDestinationFor`, `sinkNamingError`), `parseAdvanced`, `deriveSinkOptions` (with `[spec.ts:rederiveTableKeys]` for a key changed in Transform and `[spec.ts:keepPartitionBy]` for the Destination step, ADR 0007), `optionsSchemaFor`, `[spec.ts:flinkSinkOptions]`, `SNAPSHOT_MODES`, `RESOURCES`; custom sizes `[spec.ts:CUSTOM_CPUS]`, `CUSTOM_MEMORIES`, `PRESET_AMOUNTS`, `memoryMiB`, `heapMiB` (also read by the Review step and Settings → Policies).
- `[useSaveSpec.ts:useSaveSpec]` / `[useSaveSpec.ts:StepHandle]` / `[useSaveSpec.ts:SaveBody]` — the save every wizard step uses and the contract a step gives the wizard.
- Subdirectories: [page](./page/README.md) — the pipeline page's tabs; [transforms](./transforms/README.md) — the Transform step and its model; [wizard](./wizard/README.md) — the other wizard steps.

## Invariants
- `[spec.ts:fullSpec]` keeps fields it does not know, so saving from the wizard never drops settings made through YAML or the API.
- `[spec.ts:specForEngine]`: Flink CDC drops `values` and resets `debezium_image` (null), `advanced` (`{}`) and the snapshot delay/window (0/null); Debezium drops `flink_cdc` and `flink_cdc_image`. Both keep only their own typed settings (`[spec.ts:tuningFor]`: `debezium.` keys for Debezium, the rest for Flink CDC), and omit `tuning` when none are left.
- `[spec.ts:namingError]` requires `{table}`, only `{schema}`, `{table}`, `{pipeline}` placeholders, and otherwise letters, digits, `.`, `_`, `-`; `[spec.ts:sinkNamingError]` adds each destination's pattern and length limits for every captured table.
- `[useSaveSpec.ts:useSaveSpec]` saves through `useUpdatePipeline`, which sends `if-match` with the pipeline `version` (optimistic concurrency); it resolves to false instead of throwing and leaves the error for the step to show inline. The body always carries `note: ''` and `engine` only when the step sets one (`[useSaveSpec.ts:SaveBody]`).
- Leaving the wizard with a dirty step is blocked (router `useBlocker` plus `beforeunload`); "Save and leave" commits the step first; a locked step in the URL falls back to the first unlocked, unfinished one (`[NewPipelinePage.tsx:NewPipelinePage]`).
- On the pipeline page: operate actions need `pipeline.operate` and a deployed, not-deleting pipeline; edits need `pipeline.edit`; Delete needs `pipeline.deploy` and the typed pipeline name, with "delete destination topics" an explicit choice (`[PipelinePage.tsx:DeleteDialog]`). A `deleting`, `deleted` or `cleanup_failed` pipeline shows only Overview and History and offers no operate, edit or Delete. "Review and deploy" is the primary action only with both `pipeline.deploy` and `pipeline.edit`; Change Debezium version needs `pipeline.edit`, a deployed pipeline and the Debezium engine; the snapshots tab is labelled Positions on Flink CDC.
- Approvals: Approve/Reject need `pipeline.approve` and are hidden from the requester; Reject needs a comment; the requester or an approver may cancel; the banner shows what the requested version does to the output (`OutputImpact`) and what it changes in the settings (`settings_change` from the diff) (`[PipelinePage.tsx:ApprovalBanner]`).
- The list hides `deleted` pipelines; Apply YAML, Adopt and the multi-select for Change Debezium version need `pipeline.edit`, and only pipelines with a deployed Debezium image (an entry from `…/debezium-images`) can be selected (`[PipelinesPage.tsx:PipelinesPage]`).
- Apply YAML must be previewed (dry run) before applying; its deploy option needs `pipeline.deploy`. Adopted drafts are labelled `adopted: "true"` and opened at the Tables step for review (`[ImportDialogs.tsx:AdoptDialog]`).
- Change Debezium version lists only non-deprecated catalogue images plus a typed "Another image…" reference and "Follow the default" (`image: null`), re-fetches the effects 400 ms after the last choice, and deploys only with `pipeline.deploy` (`[ChangeDebeziumDialog.tsx:ChangeDebeziumDialog]`).

## Side Effects
- HTTP via `[../../lib/pipelines.ts:usePipelines]` and siblings: `GET/POST …/pipelines`, `GET/PATCH/DELETE …/pipelines/{pipeline_id}` (delete with `drop_destinations`; the wizard's draft delete sends `false`), `GET …/pipelines/{pipeline_id}/diff` (approval banner), `POST …/pause|resume|restart`, `POST …/change-requests/{request_id}/approve|reject|cancel`.
- `POST …/pipelines:apply`, `POST …/pipelines:adopt`, `POST …/debezium-images:apply`, `POST …/debezium-images:effects`; reads `GET /api/v1/debezium-catalog` and `GET …/debezium-images`. Adopt reads `GET …/connections` and `GET …/runtimes` and creates its draft with a direct `POST /api/v1/projects/{project_id}/pipelines`.
- Polling: the list refetches every 5 s and one pipeline every 5 s (2 s while `deploying`, `deleting` or `snapshotting`), defined in `[../../lib/pipelines.ts:usePipeline]`.
