# transforms

## Overview
The wizard's Transform step: an ordered chain of steps that changes events on their way (event shape, keep only some events, rename, add field, flatten, outbox, custom SMT), value formats and message key columns. `model.ts` is the pure, tested model (stages, validation, impact); the components render and preview it. On Flink CDC the same spec describes rows and columns written into tables, and Debezium-only steps are refused.

## Interface
- `[TransformStep.tsx:TransformStep]` — the wizard step; implements `StepHandle` (`dirty`/`commit`) from `../useSaveSpec.ts` and saves `transforms`, `values` and `keys` into the spec, and for Iceberg `sink.options.partition_by` (ADR 0007), the whole draft in the server key order (`[../spec.ts:inServerOrder]`) so an unchanged step saves nothing; Continue and its save wait on `partitionError` (with tables routed together checked as the server does). It never saves the recorded automatic keys: Destination and Review do. On Flink CDC Continue and its save also wait on `[model.ts:flinkKeyProblem]` for every table whose columns are known (ADR 0010).
- `[editors.tsx:ShapeEditor]` (its Deletes choice is locked and says why while Keep deleted rows or the destination decides), `[editors.tsx:SoftDeleteEditor]`, `[editors.tsx:FilterEditor]`, `[editors.tsx:RenameEditor]`, `[editors.tsx:AddFieldEditor]`, `[editors.tsx:FlattenEditor]`, `[editors.tsx:CustomEditor]`, `[editors.tsx:ValuesEditor]`, `[editors.tsx:KeysEditor]` — one editor per step type plus value formats and keys (the outbox step has no editor: YAML or the API only); `EditorContext`, `Row`, `Segmented` are shared. The key editor (ADR 0010) offers `[model.ts:keyChoices]` with each column's type: on Flink CDC every column the table writes (source columns under their written names, stored by source name; added fields; computed columns, disabled with the reason when `[model.ts:computedKeyProblem]` or, for an expression, the server's check through `[../../../lib/transforms.ts:useExpressionChecks]` and `[model.ts:expressionKeyProblem]` (the server's `key_problem`; pending or failed blocks) refuses them; left-out columns disabled); on Debezium the source's columns, with added fields disabled (the message key is built before any step). A chosen column that can't be a key stays ticked so it can be removed, and one the table no longer writes is listed as not written.
- New step types: `[editors.tsx:TruncateEditor]` (`truncate`, sources in `[model.ts:TRUNCATE_SOURCES]`), `[editors.tsx:RouteEditor]` (`route`, `[model.ts:globMatch]`, `[model.ts:routeTargets]`, `[model.ts:routeError]`), `[editors.tsx:ComputedEditor]` (`computed`, Flink CDC only: `[model.ts:COMPUTED_FUNCTIONS]` in `[model.ts:COMPUTED_GROUPS]`, `[model.ts:kindFits]`, `[model.ts:computedError]`, `[model.ts:formulaText]`, `[model.ts:PARSE_DATE_PATTERNS]`; in Expert mode *An expression*, also for Flink CDC filters in `[editors.tsx:FilterEditor]`, through `[ExpressionInput.tsx:ExpressionInput]`, which checks the text on the server (`expressions:check`) and adopts its canonical form: ADR 0008); `soft_delete` writes `[model.ts:SOFT_DELETE_FIELD]`; `[model.ts:FLINK_ONLY_STEPS]`, `[model.ts:FLINK_TITLE]`.
- `[PreviewPanel.tsx:PreviewPanel]` — server-rendered sample event before/after the chain; `[FlinkPreviewPanel.tsx:FlinkPreviewPanel]` — the columns a Flink CDC table gets (`flinkColumns`), computed locally, each with its type (ADR 0010): the source's type for a source column, the kind a step writes for the others (`[model.ts:KIND_NAMES]`, `[model.ts:computedKind]`; an expression's kind from the server's check), and where it comes from (renamed, cut, added, computed).
- `[Impact.tsx:OutputImpact]` / `[Impact.tsx:StepsSummary]` — what changes for consumers versus the deployed version, and a one-line-per-step summary.
- `[EventsMatch.tsx:EventsMatch]` — on the Events tab, compares sampled rows with the fields the deployed chain should produce.
- `[model.ts:shapeIndex]` / `[model.ts:sectionOf]` / `[model.ts:drawOrder]` / `[model.ts:effectiveDeletes]` / `[model.ts:summarizeShape]` / `[model.ts:shapeFields]` / `[model.ts:ShapeCtx]` (types `Section`, `Deletes`, `DeleteMode`) — the event shape as it runs: where the ordering boundary is, where each step is drawn and its number, what a delete really becomes (`envelope`, `rewrite`, `tombstone`, `drop`, `op_marked`, `flink_default`; decided by Keep deleted rows, the destination or the shape step), and the shape in one line; read by ShapeEditor, `[Impact.tsx:StepsSummary]`, `[Impact.tsx:OutputImpact]` (through `[Impact.tsx:useShapeCtx]`) and `../page/overview.ts`.
- `[model.ts:stepErrors]` / `[model.ts:addStep]` / `[model.ts:moveStep]` / `[model.ts:defaultStep]` / `[model.ts:fieldsBefore]` / `[model.ts:outputImpact]` / `[model.ts:stepCaps]` / `[model.ts:flinkColumns]` — the chain model; Flink CDC keys (ADR 0010): `[model.ts:flinkKey]` (mirrors `domain.FlinkKey`: a source column the table writes first, else a step's column; with no columns known, names as they are), `[model.ts:flinkRenames]`, `[model.ts:stepColumns]`, `[model.ts:flinkKeyProblem]` (the first reason a table's key can't key its rows, the primary-key rule included), `[model.ts:computedNeverEmpty]` and `[model.ts:KEY_KINDS]` (held equal to the server by `backend/testdata/key_columns.json`), `[model.ts:expressionKeyBody]`; plus validators `nameError`, `textError`, `parseRuleValue`, column typing `columnKind`/`operatorsFor`, catalogues `TYPE_TITLE`, `KNOWN_CLASSES`, `SCRIPTED_CLASSES`, `DEBEZIUM_ONLY_STEPS`, `FLINK_OPERATIONS`. `[model.ts:summarize]`, `[model.ts:summarizeValues]`, `[model.ts:METADATA]` and `[model.ts:metadataField]` are read by `../page/overview.ts`; `TYPE_TITLE` by Settings → Policies and `columnKind` by `../wizard/PartitionBy.tsx`.


- `[PartitionBy.tsx:PartitionByEditor]` — Iceberg `partition_by` on both engines (ADR 0005), edited in the Transform step's Partition by row (ADR 0007), which reads its draft (renames, computed columns and the key as they change on the same screen). It offers the columns the table writes (`[PartitionBy.tsx:writtenColumns]`: renames per engine (`[PartitionBy.tsx:renamedTo]`), added, computed (Flink CDC) and the engine's own fields, with Debezium's time of the change `__source_ts_ms`), with transforms filtered by the written kind (`[PartitionBy.tsx:partitionKind]`, `[PartitionBy.tsx:PARTITION_TRANSFORMS]`, mirrors of `domain.PartitionKind`/`domain.PartitionTransforms`, tested against `backend/testdata/partition_kinds.json`). On a table upserted by key only key columns can be picked (`[PartitionBy.tsx:equalityFields]`, `[PartitionBy.tsx:columnRefusal]`: others are shown disabled with the reason), and a Debezium table without fields shows its automatic partitioning (`[PartitionBy.tsx:automaticSummary]`). `[PartitionBy.tsx:partitionError]` checks a column on every field, bucket count 1–1024, truncate width 1–1,000,000, no duplicate field, one time transform per column, and (given `[PartitionBy.tsx:writtenByTable]`) the column, kind and key rules; the editor stops offering "add" at 4 fields per table, but `partitionError` does not check that count. `[PartitionBy.tsx:partitionByFor]` drops `__source_ts_ms` fields on Flink CDC (as `specForEngine` does on an engine switch); `[PartitionBy.tsx:cleanPartitionBy]` stores it in the server's JSONB order. `[PartitionBy.tsx:withPartitionBy]` is what the Transform step saves (the same options object when nothing changed, so an unchanged step saves nothing) and `[PartitionBy.tsx:partitionSummary]` / `[PartitionBy.tsx:fieldText]` the row's one-line summary.
## Invariants
- Stage order (`stageOf` in `../spec.ts`): keep-events filters with operations or rules (0) run before the event shape (`unwrap` and `soft_delete`, 1), field changes (`rename`, `add_field`, `flatten`, `custom`, 2) after it; every other step (a `condition`-only filter, `truncate`, `route`, `computed`, `outbox`) is stage -1, kept in written order under "Other steps". The shape boundary for ordering is the first stage-1 step (`[model.ts:shapeIndex]`, mirroring `unwrapAt` in `domain.validateTransforms`): `[model.ts:stepErrors]` flags a stage-0 step after it and a stage-2 step before it or with none. `[model.ts:addStep]` puts a stage-0 step just before the boundary, Keep deleted rows just after the `unwrap` (at the end when there is none), and anything else at the end; `[model.ts:moveStep]` only swaps two adjacent stage-2 steps. Steps are drawn by `[model.ts:sectionOf]` and numbered by `[model.ts:drawOrder]` (keep, event shape, field changes, other; the `unwrap` row before Keep deleted rows): on Debezium Keep deleted rows sits under Event shape, on Flink CDC under Keep rows, duplicates included. Every step except the event-shape row (which has no Remove, and is not drawn on Flink CDC) is drawn with Remove. Nothing reorders a saved spec.
- `[model.ts:stepErrors]` mirrors the backend decoder: a filter needs an operation, a rule or a raw `condition`, every stage-0 rule has a field and its value(s), renames are valid, distinct and not to the same name, added fields pass `nameError` (`NAME_RE`, at most 128 characters) and, for a static value, `textError` (no `${`, no control characters, at most 200 characters), a truncate step needs at least one column and a column on every row, a computed step passes `[model.ts:computedError]` (table, name, function; numbers whole 1–65535; text literals pass `textError`), a route step passes `[model.ts:routeError]` (1–20 routes, `schema.table` patterns, destination names of at most 200 characters; the "one table, two routes" check runs once, on the first route step, against the captured tables), custom steps need a dotted class name. The step cannot advance while any error exists (`[TransformStep.tsx:TransformStep]`). A new filter (`[model.ts:defaultStep]`) has no `match` until it has rules, and removing its last rule drops `match`: the decoder refuses `match` without rules.
- Step availability (`locked` in `[TransformStep.tsx:TransformStep]`): `DEBEZIUM_ONLY_STEPS` are refused on Flink CDC and `FLINK_ONLY_STEPS` (`computed`) on Debezium; custom needs the project policy `allow_custom_transforms` and Expert mode, and is never refused by `allowed_transforms`, which limits the built-in types only, exactly as the server does (`domain.transformPolicyChecks`; `.rules/backend.md`); other types outside `allowed_transforms` are refused; Debezium field steps need an explicit Row after change first (on Flink CDC it is added silently), so the wizard never builds `[soft_delete, rename]` without one (the compiler orders that chain correctly too); Keep deleted rows is offered once ("Already added"). The event shape cannot be removed while field steps or Keep deleted rows exist, or when the destination requires it (`unwrap.required`); on Flink CDC the event shape section is not rendered at all.
- `[model.ts:stepCaps]` drops value formats on Flink CDC and the `epoch` timestamp format for destinations with `time_precision`; Flink CDC never saves `values`, and on Debezium a value format equal to the first choice the source connector type offers (`caps.value_formats[k][0]`, from its `transforms` descriptor through `stepCaps`) is dropped before saving (`[TransformStep.tsx:cleanValues]`).
- Mirrors of backend rules must match them: `[model.ts:globMatch]` and `[model.ts:routeTargets]` follow `domain.GlobMatch` and `RouteTargets` (first match wins; a table two routes match is an error), `[model.ts:COMPUTED_FUNCTIONS]` and `[model.ts:kindFits]` follow `domain.ComputedFunctions` and `KindFits` (held equal by `backend/testdata/computed_functions.json`), `[model.ts:SOFT_DELETE_FIELD]` follows `domain.SoftDeleteField`, and `[model.ts:TRUNCATE_SOURCES]` follows `domain.TruncateSources`. `[model.ts:shapeIndex]` follows `unwrapAt` in `domain.validateTransforms`; `[model.ts:effectiveDeletes]` follows `compiler.withSinkUnwrap` then `withSoftDelete` (Keep deleted rows wins over the destination's Deletes option, read with the option schema's defaults, which wins over the shape step; a mapped option applies only to an unwrap the spec has).
- `[model.ts:newStepId]` gives each step a stable random id unique within the chain; `outputImpact` matches steps by id.
- `[EventsMatch.tsx:EventsMatch]` compares only plain-JSON, non-MongoDB pipelines with an event shape and no embedded schema.

## Side Effects
- HTTP: `POST /api/v1/projects/{project_id}/pipelines/{pipeline_id}/transforms:preview` via `[../../../lib/transforms.ts:useTransformPreview]` (from `PreviewPanel` and `EventsMatch`); `POST …/pipelines/{pipeline_id}/expressions:check` via `[../../../lib/transforms.ts:useExpressionCheck]` (from `ExpressionInput` and `FlinkPreviewPanel`) and `[../../../lib/transforms.ts:useExpressionChecks]` (the Transform step, for expression columns that could key a Flink CDC table); `POST …/connections/{connection_id}/discover` (discovery), `GET …/connector-types`, `GET …/policies`, `GET …/pipelines/{pipeline_id}/versions` (Impact, EventsMatch); saving goes through `useSaveSpec` (`PATCH …/pipelines/{pipeline_id}`).
