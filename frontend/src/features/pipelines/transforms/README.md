# transforms

## Overview
The wizard's Transform step: an ordered chain of steps that changes events on their way (event shape, keep only some events, rename, add field, flatten, outbox, custom SMT), value formats and message key columns. `model.ts` is the pure, tested model (stages, validation, impact); the components render and preview it. On Flink CDC the same spec describes rows and columns written into tables, and Debezium-only steps are refused.

## Interface
- `[TransformStep.tsx:TransformStep]` — the wizard step; implements `StepHandle` (`dirty`/`commit`) from `../useSaveSpec.ts` and saves `transforms`, `values` and `keys` into the spec.
- `[editors.tsx:ShapeEditor]` (its Deletes choice is locked and says why while Keep deleted rows or the destination decides), `[editors.tsx:SoftDeleteEditor]`, `[editors.tsx:FilterEditor]`, `[editors.tsx:RenameEditor]`, `[editors.tsx:AddFieldEditor]`, `[editors.tsx:FlattenEditor]`, `[editors.tsx:CustomEditor]`, `[editors.tsx:ValuesEditor]`, `[editors.tsx:KeysEditor]` — one editor per step type plus value formats and keys (the outbox step has no editor: YAML or the API only); `EditorContext`, `Row`, `Segmented` are shared.
- New step types: `[editors.tsx:TruncateEditor]` (`truncate`, sources in `[model.ts:TRUNCATE_SOURCES]`), `[editors.tsx:RouteEditor]` (`route`, `[model.ts:globMatch]`, `[model.ts:routeTargets]`, `[model.ts:routeError]`), `[editors.tsx:ComputedEditor]` (`computed`, Flink CDC only: `[model.ts:COMPUTED_FUNCTIONS]`, `[model.ts:kindFits]`, `[model.ts:computedError]`, `[model.ts:formulaText]`); `soft_delete` writes `[model.ts:SOFT_DELETE_FIELD]`; `[model.ts:FLINK_ONLY_STEPS]`, `[model.ts:FLINK_TITLE]`.
- `[PreviewPanel.tsx:PreviewPanel]` — server-rendered sample event before/after the chain; `[FlinkPreviewPanel.tsx:FlinkPreviewPanel]` — the columns a Flink CDC table gets (`flinkColumns`), computed locally.
- `[Impact.tsx:OutputImpact]` / `[Impact.tsx:StepsSummary]` — what changes for consumers versus the deployed version, and a one-line-per-step summary.
- `[EventsMatch.tsx:EventsMatch]` — on the Events tab, compares sampled rows with the fields the deployed chain should produce.
- `[model.ts:shapeIndex]` / `[model.ts:sectionOf]` / `[model.ts:drawOrder]` / `[model.ts:effectiveDeletes]` / `[model.ts:summarizeShape]` / `[model.ts:ShapeCtx]` — the event shape as it runs: where the ordering boundary is, where each step is drawn and its number, what a delete really becomes (`envelope`, `rewrite`, `tombstone`, `drop`, `op_marked`, `flink_default`; decided by Keep deleted rows, the destination or the shape step), and the shape in one line; read by ShapeEditor, `[Impact.tsx:StepsSummary]`, `[Impact.tsx:OutputImpact]` (through `[Impact.tsx:useShapeCtx]`) and `../page/overview.ts`.
- `[model.ts:stepErrors]` / `[model.ts:addStep]` / `[model.ts:moveStep]` / `[model.ts:defaultStep]` / `[model.ts:fieldsBefore]` / `[model.ts:outputImpact]` / `[model.ts:stepCaps]` / `[model.ts:flinkColumns]` — the chain model; plus validators `nameError`, `textError`, `parseRuleValue`, column typing `columnKind`/`operatorsFor`, catalogues `TYPE_TITLE`, `KNOWN_CLASSES`, `SCRIPTED_CLASSES`, `DEBEZIUM_ONLY_STEPS`, `FLINK_OPERATIONS`. `[model.ts:summarize]`, `[model.ts:summarizeValues]`, `[model.ts:METADATA]` and `[model.ts:metadataField]` are read by `../page/overview.ts`; `TYPE_TITLE` by Settings → Policies and `columnKind` by `../wizard/PartitionBy.tsx`.

## Invariants
- Stage order (`stageOf` in `../spec.ts`): keep-events filters with operations or rules (0) run before the event shape (`unwrap` and `soft_delete`, 1), field changes (`rename`, `add_field`, `flatten`, `custom`, 2) after it; every other step (a `condition`-only filter, `truncate`, `route`, `computed`, `outbox`) is stage -1, kept in written order under "Other steps". The shape boundary for ordering is the first stage-1 step (`[model.ts:shapeIndex]`, mirroring `unwrapAt` in `domain.validateTransforms`): `[model.ts:stepErrors]` flags a stage-0 step after it and a stage-2 step before it or with none. `[model.ts:addStep]` puts a stage-0 step just before the boundary, Keep deleted rows just after the `unwrap` (at the end when there is none), and anything else at the end; `[model.ts:moveStep]` only swaps two adjacent stage-2 steps. Steps are drawn by `[model.ts:sectionOf]` and numbered by `[model.ts:drawOrder]` (keep, event shape, field changes, other; the `unwrap` row before Keep deleted rows): on Debezium Keep deleted rows sits under Event shape, on Flink CDC under Keep rows, and every step in the spec is drawn with Remove, duplicates included. Nothing reorders a saved spec.
- `[model.ts:stepErrors]` mirrors the backend decoder: a filter needs an operation, a rule or a raw `condition`, every stage-0 rule has a field and its value(s), renames are valid, distinct and not to the same name, added fields pass `nameError` (`NAME_RE`, at most 128 characters) and, for a static value, `textError` (no `${`, no control characters, at most 200 characters), a truncate step needs at least one column and a column on every row, a computed step passes `[model.ts:computedError]` (table, name, function; numbers whole 1–65535; text literals pass `textError`), a route step passes `[model.ts:routeError]` (1–20 routes, `schema.table` patterns, destination names of at most 200 characters; the "one table, two routes" check runs once, on the first route step, against the captured tables), custom steps need a dotted class name. The step cannot advance while any error exists (`[TransformStep.tsx:TransformStep]`). A new filter (`[model.ts:defaultStep]`) has no `match` until it has rules, and removing its last rule drops `match`: the decoder refuses `match` without rules.
- Step availability (`locked` in `[TransformStep.tsx:TransformStep]`): `DEBEZIUM_ONLY_STEPS` are refused on Flink CDC and `FLINK_ONLY_STEPS` (`computed`) on Debezium; custom needs the project policy `allow_custom_transforms` and Expert mode, and returns before the `allowed_transforms` check, so a custom step is never refused by that list — known issue, see [ARCHITECTURE.md › Known issues](../../../../../ARCHITECTURE.md#known-issues); other types outside `allowed_transforms` are refused; Debezium field steps need an explicit Row after change first (on Flink CDC it is added silently), so the wizard never builds `[soft_delete, rename]` without one (see Known issue 18); Keep deleted rows is offered once ("Already added"). The event shape cannot be removed while field steps exist or when the destination requires it (`unwrap.required`); on Flink CDC the event shape section is not rendered at all.
- `[model.ts:stepCaps]` drops value formats on Flink CDC and the `epoch` timestamp format for destinations with `time_precision`; Flink CDC never saves `values`, and on Debezium a value format equal to the first choice the source connector type offers (`caps.value_formats[k][0]`, from its `transforms` descriptor through `stepCaps`) is dropped before saving (`[TransformStep.tsx:cleanValues]`).
- Mirrors of backend rules must match them: `[model.ts:globMatch]` and `[model.ts:routeTargets]` follow `domain.GlobMatch` and `RouteTargets` (first match wins; a table two routes match is an error), `[model.ts:COMPUTED_FUNCTIONS]` and `[model.ts:kindFits]` follow `domain.ComputedFunctions` and `KindFits`, `[model.ts:SOFT_DELETE_FIELD]` follows `domain.SoftDeleteField`, and `[model.ts:TRUNCATE_SOURCES]` follows `domain.TruncateSources`. `[model.ts:shapeIndex]` follows `unwrapAt` in `domain.validateTransforms`; `[model.ts:effectiveDeletes]` follows `compiler.withSinkUnwrap` then `withSoftDelete` (Keep deleted rows wins over the destination's Deletes option, read with the option schema's defaults, which wins over the shape step; a mapped option applies only to an unwrap the spec has).
- `[model.ts:newStepId]` gives each step a stable random id unique within the chain; `outputImpact` matches steps by id.
- `[EventsMatch.tsx:EventsMatch]` compares only plain-JSON, non-MongoDB pipelines with an event shape and no embedded schema.

## Side Effects
- HTTP: `POST /api/v1/projects/{project_id}/pipelines/{pipeline_id}/transforms:preview` via `[../../../lib/transforms.ts:useTransformPreview]` (from `PreviewPanel` and `EventsMatch`); `POST …/connections/{connection_id}/discover` (discovery), `GET …/connector-types`, `GET …/policies`, `GET …/pipelines/{pipeline_id}/versions` (Impact, EventsMatch); saving goes through `useSaveSpec` (`PATCH …/pipelines/{pipeline_id}`).
