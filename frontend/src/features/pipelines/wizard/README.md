# wizard

## Overview
The steps of the pipeline wizard (`/p/$projectSlug/pipelines/new?draft=&step=`), driven by `../NewPipelinePage.tsx`: Source → Tables → Destination → Transform (in [../transforms](../transforms/README.md)) → Review & deploy. Every step edits the same draft pipeline spec and saves through `useSaveSpec` when it is left; `personal.ts` holds the pure personal-data rules logic.

## Interface
- `[shared.tsx:STEPS]` / `[shared.tsx:stepState]` / `[shared.tsx:StepNav]` — step order, done/locked state with the reason, and the step navigation; `StepHeader`, `ConnectionCards` are shared UI; `[shared.tsx:createdHere]` remembers drafts created in this tab.
- `[SourceStep.tsx:SourceStep]` — pick a source connection (only types the project's `allowed_source_types` policy allows, plus an existing pipeline's own source, with a notice naming the allowed types) and optionally a template (sent as `template_id`); a source no engine the project allows can read, and a template whose destination the chosen source can't go to, are disabled with the reason and block Continue (`sourceFit`, `sinkFit`, ADR 0011); run its readiness check (automatically, before a draft exists, when the source was never checked or its last check is over 5 minutes old, otherwise on Re-check), create the draft pipeline.
- `[TablesStep.tsx:TablesStep]` — choose captured tables from discovery and the personal-data choice per column (`[PersonalDataCard.tsx:PersonalDataCard]`).
- `[SinkStep.tsx:SinkStep]` — destination connection (only those an allowed, available engine runs from the source: `sinkFit` hides what no engine or no allowed engine runs, names them under the list by reason, and disables what only an engine that is off writes; the saved destination always shows; nothing is judged before engines and policies load, unreadable policies judge nothing; ADR 0011), engine (Debezium or Flink CDC; a disallowed engine disabled, `pickEngine` prefers allowed ones), naming template, event format and destination options; it carries the stored Iceberg `partition_by` through unchanged (`[../spec.ts:keepPartitionBy]`, dropped for a destination that isn't Iceberg) and only says when it no longer fits, since the Transform step edits it (ADR 0007); on Debezium, when the destination's Deletes option decides the event shape's deletes (`unwrap.delete_handling_from`) and the spec has Keep deleted rows, it notes that Keep deleted rows decides them.
- `[ReviewStep.tsx:ReviewStep]` — warns (without blocking) when the saved Iceberg Partition by no longer fits, with a button back to Transform (the step list can skip it; ADR 0007); name, owner (`[OwnerPicker.tsx:OwnerPicker]`), runtime, snapshot, size, policies, placement profile, engine settings (`SettingsEditor`, with recommendations and the project's limits), raw properties (`RawProperties`), advanced/Flink settings, final checks (preflight) and deploy; `[ReviewStep.tsx:flinkSizeHelp]` describes the Flink cluster size. A Flink CDC pipeline to an event destination (Kafka) is summarised as JSON events with a message key, not tables (ADR 0011).
- `[review.ts:autosaveDecision]` / `[review.ts:isPaused]` / `[review.ts:useAutosave]` / `[review.ts:rawLabel]` — Review's rules: when autosave saves, and the raw properties section's name per engine ("Advanced Debezium properties", "Advanced Flink CDC options").
- `[review.ts:reviewProblems]` / `[review.ts:ReviewProblem]` / `[review.ts:customErrors]` / `[review.ts:problemsSummary]` / `[review.ts:focusReviewField]` — every client-side reason a draft can't be saved, each on its own field (`ReviewField`, the `data-review-field` wrapper), in page order; the badge ("Not saved: fix Memory and 2 more", a button that focuses the first one), the Deploy reason and each field's error read this list. `[BlockingSettings.tsx:BlockingSettings]` lists the engine settings and raw properties that block saving, with Remove, where their editor isn't drawn; `[FlinkClusterEditor.tsx:FlinkClusterEditor]` takes its fields' errors as `errors`.
- `[FlinkSettings.tsx:FlinkRunSettings]` / `[FlinkSettings.tsx:FlinkConfEditor]` / `[FlinkSettings.tsx:BATCH_LOAD_SINKS]` — Flink CDC run settings (worded for events on an event destination, `events`, ADR 0011) and the Expert catalogue editor.
- `[FlinkClusterEditor.tsx:FlinkClusterEditor]` — a custom Flink CDC cluster (readers and per-slot size, or manual TaskManagers), previewed with the server's packing; `[FlinkClusterEditor.tsx:copyMinutes]` estimates the first copy.
- `[personal.ts:defaultsFor]` / `[personal.ts:setChoice]` / `[personal.ts:normalize]` / `[personal.ts:personalRows]` / `[personal.ts:personalProblem]` / `[personal.ts:rulesToSave]` / `[personal.ts:personalSummary]` — mask / remove / keep rules per column; `[personal.ts:canMask]`, `[personal.ts:choiceOf]`, `[personal.ts:safeChoice]` are the per-column helpers the Tables step and `PersonalDataCard` use.

## Invariants
- A step unlocks only when the ones before it are done: tables need a pipeline, the destination needs tables, Transform and Review need a destination whose naming passes `namingError`; a step whose unsaved choices are complete (`ready`) counts as done for the next one (`[shared.tsx:stepState]`).
- Each step implements `StepHandle`: `commit` refuses while the step is invalid (no tables, `missing` destination, invalid review settings) and saves only when dirty, so visiting a step never makes a new version. In Tables a blocking personal-data problem only clears `ready` and disables Continue; `commit` still saves, so leaving through the step list or "Save and leave" saves the blocked choices (`[TablesStep.tsx:TablesStep]`).
- On Flink CDC nothing can be masked (no hash function): the Tables step offers only remove or keep (`maskable = []`).
- Personal data is protected by default: a newly picked table masks each detected column when the source can hash its type, else removes it (`[personal.ts:defaultsFor]`); remove wins over mask, mask over keep (`[personal.ts:normalize]`); a column set to mask that cannot be masked blocks the step (`[personal.ts:personalProblem]`); untouched saved rules are kept as is (`[personal.ts:rulesToSave]`).
- Tables step prunes transforms and keys to the captured tables (`pruneToTables`); the Destination step saves the spec through `specForEngine` so each engine gets only its own settings, and a deployed pipeline keeps its engine and its destination connection (`[SinkStep.tsx:SinkStep]`).
- Draft names are `slugify(<source>-cdc)`, then `<source>-cdc-2`, `-3`… until unique in the project (`[SourceStep.tsx:SourceStep]`).
- Review autosaves 800 ms after the last change (`AUTOSAVE_MS`), one save at a time (`[review.ts:useAutosave]`, deciding with `[review.ts:autosaveDecision]`: first match of not dirty, saving, invalid, paused). A save the server refused pauses autosave on that draft's signature: the next attempt comes only from a change to the draft, Try again (`useAutosave`'s `attempt`, offered for network errors and 5xx and never while the draft has a client-side problem), or leaving the step (`commit` makes one attempt when nothing client-side blocks); the badge reads "Not saved" only while paused; it never retries by itself, and back on the stored values the stale error is cleared; preflight re-runs after every save (on `pipeline.version`) when a runtime and destination are set; a single usable runtime (enabled, allowed by the policy's `allowed_runtime_ids`, last test not failed) is picked automatically (`[ReviewStep.tsx:ReviewStep]`).
- Engine settings follow the project's setting limits: settings the project hides are not offered, pinned ones are shown as set by the project, an int `max` bounds the control; any saved `tuning` key that is not offered (including one now hidden) or fails `settingError` is a `tuning` problem in `[review.ts:reviewProblems]`, which blocks autosave and deploy. `tuning` (JSONB-sorted) and then `placement` are written last and only when set, so an unchanged draft matches the stored spec (`[ReviewStep.tsx:ReviewStep]`).
- Every problem in `reviewProblems` has a drawn field in both modes: the custom size's CPU and Memory while Size is Custom, the streaming fields only for an automatic shape with a streaming size and the TaskManager fields only for a manual one (`streamingErrors` and `manualErrors` return nothing otherwise), and engine settings or raw properties in the Engine settings card in Expert mode, else in `BlockingSettings`: all of them in Guided mode, and the engine-setting ones in Expert mode when nothing typed is offered. A stored value that blocks (a setting the project hid since) makes the badge read "Fix … before deploying". Placement is never a problem: preflight checks it.
- Raw properties are classified by the server whenever the draft has any, in both modes (Guided hides the rows but they still block). A row blocks saving when its key is set twice or the server refuses it and it is new or its value changed against the stored spec (`[../../../lib/settings.ts:rawErrors]`, the rule `services.RefuseNewAdvanced` applies); an unchanged refused key an older pipeline holds still saves, and preflight blocks its deploy.
- Flink CDC in Review: no canary, no snapshot window, no `custom_resources`, no `always` snapshot mode; a custom cluster is kept only while the size is Custom; once deployed, sizes are locked while saved positions load or a current one exists (readers can't change under a saved position); cluster packing is asked for only when `manualError`/`streamingError` are clear. The Flink catalogue (`[FlinkSettings.tsx:FlinkConfEditor]`) offers only `scope === 'engine'` keys and flags unknown ones.
- Deploy needs `pipeline.deploy`, valid and saved settings, a runtime and passing final checks (`deployWhy`); forcing past failed checks is offered only when the policy does not set `allow_force_deploy: false`, every failure is a source or destination check, the settings are saved, and a reason of at least 10 characters is given. With approvals required the deploy becomes an approval request.

## Side Effects
- HTTP: `POST …/pipelines` (create draft), `POST …/pipelines/{pipeline_id}/settings:classify` and `POST …/pipelines/{pipeline_id}/cluster:pack` (Review, both as queries), `GET …/pipelines/{pipeline_id}/positions` (Review, Flink CDC once deployed), `PATCH …/pipelines/{pipeline_id}` with `if-match` (via `useSaveSpec`), `POST …/connections/{connection_id}/check`, `POST …/connections/{connection_id}/discover`, `POST …/pipelines/{pipeline_id}/preflight` and `POST …/pipelines/{pipeline_id}/deploy` (with `force_reason`), both sent by Review with the pipeline's `current_version` when the checks run: Deploy sends the version the shown checks ran on, so it never deploys one someone saved after them, and when someone else's version arrives while Review is open (one not made by Review's own autosave) a notice says that the summary, the checks and Deploy now show it (`[../../../lib/pipelines.ts:usePreflight]`, `[../../../lib/pipelines.ts:useDeploy]`); reads connections, connector types, `GET /api/v1/engines`, templates, policies, runtimes, pipelines.
- Timers: the Review autosave `window.setTimeout` (`[review.ts:useAutosave]`), set only while `autosaveDecision` says `schedule`, cleared on each change and on unmount.
- Module state: `[shared.tsx:createdHere]` is a process-wide `Set` of draft ids created in this browser tab.
