# page

## Overview
The tabs of one pipeline's page (`/p/$projectSlug/pipelines/$pipelineId?tab=`), rendered by `../PipelinePage.tsx`: Overview, Data, Events, Logs, Snapshots (Positions on Flink CDC) and History. Card wording is decided by the pure functions in `overview.ts` so it can be tested without rendering; server state comes from the hooks in `lib/pipelines.ts`.

## Interface
- `[Overview.tsx:Overview]` — flow strip, stale-status and reason notices, Flink cluster card (with "shrink now" for a custom cluster after its copy, `pipeline.operate`), metrics chart (`TimeSeries`), Since start, Source protection, Transforms (`TransformsCard`: lists `status.transform_drift` with an "N to fix" pill, and an Edit link that becomes Fix when there is drift) and delivery cards; a "Not deployed yet" card for drafts and a "Cleanup report" card from `artifacts.cleanup`, shown even once the pipeline is gone.
- `[overview.ts:protectionView]` / `[overview.ts:transformView]` / `[overview.ts:flinkView]` — what Source protection, Transforms (output vs steps; Flink CDC describes tables kept in sync) and the Flink cluster card say; `[overview.ts:shapeView]` (`ShapeView`) — what a custom Flink CDC cluster that shrinks after its copy is doing (`artifacts.flink_shape`: copy or streaming shape, whether Shrink now is offered, why shrinking stopped); helpers `formatWindow`, `formatLatency`, `latest`. `transformView` describes deletes as they run (`../transforms/model.ts` `effectiveDeletes`, with the destination's `ShapeCtx` from `useShapeCtx`): Keep deleted rows shows the row and kept deletes on Debezium; on a Flink CDC event destination (`events`, ADR 0011) `flinkEventsView` describes Debezium-style events, deletes as events or marked inserts and the message key; otherwise `flinkTransformView` checks for Keep deleted rows (rows marked `__op = -D`) or Iceberg's `write_mode` itself and ignores `ctx`.
- `[Flow.tsx:Flow]` / `[Flow.tsx:flinkLine]` — source → engine → destination strip with link states and the engine line.
- `[DataTab.tsx:DataTab]` — captured tables with their destinations and column rules (masked / removed / kept), and the tracked schema with "Mark as reviewed" for breaking changes (`SchemaSection`, offered with `pipeline.operate` while `pending_breaking > 0`); a schema change flagged `personal_data` offers "Choose what to send" (Tables step, `pipeline.edit`).
- `[StreamTabs.tsx:EventsTab]` / `[StreamTabs.tsx:LogsTab]` — sample events per table, and connector logs with level/search filtering (`[StreamTabs.tsx:filterLogs]`); on Flink CDC a component picker (`[StreamTabs.tsx:logComponents]`).
- `[SnapshotsTab.tsx:SnapshotsTab]` / `[SnapshotsTab.tsx:copyEstimate]` — Debezium: re-copy chosen tables (`Recopy`) and reset the stored position (`Position`); Flink CDC: `FlinkPositions` plus an explanation. `LARGE_TABLES`/`LARGE_ROWS` mark a large copy.
- `[FlinkPositions.tsx:FlinkPositions]` / `[FlinkPositions.tsx:startOverEffects]` / `[FlinkPositions.tsx:positionLabel]` — saved positions newest first, Restore, and Start over (copy again / from now / since a time).
- `[HistoryTab.tsx:HistoryTab]` / `[HistoryTab.tsx:DiffView]` — versions with rendered config, what each version changes in the settings (`settings_change`, with impacts), deploy/roll back (`DeployConfirm`), activity, diff, Export YAML, Promote to another project, Save as template.

## Invariants
- Source protection never turns a missing value into a reassuring one: an error is an `Unknown` grey pill, nothing measured is "Not measured yet" (grey), and OK needs evidence — SQL Server needs `position_kept === true` and time-kept sources (`KEPT_LABEL`) need both how far behind and the retention window, otherwise `Unknown` (`[overview.ts:protectionView]`).
- Overview warns when status is stale (`isStale`) and hides the flow strip, the Flink cluster card and the metric cards once the pipeline is deleting/deleted/cleanup_failed (`[Overview.tsx:Overview]`). Shrink now is offered only when `shapeView(...).ready` (copy done, `suggest` policy, shrinking not turned off) and with `pipeline.operate`.
- Tables, Change Debezium version and Choose what to send links need `pipeline.edit` (`[DataTab.tsx:DataTab]`, `[Flow.tsx:Flow]`), as does the Transforms card's Edit/Fix link (`[Overview.tsx:TransformsCard]`); Mark as reviewed needs `pipeline.operate` and `pending_breaking > 0`.
- Events need `pipeline.preview_data` and a deployed version; logs need a deployed version (`[StreamTabs.tsx:EventsTab]`). `filterLogs` keeps level-less lines with the line before them.
- Re-copy is offered only when the source supports incremental snapshots (`capture.incremental`) and needs `pipeline.operate`, a running (`desired_state === 'running'`) and deployed pipeline and at least one table; it can run now or in the scheduled window; a copy over `LARGE_TABLES` tables or `LARGE_ROWS` rows asks to confirm first (`[SnapshotsTab.tsx:Recopy]`).
- Position reset and Flink restore/start-over need `offsets.reset`, a deployed version, the pipeline paused (`desired_state === 'paused'`) and the typed pipeline name (`typeToConfirm`, also sent as `confirm`) (`[SnapshotsTab.tsx:Position]`, `[FlinkPositions.tsx:FlinkPositions]`); "since a time" must be in the past and is gated by `caps.start_from_time`; the newest current saved position offers no Restore, and Debezium's "Re-snapshot from scratch" is offered only when the source can copy rows.
- Deploying or rolling back to another version needs `pipeline.deploy`, an already deployed pipeline that is not deleting/deleted, and a version that is not the deployed one; the confirmation lists the diff notes and what the version changes in the settings (`settingsChangeLines`) and, when the project requires approval, that the deploy waits for someone else (`[HistoryTab.tsx:DeployConfirm]`). Save as template needs `project.manage`; Promote needs a current version; Export YAML is always offered. The toolbar (Export, Promote, Save as template) is hidden only while `deleting` or `deleted`, so a `cleanup_failed` pipeline still shows it (`[HistoryTab.tsx:HistoryTab]`).
- Promote targets only projects where the caller has `pipeline.edit`, runs a dry run before the real request, offers copying missing connections only with `connection.manage` here and there, and offers deploying there only with `pipeline.deploy` in the target (`[HistoryTab.tsx:PromoteDialog]`).

## Side Effects
- HTTP reads via `[../../../lib/pipelines.ts:useVersions]` and siblings (many poll with `refetchInterval`): `…/pipelines/{pipeline_id}/metrics`, `/events`, `/logs`, `/schema`, `/offsets`, `/positions`, `/versions`, `/config`, `/diff`, project `/events` (activity), `…/policies`, `…/templates`, `…/debezium-images` (Flow), connector types and `POST …/connections/{connection_id}/discover` (only with `pipeline.operate`), and the target project's connections and runtimes in Promote.
- HTTP writes: `POST …/cluster:shrink` (Shrink now), `POST /api/v1/projects/{project_id}/connections:copy` (copying missing connections in Promote, through `CopyDialog`), `POST …/snapshots`, `POST …/offsets/reset`, `POST …/positions/{position_id}/restore`, `POST …/schema/review`, `POST …/deploy`, `POST …/promote`, `POST …/templates`; `GET …/manifest` for Export.
