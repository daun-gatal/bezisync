# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [v0.4.0] - 2026-11-06

### Added
- **Custom Flink CDC clusters** - in Expert mode, Review → Size → Custom sets how many readers a Flink CDC pipeline runs and what each one needs, and draws the TaskManagers they would be packed into; BeziSync packs them into TaskManagers that fit the runtime's nodes when it deploys (or takes the TaskManagers you set) and keeps that shape until the next deploy. Preflight blocks a cluster no node can hold, and says so when the runtime doesn't report its nodes. A deployed pipeline can be resized and restores its position; changing its number of readers needs Start over first, and preflight now says so instead of letting the restore fail.
- **Flink CDC clusters shrink after their first copy** - give each reader less while streaming and BeziSync repacks the cluster once every table is copied and a position is saved, restarting it from that position, then grows it back before copying again. A streaming shape that keeps failing goes back to the copy size and raises an alert; the `shrink_after_copy: suggest` policy offers Shrink now instead.
- **Resource limits per project** - Policies → Resources caps the CPU, memory and readers one pipeline may ask for at its peak, on both engines, and lists the running pipelines a new limit would block (they keep running). A custom Flink CDC cluster is now held to the largest size too, by the Flink CDC preset's totals; before, it passed whatever its size.
- **Placement profiles** - a Kubernetes runtime's Admins define where pipelines may run (node selector, tolerations, priority class, pod labels) and a pipeline picks one in Review. Preflight blocks a profile no node takes; a custom Flink CDC cluster is packed for the profile's nodes; a profile edit applies at each pipeline's next deploy, and one in use can't be removed.
- **More Debezium settings, checked and suggested** - queue and batch sizes, a queue memory limit, the reconnect wait, skipping unchanged updates, the position save interval and the log level. Preflight checks tuned settings exist in the image's Debezium release, snapshot threads fit the source's free connections, and the queue and copy fetch fit the heap; Review suggests settings from that evidence with one click to use them.
- **Settings for each source and destination** - PostgreSQL, MySQL/MariaDB, Oracle and MongoDB get their own streaming settings, and Kafka, Pub/Sub and Redis destinations their batching and retry settings, each offered only where it applies. MongoDB and Spanner refuse JDBC driver properties.
- **Import and version changes know the settings** - adopting a Debezium Server sorts every property into settings, wizard choices, what BeziSync manages, advanced and refused, creates typed settings (an out-of-bounds one is listed, never clamped) and keeps excluded and masked columns, which it used to drop. Changing the Debezium version shows what the release does to each pipeline's settings and refuses one it lacks.
- **Setting limits per project** - Admins bound any typed setting (a range, some choices, an always-set value, or hidden); Policies counts the pipelines a limit would block before saving, saves outside the limits are refused, older pipelines' next deploys are blocked, pinned values are written into each deploy, and Promote's plan names what a target project refuses.
- **Flink CDC options** - Engine settings offer the Flink CDC sources' and destinations' own options (connect timeouts and attempts, PostgreSQL's WAL release delay, StarRocks loads, Iceberg file size, the schema change timeout; experimental ones say so), and Experts can pass the connectors' pass-through options (JDBC driver, embedded Debezium, destination table properties) with the same safety rules as Debezium.
- **Keep deleted rows** - a Transform step that keeps every deleted row, marked deleted (`__deleted` on Debezium, `__op` on Flink CDC), instead of removing it; the preview shows it, and a table that already has that column is refused.
- **Cut long text** - a Transform step that cuts text columns to a length, on Debezium (PostgreSQL, MySQL) and Flink CDC; a masked column can't be cut, a non-text one is left as it is (and blocks on Flink CDC), and importing a Debezium Server moves its truncations into the step.
- **Send tables elsewhere** - a Transform step that routes the tables a pattern matches (`shop.orders_*`) to one topic or table you name, on both engines, showing where every captured table goes; a table two routes match is refused, and preflight blocks tables of different shapes sent to one destination.
- **Computed columns on Flink CDC** - a Transform step that adds a column from a function picked from a list (case, trim, length, join, part of text, a date as text, as text, as a number) over the table's columns, never typed as SQL; masked and left-out columns can't be inputs, preflight blocks an input that's gone or of another type, and Debezium says why it can't run it.
- **Partition by for Iceberg on Flink CDC** - the Destination step partitions each table by a column's value, year, month, day, hour, hash buckets or leading part; preflight blocks a partition column the rows don't carry, and a table that already exists partitioned otherwise (Iceberg keeps a table's partitioning).
- **Settings for agents and CI** - the MCP tool `list_engine_settings` (and `GET …/pipelines/{id}/settings`) shows what a pipeline may tune with the project's limits applied; `bezisync remote diff` and `apply` print each setting change with what it does, each advanced property's class and what would break a running pipeline, and stop (exit 3) on a breaking change until `--confirm`.
- **Capacity checked when you deploy** - preflight measures the runtime as it runs, checks memory as well as CPU, blocks a deploy the Kubernetes namespace's ResourceQuota would refuse, counts only what a redeploy adds, and shows the check as unknown when the runtime doesn't report its capacity. Both Helm charts (0.2.1) let BeziSync read ResourceQuotas.
- **Custom sizes for Debezium pipelines** - in Expert mode a pipeline can run at its own CPU (0.25 to 8) and memory (512 MiB to 16 GiB); BeziSync works out the Java heap so the JVM always keeps room. A project's largest size and a destination's smallest size apply to it by CPU and memory.
- **What a deploy changes in the settings** - Review's final checks, a deploy or rollback confirmation, the version diff and an approval request list each setting a deploy changes, from what to what, grouped by what it does to the running pipeline (restart, first copy, next copy, starts over), heaviest first.
- **Engine settings in Review** - Expert mode gets an Engine settings card: typed settings grouped by when they matter, each with its bounds, default and what changing it does, and advanced Debezium properties as one row per key, each checked by the server as you type (with the reason and where to set it instead when refused, or the offer to use the typed setting).
- **Typed engine settings** - a pipeline spec takes `tuning`: settings from BeziSync's registry, each checked against the pipeline's engine, source and destination and its bounds, and carried by YAML, the API and MCP. The first ones: snapshot threads and the poll interval (Debezium), the connection pool (Flink CDC). `GET /engines` lists every setting with what changing it does to a running pipeline, and preflight and the version diff list the settings a deploy changes with that impact (`settings_change`).
- **A project policy for advanced Debezium properties** - Admins decide whether pipelines may pass raw properties (Settings → Policies, *Allow advanced properties*); without it their deploy is blocked. Upgrading turns it on for every project that already has a pipeline using them, with an audit entry.

### Changed
- **Unknown checks** - preflight checks BeziSync can't verify are now *Unknown*: grey, never shown as passed. Advanced properties that are allowed show as one, listing each key.
- **Images** - the `bezisync` and `bezisync-web` images leave out the source tree's `README.md` files (the new per-directory contracts for contributors); nothing they run changes.

### Fixed
- **Review stops re-saving a change the server refused** - when a save is refused (a property BeziSync doesn't allow, a setting only the server checks, someone else's edit, a network error), Review & deploy shows why and waits: it tries again when you change something, click Try again (for network and server errors) or leave the step, instead of saving every second. A refused advanced property is caught as you type, in Guided mode too, and one an older pipeline already has still saves.
- **Review says which field to fix** - "Not saved" now names the field (**Not saved: fix Memory**, or **Memory and 2 more**) and takes you to it, and each error sits under its own field: a custom memory over the project's limit is shown under Memory, not CPU, and a Flink CDC streaming size under the streaming field it is about. In Guided mode, an engine setting or advanced property that blocks saving is listed with Remove instead of blocking unseen.
- **Keep deleted rows shows in the Transform step** - added, it used to vanish from the Transform step while still saved (and shown in Review). It now sits under Event shape on Debezium and under Keep rows on Flink CDC, can be removed, and is offered once. Where it decides deletes, the Transform step, Review, the deploy's impact, the Overview and the Destination step say so instead of showing the row shape's or the destination's own choice, and a filter added after it on Flink CDC goes before it, as the server requires.
- **A new Keep only some events filter saves** - a filter added in the Transform step without column rules was refused on save ("match needs rules"), on both engines; it now saves.
- **Advanced Debezium properties can't override BeziSync** - a raw property may no longer change a key BeziSync sets for the pipeline (where events go, tables, columns and personal-data choices, the error policy, connection and TLS details, heartbeats and signals). Credentials, values containing `${…}` or line breaks, and unsafe options (SQL on the source, dropping the slot, skipping changes, weaker TLS, loading classes, `quarkus.*`) are refused too. Saving refuses new ones with where to set them instead; ones an older pipeline already has still save, and its deploy is blocked by the new *Advanced properties* check (a forced deploy can't skip it). Adopting a Debezium Server keeps only allowed properties.
- **JDBC driver options that can read files or load code are refused** - advanced `driver.*` and `database.*` properties that read local files, deserialize or load classes, call out, log to files, or change TLS and sign-in (for example MySQL's `allowLoadLocalInfile`) are no longer passed to the source's driver.
- **Flink CDC on PostgreSQL checks replication slots for the copy** - during a first copy each reader opens its own temporary replication slot and WAL sender, so it needs 1 + readers of each; preflight only checked for one free slot, so a large pipeline could pass it and then stop part-way. The new check blocks such a deploy, with the SQL to fix it.
- **Credential-looking advanced properties are hidden** - a pipeline saved before credentials were refused as advanced properties may still hold one; preflight, the Config view and change summaries now show its value as `(hidden)` instead of in plain text (the pipeline keeps working).
- **Review settles with advanced properties in any order** - the server stores advanced properties shorter key first; Review compared them in the order they were typed, so some orders never matched and it kept saving. It now builds them in the stored order.
- **Dependency advisories** - Go modules updated past new advisories: `github.com/andybalholm/brotli` 1.2.8 (GO-2026-6888, critical), `software.sslmate.com/src/go-pkcs12` 0.7.4 (GHSA-mpwr-8vm7-h73f) and `golang.org/x/crypto` at the commit that fixes GO-2026-5932 (no tagged release has it yet).

## [v0.3.0] - 2026-11-05

### Added
- **Flink CDC engine** - pipelines into Iceberg, StarRocks, Doris and Fluss can run on Flink CDC (a JobManager and TaskManagers per pipeline on Docker or Kubernetes), with parallel first copies, schema changes applied to the destination tables and saved positions kept by BeziSync. Debezium stays the engine for every other destination; each pipeline shows its engine. Transforms on Flink CDC are filters built from rules, renames and added fields; value formats, the outbox router, flattening and custom steps stay Debezium options.
- **StarRocks, Apache Doris and Apache Fluss destinations** - on Flink CDC: one primary-key table per source table, created and kept in step with the source. StarRocks and Doris are checked, read back in the Events tab and dropped on delete, and get no source column defaults (they refuse them); Fluss is checked for reachability and its tables are kept on delete. None of the three loads over TLS: keep them on a private network.
- **Iceberg on Flink CDC** - Iceberg pipelines from MySQL, MariaDB, PostgreSQL or SQL Server can choose Flink CDC in the wizard (Debezium stays the default) over the same REST and Glue catalog connections.
- **Flink CDC settings in the wizard** - the review step sets what schema changes and new columns do, how often the position is saved (and Iceberg commits), how fresh StarRocks and Doris loads are, and in Expert mode Flink settings from a reviewed list.
- **Engine versions** - Settings → Debezium versions is now Settings → Engine versions, with a Flink CDC tab. Flink CDC stays off until an Admin registers an image they build (BeziSync publishes none; the guide lists what it holds). MySQL/MariaDB sources need MySQL Connector/J added to it.
- **Saved positions** - a Flink CDC pipeline's Positions tab lists its saved positions (encrypted in the state database) and, while paused, restores one or starts over: copy every table again, read from now, or read since a time (MySQL, SQL Server).
- **Flink CDC from scripts and agents** - manifests take `spec.engine`, `flink_cdc` settings and `flinkCdcImage`; `bezisync remote pipelines positions|restore|start-over` and the ENGINE column in `remote get`; MCP tools `list_engines`, `list_saved_positions`, `restore_saved_position`, and `from_time` on `reset_pipeline_offsets`.

### Changed
- **Helm charts 0.2.0** - the control-plane and agent charts' Roles allow Services, which a Flink CDC pipeline's TaskManagers use to reach its JobManager on Kubernetes.

## [v0.2.0] - 2026-11-04

### Added
- **About BeziSync** - Help & tour → About BeziSync shows the server version and the license (Apache 2.0), links the source code, and opens the licenses and notices of the third-party software in the web UI and the server.
- **Licenses shipped with BeziSync** - The web image serves `/licenses.txt`; the server binary carries its own (`bezisync licenses`, `GET /api/v1/system/licenses`, and `LICENSES.txt` in each CLI archive). Each lists BeziSync's NOTICE and LICENSE, then every included dependency with its license text and notices.

### Changed
- **Lab testing policy** - The open lab's testing policy now says BeziSync is open source (Apache 2.0) and links its GitHub repository, offers GitHub private vulnerability reporting alongside in-app Feedback, and points load testing at your own copy.

## [v0.1.0] - 2026-11-03

### Added
- **BeziSync is open source** - the first public release under the Apache License 2.0: a self-service control plane for Debezium Server with preflight checks, source protection, one-click operations, evidence-based health, encrypted write-only secrets, RBAC and SSO, per-pipeline personal-data handling and AI agents over MCP
