# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [v0.9.0] - 2026-11-13

### Added
- **Run your own lab in GitHub Codespaces** - the README's "Open in GitHub Codespaces" button starts a private BeziSync in your own codespace: the control plane, sample PostgreSQL and MySQL shops with live orders, a PostgreSQL that isn't ready for change data capture (so preflight shows its fixes), Kafka, a PostgreSQL warehouse and an HTTP endpoint, with a random admin password. Nothing is hosted for you; it runs on your free Codespaces quota (ADR 0018).
- **More in the Sandbox** - the demo stack's Sandbox project can now also create a MySQL source, a PostgreSQL source that isn't ready for CDC, a JDBC warehouse and an HTTP destination (each destination with a template), and teammates for the Editor, Operator and Viewer roles. Each is opt-in through new `BEZISYNC_SANDBOX_*` settings and created once, with the project; without them the Sandbox is unchanged.

### Fixed
- **Security updates** - built with Go 1.27.4 (GO-2026-6859 in `net/http`) and Apache Thrift 0.25.0 (CVE-2026-82458, CVE-2026-63772, CVE-2026-83663, CVE-2026-66055, CVE-2026-94637).

## [v0.8.0] - 2026-11-10

### Added
- **Discard a deployed pipeline's undeployed changes (ADR 0017)** - a change saved from the wizard but not deployed could only be deployed or rolled back over (which restarts the connector). Closing the wizard now asks "Keep vN?" (keep it, or discard it), and the "vN is saved but not deployed" notice has **Discard vN**. Discarding points the pipeline back at its deployed version: the connector keeps running and doesn't restart, no approval is needed, and the discarded version stays in History, deployable. Also `POST …/pipelines/{id}/changes:discard` (with `If-Match`), `bezisync remote pipelines discard NAME` and the MCP tool `discard_pipeline_changes`. It is refused while a change request is pending.

### Changed
- **Destination checks create nothing on the destination (ADR 0016)** - the Database (JDBC), Iceberg, StarRocks, Doris, OceanBase and Elasticsearch checks used to create and drop a `bezisync_check_*` table or index, which a least-privilege login could leave behind (and which needed rights the pipeline never uses). They now only read: PostgreSQL asks `has_schema_privilege` (`USAGE` and `CREATE`; a missing schema warns), SQL Server `HAS_PERMS_BY_NAME`, MySQL, MariaDB, StarRocks, Doris and OceanBase read `SHOW GRANTS` (Pass when the grants show the right, "not known" when it may come from a role), and Elasticsearch asks `_has_privileges` for the pipeline's own indexes when the pipeline is checked. Iceberg's "Table create and commit" is "not known": the catalog answers that only by trying, and the first commit shows it. Paimon and Redis still write a short-lived object or key and delete it.
- **StarRocks, Doris and OceanBase create the database on deploy** - the check used to run `CREATE DATABASE IF NOT EXISTS`; deploy now looks the database up and creates it when missing, and says which grant or manual step is needed when it can't.
- **Agents that predate this aren't sent those checks** - an agent without the `readonly_destination_checks` feature would still create test objects, so BeziSync answers its Iceberg, Database, StarRocks, Doris, OceanBase and Elasticsearch checks with "not known" (`agent_readonly_checks`) until the agent is upgraded. Upgrade the control plane first, then the agents.
- **Dropping what earlier versions left** - look for `bezisync_check_<digits>` objects and drop them: tables in the destination schema or database (`DROP TABLE <schema>.bezisync_check_…` on PostgreSQL, MySQL, SQL Server, StarRocks, Doris, OceanBase), tables in the Iceberg namespace (drop them with purge through your catalog), and indexes in Elasticsearch (`DELETE /bezisync_check_*`; allow wildcard deletes with `action.destructive_requires_name: false` only for that call).
- **Editing back to what is deployed clears the change** - saving a spec equal to the deployed one (with the project's pinned settings) now points the pipeline back at the deployed version instead of keeping a draft that reads "saved but not deployed"; `pipelines:apply` of a manifest that matches what runs does the same.

### Fixed
- **Iceberg REST catalogs that can't vend credentials pass the write check** - BeziSync's own catalog client (checks, the "Write a test table" check, tails, column reads) asked the catalog for vended credentials on every request, even for a connection with its own object-storage keys (iceberg-go's default). A catalog that can't vend, such as Polaris over storage without STS, refused the request with HTTP 400 ("Credential vending was requested … but no credentials are available"), and the check blocked the deploy although the connector writes with the connection's keys. Only "Credentials vended by the catalog" asks for them now.

## [v0.7.0] - 2026-11-09

### Added
- **Flink CDC switches columns at the saved position** - a version that changes the columns a Flink CDC pipeline writes (a step that adds, computes or removes a column, keeping deleted rows, a rollback) no longer needs a Start over: once the running job has stopped with a savepoint, BeziSync adds the new columns to the destination tables and the job resumes from exactly that position writing them, with nothing copied again and no change lost (ADR 0013). Positions saved before the switch restore with the new columns too. Flink CDC pipelines keep their configuration until their next deploy.

### Fixed
- **Flink CDC never writes a value into another column** - Iceberg and Paimon write rows into a table by position, and Flink CDC doesn't change a table that already exists: a Start over after a step added a column (or after the source added, renamed or dropped one) filled existing columns with other columns' values while the pipeline stayed Healthy. Before every start without a saved position BeziSync now reads each destination table, writes its columns in the table's order (a column the pipeline no longer writes stays, empty), and adds the columns a table lacks (Iceberg, StarRocks, Doris, OceanBase; Paimon gets the statements to run); a start it can't make safe doesn't happen (ADR 0012).
- **A column change is no longer dropped silently** - Flink CDC resumes a saved position with the columns it started with, so a version that changed them was half-applied without a word; such a version now switches columns at the saved position (see *Flink CDC switches columns at the saved position*).
- **No hidden fresh starts** - with nothing to restore, a Flink CDC pipeline starts without a saved position only when BeziSync planned that start; otherwise it stops with `no_position` instead of writing into tables nobody read. Restoring a position saved before the last Start over is refused (`position_before_layout`).
- **Keep deleted rows on StarRocks** - StarRocks reserves `__op`, so the table was never created; the change type is written to `__bz_op` there. Flink CDC pipelines to StarRocks that keep deleted rows restart on upgrade (they never ran).
- **MCP `update_pipeline` changes only the fields sent** - it replaced the whole spec, resetting the tables, steps and snapshot mode when one field was sent.
- **Fix texts** no longer point to a Start over that drops destinations (there is none).
- **The capacity check counts pipelines still starting** - two pipelines deployed to one runtime seconds apart both passed preflight while the first one's pods didn't exist yet, and one then waited forever on the namespace's ResourceQuota. Preflight now adds what the pipelines on that runtime without pods yet ask for, and names them.
- **A pod Kubernetes won't create says why** - the status said only "Waiting for the pod to be created" when a ResourceQuota (or an admission webhook) refused the pod; it now gives Kubernetes' reason.
- **Restoring an older Flink CDC position into Iceberg no longer drops rows** - the restored job numbered its checkpoints from the old position, and Flink CDC's Iceberg committer skipped every commit whose number it had already seen, so what the job wrote until it passed the old numbers was lost. A restore of an older position, or from a checkpoint after a crash (when the job may have committed later ones), now numbers past every checkpoint the pipeline reached (ADR 0014).
- **A Flink CDC job to Elasticsearch that can't read its own state stops and says why** - Flink CDC 3.7's Elasticsearch writer runs out of memory reading the requests it held when the position was saved, and restarted forever; BeziSync now cancels it and says to Start over, copying the tables again (documents are written by id, so nothing is lost).
- **A Flink CDC job that replays a source column change stops and says why** - a restore from before a source column change (or a crash right after one) made Flink CDC add the column again, the destination refused it, and the job failed over forever; it now stops with `schema_change_replayed`: restore a later position, or Start over.
- **A source column added while a Flink CDC pipeline was stopped no longer fails it** - a deploy named the column before the resumed job had read the change that added it, and the job failed with a misleading "transform can't run" (hold mode, the default, and tables written column by column). BeziSync now holds such a column back and resumes; the next deploy writes it (ADR 0015).

## [v0.6.0] - 2026-11-08

### Changed
- **The Destination step follows the source** - it lists only the destinations an engine the project allows can write from the pipeline's source, names the rest with the reason, and disables those whose engine isn't set up; Add a destination, the engine picker and the Source step's sources and templates follow the same rule (ADR 0011).
- **Flink CDC to Kafka speaks events** - the Transform step, its preview, Review and the pipeline Overview describe topics, events and the message key instead of tables (ADR 0011).
- **Allowed engines choose the default** - when a destination takes both engines and the project allows one, that one is chosen, through the UI, API, CLI and MCP.

### Fixed
- **Kafka on Flink CDC keeps its one format** - choosing Flink CDC sets JSON without the schema, and saving another format is refused at save instead of at Review.

## [v0.5.0] - 2026-11-08

### Added
- **Partition by on Debezium** - Iceberg tables on Debezium can now be partitioned per table in the Destination step, as on Flink CDC: a column, the year/month/day/hour of a date or timestamp, buckets of a hash or the leading part, up to four fields, plus Debezium's time of the change for change logs. Tables Partition by doesn't list keep the automatic partitioning (bucket by key, day of the change), compiled as before (a pipeline with no Route step keeps its configuration).
- **Flink CDC reads Oracle** - Oracle tables can be synced into StarRocks, Doris and Fluss, and into Iceberg on Flink CDC (Debezium stays Iceberg's default), with parallel first copies, added columns applied and restorable positions. It needs a Flink CDC image with the `oracle` connector (`/opt/flink-cdc/connectors/oracle.jar`; the reference image adds it). Flink CDC's Oracle reader is narrower than Debezium's, and preflight says so before a deploy: Enterprise, Standard or Express Edition up to 23ai only (`flink_oracle_version`; not Oracle Database Free or 26ai), `ANALYZE ANY` for the first copy, which replaces the tables' optimizer statistics (`flink_oracle_analyze`), and, on a multitenant database, a `LOG_MINING_FLUSH` table in the CDB root that BeziSync creates (`flink_oracle_flush_table`). Tables must have upper-case names; renaming or dropping a column stops the pipeline (Start over), and adding tables needs a Start over first (`flink_tables_added`). MongoDB, Vitess, TiDB and OceanBase stay on Debezium: Flink CDC has no pipeline source for them (ADR 0006).
- **More functions for Flink CDC computed columns** - replace text, first and last characters, pad, join with a separator, first that isn't empty, absolute value, round (up, down, to digits), add, subtract, multiply, divide, year, month, day of the month, hour, date from text, days between, and as a decimal or floating-point number, picked by group (ADR 0008).
- **Flink CDC expressions** - in Expert mode a computed column, or a filter's condition, can be written as an expression in Flink CDC's functions (`CASE WHEN total > 100 THEN 'big' ELSE 'small' END`), checked as you type (`POST …/expressions:check`). BeziSync parses it and writes its own rendering into the job: only documented functions (no user-defined, AI or regular-expression functions), no comments or `;`, and every function NULL-safe so no value can stop the job. Preflight's `transform_expression` checks the columns and their kinds.
- **More Flink CDC destinations: Elasticsearch, Apache Paimon and OceanBase, and Kafka on Flink CDC** - Elasticsearch (6, 7 or 8; one index per table, a document per row keyed by the primary key), Apache Paimon (primary-key tables in a filesystem catalog on S3 or an S3-compatible store) and OceanBase (MySQL tenants, through OceanBase Connector/J) run on Flink CDC, with connection checks that write and remove a test index, object or table. Kafka can now also run on Flink CDC (JSON without the schema, keyed by the primary key; Debezium stays its default), so a pipeline that needs Flink CDC can write Kafka. They need a Flink CDC image with the `kafka`, `elasticsearch`, `paimon` + `paimon-s3` and `oceanbase` + `oceanbase-client` JARs (the guide lists them; the reference image adds them). Paimon has no read-back: Events stay empty and health is Unknown. Hudi and MaxCompute aren't offered (ADR 0009).
- **Column types in the Destination table** - the Transform step's Destination table (Flink CDC) shows each column's type: the source's type for a source column, and the kind a computed or added column writes (text, a whole number, …), and when a column is cut short.
- **Primary keys from any written column (Flink CDC)** - the Primary key picker offers every column the table writes, with its type: source columns under their new names, added fields and computed columns (ADR 0010). A computed key column must be text or a whole number, never empty and the same each time a row is written; BeziSync writes it NOT NULL, as destinations such as Iceberg require. On Debezium, which builds the message key before any step runs, added fields are shown but can't be picked.

### Changed
- **CORS `*` no longer sends credentials** - with `*` among the CORS origins, any site's `Origin` used to be answered with credentials, so another site could read the API with a signed-in user's cookie. Origins listed by name keep credentialed CORS; any other origin `*` allows now gets a literal `*` without credentials, and the API warns at startup. A cross-origin UI that signs in with cookies must be listed by name; bearer tokens are unaffected.
- **Project policies that can't be read fail closed** - stored policies that fail to parse used to fall back to the defaults, which allow everything. Now the fields that parsed are kept, the others take their strictest value, and every change in the project (saving a changed spec, creating, deploying, even with Deploy anyway) is refused with `policy_unreadable` until an Admin fixes them: Settings → Policies lists what couldn't be read. Running pipelines keep running; pause, resume and delete still work.
- **Testing a runtime needs `runtime.manage`** - it calls the runtime and rewrites its test result and capacity; members who aren't Admins no longer see Test. MCP `test_runtime` is now a write tool, and `delete_pipeline` asks for `pipeline.deploy`, the permission deleting already needed.
- **Labels are checked when an edit changes them** - at most 20, slug keys, values of at most 63 characters, as on create (and manifest apply). Labels a pipeline already holds still save unchanged.
- **Flink CDC pipelines refuse snapshot requests** - Flink CDC can't copy one table again while the others stream (use Start over); a deploy that adds tables lets Flink CDC copy them itself instead of queuing a Debezium snapshot.
- **The SSRF guard holds on every connection, not just the check** - BeziSync used to check a host when testing a connection and then let the database or broker driver dial on its own, so discovery, preparing, cleanup, signals, canaries, probes and the Events tab could reach loopback or cloud-metadata addresses, and a DNS answer that changed after the check, a redirect or an address a server advertises (Kafka brokers, MongoDB members, NATS servers) was never checked. Every driver, HTTP client, emulator host and custom cloud endpoint now dials through the guard; SSH-tunnelled sources keep working. A connection whose host resolves to a refused address now fails on every path, not only its check: allow it with `BEZISYNC_SSRF_ALLOW_CIDRS` if it is meant to be reached (an emulator on `localhost`, for example). An egress proxy set with `HTTPS_PROXY`/`HTTP_PROXY` is still used, after the target is checked, and now also for single sign-on, Iceberg and Pulsar admin calls, which ignored it before.
- **Upserted Iceberg tables are partitioned only by key columns** - rows are upserted by writing deletes on the key, and Iceberg applies a delete only to rows in its own partition, so a table partitioned by a column outside its key (an `updated_at` day, a `status`) kept the old row whenever an update changed that column. Preflight now blocks it (`iceberg_partition_key`), and the editor shows such columns disabled; for time-like layout partition by the leading part of an increasing key (`truncate[100000](id)`). **Flink CDC pipelines partitioned that way are blocked on their next deploy** (they keep running); their tables may already hold duplicate rows: find them with `SELECT <key>, count(*) FROM <table> GROUP BY <key> HAVING count(*) > 1`, and recreate the table with Start over, dropping destinations. The same check covers existing tables partitioned off their own identifier fields, on both engines.
- **Partition checks use the type the engine writes** - buckets of a true/false or floating-point value, truncating a UUID, two time transforms of one column, and columns written as lists or structures (on Debezium also PostgreSQL arrays, user-defined types and NUMERIC) are refused before the deploy instead of failing when the table is created. Decimals sent as double or text, binary sent as text and a time of day (a number on Debezium) are judged by what is written. Truncate widths go up to 1,000,000.
- **Raw Debezium 1.9 options that load code or open connections are refused on Flink CDC** - Flink CDC embeds Debezium 1.9, whose `source.debezium.database.history*`, `source.debezium.rac.nodes` and `source.debezium.database.connection.adapter` could load a class, send the schema history elsewhere or hand the source's credentials to other hosts. A pipeline that set one fails preflight until it is removed.
- **Partition by is chosen in the Transform step** - Iceberg's Partition by now has its own row in Transform, after the key, so the key, renames and computed columns chosen on the same screen are offered as they change; the Destination step says where it went and warns when a write-mode or engine change made a saved field invalid, and so does Review. Nothing is stored differently, and no pipeline restarts (ADR 0007).
- **Flink CDC shows why Iceberg has no change log** - "Every change appended" is shown unavailable on Flink CDC with the reason (its Iceberg writer always writes rows by the table's key), naming Debezium when it is a real choice. A pipeline switched to Flink CDC with that choice must pick another before continuing.
- **Pipelines with Flink CDC computed columns, or a filter comparing a number for equality, restart once on upgrade** to run the fixed rendering. Rolling back: an older BeziSync refuses a spec with an expression or one of the new functions; remove those steps first.
- **StarRocks and Doris hosts must be a host name or an IP address** - the host goes into the JDBC and load URLs, so a `/`, `?` or `&` in it could add driver options. Connections whose host already is one are unchanged.
- **The preflight check reference names the engines** - each source and destination section says whether Debezium, Flink CDC or both read or write it, and the PostgreSQL, MySQL / MariaDB, SQL Server and Oracle sections link the Flink CDC checks that also run for them (replica identity, replication slots for the copy, server ids, the Oracle checks), which were listed only under Flink CDC.
- **A computed date as a key says how to partition by date** - put the timestamp column itself in the key and partition it by its day under Partition by.

### Fixed
- **Jobs a crashed controller left running are taken back** - a restart, cleanup or notification interrupted by a controller crash runs again on the next leader; an interrupted snapshot is marked failed ("Interrupted…") rather than sent twice. Project deletion and runtime removal no longer stay blocked behind such a job.
- **The "Position moved backwards" alert can fire** - the stored position was dropped on the tick after each probe, so a position going back was never noticed.
- **Delivery canaries keep running after one is lost** - a canary that never arrived stopped canary checking for the pipeline; the alert now names when the lost one was written, and the next canary goes out on schedule.
- **Keep deleted rows before a field step on Iceberg** - `[Keep deleted rows, Rename]` without an explicit Row after change ran the rename on the change envelope; the row shape now comes first. Only pipelines with that chain restart on upgrade.
- **Review deploys the version it checked** - Deploy names the version the final checks ran on, so it never deploys an edit someone saved after.
- **A setting a project policy pins can't be switched** - an On/Off setting pinned by policy stayed clickable in the settings editor.
- **Sign-in opens when saving your profile finds the session expired** - changing Guided/Expert mode or notification settings after the session expired failed silently.
- **Slow Flink CDC helper copies on Docker** - copying the helper was cut off after 30 seconds instead of its two-minute limit.
- **A data race in the remote-runtime agent** - its report read the desired workloads while they were being replaced.
- **IAM-role credentials for SQS, SNS and Iceberg checks** - their checks sent the AWS credential chain through the SSRF guard, which refuses instance and pod metadata addresses; only service calls are guarded now.
- **Vault answers are bounded and redirects aren't followed** - an answer is read up to 4 MiB, and a redirect no longer carries the Vault token to another address.
- **Routed Debezium Iceberg tables get their automatic partitioning** - the automatic partitioning (buckets of the key, the day of the change) was set under the table's name before its route, which the Iceberg build never looks up, so a table a Route step sends elsewhere was always created unpartitioned. It now follows the route; tables routed to one destination share it when they agree. **Routed Debezium Iceberg pipelines restart once on upgrade**; tables they create afterwards are partitioned, existing ones keep their partitioning.
- **Iceberg checks no longer pass when the catalog can't be read** - an access or network error reading a destination table counted as "the table doesn't exist yet", so the existing-table partitioning check passed; it now warns.
- **Renamed or left-out key columns on Debezium Iceberg upserts** - Debezium's Iceberg build keys a table only by key columns its rows carry under the same name, so a key column renamed or left out narrowed the table's identity and upserts replaced rows sharing the rest of the key. Preflight blocks it (`iceberg_key_columns`), and warns when no key column is left (the table is appended).
- **Flink CDC pipelines no longer run the delivery canary** - Flink CDC captures only the pipeline's tables, so a canary row never arrived; the canary is now off for them and preflight says why.
- **Flink CDC pipelines keep `$` in values as written** - the Flink CDC helper filled `$name` and `${name}` anywhere in the pipeline definition, so a literal such as `'US$5'` in a transform reached Flink CDC changed, and a value containing `$BZ_…` could have had a secret written into it. Now only the placeholders BeziSync writes as whole values are filled. Pipelines restart only when their helper restarts; nothing else changes.
- **Connection settings can't name another secret** - a setting (not a secret) containing `${`, such as a user name of `${BZ_STATE_PASSWORD}`, would have been filled in by Debezium Server or the Flink CDC helper and sent to that connection's server. Saving one is refused, and a pipeline using a connection saved with one before stops compiling (422 `connection_config`) until the setting is changed; its running workload is left as it is.
- **Flink CDC refuses an existing Iceberg table without a key** - Flink CDC 3.7.0 writes every delete, and the old values of every update, into such a table as ordinary rows. Preflight now blocks it (`iceberg_flink_keyless_table`); a table the pipeline creates is unaffected.
- **Wizard steps no longer save an unchanged pipeline** - with several Iceberg tables, the Destination and Review steps saved the recorded table keys in another order on every visit, and Transform and Tables saved when the spec carried value formats or keys next to Flink CDC settings.
- **Unticking a partitioned table** - its Partition by and recorded key stayed in the spec, and the server refused the save.
- **Preflight fixes for Iceberg partitioning** point at the Transform step, and RustFS's upsert check no longer tells Flink CDC pipelines to choose a change log.
- **Flink CDC computed columns no longer stop on an empty value** - upper/lower case, trim, length and part of text threw on a NULL, which stopped the job on the first such row; they now give an empty value.
- **Flink CDC "Join" with a column and "As text" run** - they compiled to `CAST(… AS STRING)`, which Flink CDC 3.7.0 doesn't accept, so the pipeline never started.
- **Flink CDC filters compare numbers by value** - "is", "is not", "is one of" with a number matched nothing on a BIGINT or DECIMAL column (Flink CDC compares Java objects). They now compare as numbers.
- **Preflight and the schema-drift alert check computed columns** - a computed column whose input left the table was only caught when the job failed.
- **Kafka SASL passwords with a backslash** - the JAAS line escaped only `"`; a `\` in a user or password broke sign-in. Pipelines whose Kafka credentials hold a `\` restart once.
- **Flink CDC key checks** - a key column the table doesn't write (left out, or a step's column since removed or renamed) is now refused before deploy (`transform_key_column_unknown`), instead of failing the job; the left-out check no longer compares the renamed name, and Debezium's "falls back to the primary key" finding no longer appears on Flink CDC pipelines.
- **A Flink CDC key column that can be empty is now a warning** (`transform_key_column_nullable`): Flink CDC writes it as an empty text, so the rows where it is empty share one key and replace each other.
- **Flink CDC key editor shows an expression column's type** - it said "decided when it runs" while the reason beside it named the type; it now shows the kind the server's check reads.
- **A nullable key column next to the primary key no longer warns** (`transform_key_column_nullable`) - with the whole primary key in the key, rows can't share a key.

## [v0.4.0] - 2026-11-06

### Added
- **Custom Flink CDC clusters** - in Expert mode, Review → Size → Custom sets how many readers a Flink CDC pipeline runs and what each one needs, and draws the TaskManagers they would be packed into; BeziSync packs them into TaskManagers that fit the runtime's nodes when it deploys (or takes the TaskManagers you set) and keeps that shape until the next deploy. Preflight blocks a cluster no node can hold, and says so when the runtime doesn't report its nodes. A deployed pipeline can be resized and restores its position; changing its number of readers needs Start over first, and preflight now says so instead of letting the restore fail.
- **Flink CDC clusters shrink after their first copy** - give each reader less while streaming and BeziSync repacks the cluster once every table is copied and a position is saved, restarting it from that position, then grows it back before copying again. A streaming shape that keeps failing goes back to the copy size and raises an alert; the `shrink_after_copy: suggest` policy offers Shrink now instead.
- **Resource limits per project** - Policies → Resources caps the CPU, memory and readers one pipeline may ask for at its peak, on both engines, and lists the running pipelines a new limit would block (they keep running). A custom Flink CDC cluster is now held to the largest size too, by the Flink CDC preset's totals; before, it passed whatever its size.
- **Placement profiles** - a Kubernetes runtime's Admins define where pipelines may run (node selector, tolerations, priority class, pod labels) and a pipeline picks one in Review. Preflight blocks a profile no node takes; a custom Flink CDC cluster is packed for the profile's nodes; a profile edit applies at each pipeline's next deploy, and one in use can't be removed.
- **More Debezium settings, checked and suggested** - queue and batch sizes, a queue memory limit, the reconnect wait, skipping unchanged updates, the position save interval and the log level. Preflight checks tuned settings exist in the image's Debezium release, snapshot threads fit the source's free connections, and the queue and copy fetch fit the heap; Review suggests settings from that evidence with one click to use them.
- **Settings for each source and destination** - PostgreSQL, MySQL/MariaDB, Oracle and MongoDB get their own streaming settings, and Kafka, Pub/Sub and Redis destinations their batching and retry settings, each offered only where it applies. MongoDB and Spanner refuse JDBC driver properties.
- **Import and version changes know the settings** - adopting a Debezium Server sorts every property into settings, wizard choices, what BeziSync manages, advanced and refused, creates typed settings (an out-of-bounds one is listed, never clamped) and keeps excluded and masked columns, which it used to drop. Changing the Debezium version shows what the release does to each pipeline's settings and refuses one it lacks.
- **Setting limits per project** - Admins bound any typed setting (a range, some choices, an always-set value, or hidden); Policies counts the pipelines a limit would block before saving, saves outside the limits are refused, older pipelines' next deploys are blocked, pinned values are written into each deploy, and Promote's plan names what a target project refuses.
- **Flink CDC options** - Engine settings offer the Flink CDC sources' and destinations' own options (connect timeouts and attempts, PostgreSQL's WAL release delay, StarRocks loads, Iceberg file size, the schema change timeout; experimental ones say so), and Experts can pass the connectors' pass-through options (JDBC driver, embedded Debezium, destination table properties) with the same safety rules as Debezium.
- **Keep deleted rows** - a Transform step that keeps every deleted row, marked deleted (`__deleted` on Debezium, `__op` on Flink CDC), instead of removing it; the preview shows it, and a table that already has that column is refused.
- **Cut long text** - a Transform step that cuts text columns to a length, on Debezium (PostgreSQL, MySQL) and Flink CDC; a masked column can't be cut, a non-text one is left as it is (and blocks on Flink CDC), and importing a Debezium Server moves its truncations into the step.
- **Send tables elsewhere** - a Transform step that routes the tables a pattern matches (`shop.orders_*`) to one topic or table you name, on both engines, showing where every captured table goes; a table two routes match is refused, and preflight blocks tables of different shapes sent to one destination.
- **Computed columns on Flink CDC** - a Transform step that adds a column from a function picked from a list (case, trim, length, join, part of text, a date as text, as text, as a number) over the table's columns, never typed as SQL; masked and left-out columns can't be inputs, preflight blocks an input that's gone or of another type, and Debezium says why it can't run it.
- **Partition by for Iceberg on Flink CDC** - the Destination step partitions each table by a column's value, year, month, day, hour, hash buckets or leading part; preflight blocks a partition column the rows don't carry, and a table that already exists partitioned otherwise (Iceberg keeps a table's partitioning).
- **Settings for agents and CI** - the MCP tool `list_engine_settings` (and `GET …/pipelines/{id}/settings`) shows what a pipeline may tune with the project's limits applied; `bezisync remote diff` and `apply` print each setting change with what it does, each advanced property's class and what would break a running pipeline, and stop (exit 3) on a breaking change until `--confirm`.
- **Capacity checked when you deploy** - preflight measures the runtime as it runs, checks memory as well as CPU, blocks a deploy the Kubernetes namespace's ResourceQuota would refuse, counts only what a redeploy adds, and shows the check as unknown when the runtime doesn't report its capacity. Both Helm charts (0.2.1) let BeziSync read ResourceQuotas.
- **Custom sizes for Debezium pipelines** - in Expert mode a pipeline can run at its own CPU (0.25 to 8) and memory (512 MiB to 16 GiB); BeziSync works out the Java heap so the JVM always keeps room. A project's largest size and a destination's smallest size apply to it by CPU and memory.
- **What a deploy changes in the settings** - Review's final checks, a deploy or rollback confirmation, the version diff and an approval request list each setting a deploy changes, from what to what, grouped by what it does to the running pipeline (restart, first copy, next copy, starts over), heaviest first.
- **Engine settings in Review** - Expert mode gets an Engine settings card: typed settings grouped by when they matter, each with its bounds, default and what changing it does, and advanced Debezium properties as one row per key, each checked by the server as you type (with the reason and where to set it instead when refused, or the offer to use the typed setting).
- **Typed engine settings** - a pipeline spec takes `tuning`: settings from BeziSync's registry, each checked against the pipeline's engine, source and destination and its bounds, and carried by YAML, the API and MCP. The first ones: snapshot threads and the poll interval (Debezium), the connection pool (Flink CDC). `GET /engines` lists every setting with what changing it does to a running pipeline, and preflight and the version diff list the settings a deploy changes with that impact (`settings_change`).
- **A project policy for advanced Debezium properties** - Admins decide whether pipelines may pass raw properties (Settings → Policies, *Allow advanced properties*); without it their deploy is blocked. Upgrading turns it on for every project that already has a pipeline using them, with an audit entry.

### Changed
- **Unknown checks** - preflight checks BeziSync can't verify are now *Unknown*: grey, never shown as passed. Advanced properties that are allowed show as one, listing each key.
- **Images** - the `bezisync` and `bezisync-web` images leave out the source tree's `README.md` files (the new per-directory contracts for contributors); nothing they run changes.

### Fixed
- **Review stops re-saving a change the server refused** - when a save is refused (a property BeziSync doesn't allow, a setting only the server checks, someone else's edit, a network error), Review & deploy shows why and waits: it tries again when you change something, click Try again (for network and server errors) or leave the step, instead of saving every second. A refused advanced property is caught as you type, in Guided mode too, and one an older pipeline already has still saves.
- **Review says which field to fix** - "Not saved" now names the field (**Not saved: fix Memory**, or **Memory and 2 more**) and takes you to it, and each error sits under its own field: a custom memory over the project's limit is shown under Memory, not CPU, and a Flink CDC streaming size under the streaming field it is about. In Guided mode, an engine setting or advanced property that blocks saving is listed with Remove instead of blocking unseen.
- **Keep deleted rows shows in the Transform step** - added, it used to vanish from the Transform step while still saved (and shown in Review). It now sits under Event shape on Debezium and under Keep rows on Flink CDC, can be removed, and is offered once. Where it decides deletes, the Transform step, Review, the deploy's impact, the Overview and the Destination step say so instead of showing the row shape's or the destination's own choice, and a filter added after it on Flink CDC goes before it, as the server requires.
- **A new Keep only some events filter saves** - a filter added in the Transform step without column rules was refused on save ("match needs rules"), on both engines; it now saves.
- **Advanced Debezium properties can't override BeziSync** - a raw property may no longer change a key BeziSync sets for the pipeline (where events go, tables, columns and personal-data choices, the error policy, connection and TLS details, heartbeats and signals). Credentials, values containing `${…}` or line breaks, and unsafe options (SQL on the source, dropping the slot, skipping changes, weaker TLS, loading classes, `quarkus.*`) are refused too. Saving refuses new ones with where to set them instead; ones an older pipeline already has still save, and its deploy is blocked by the new *Advanced properties* check (a forced deploy can't skip it). Adopting a Debezium Server keeps only allowed properties.
- **JDBC driver options that can read files or load code are refused** - advanced `driver.*` and `database.*` properties that read local files, deserialize or load classes, call out, log to files, or change TLS and sign-in (for example MySQL's `allowLoadLocalInfile`) are no longer passed to the source's driver.
- **Flink CDC on PostgreSQL checks replication slots for the copy** - during a first copy each reader opens its own temporary replication slot and WAL sender, so it needs 1 + readers of each; preflight only checked for one free slot, so a large pipeline could pass it and then stop part-way. The new check blocks such a deploy, with the SQL to fix it.
- **Credential-looking advanced properties are hidden** - a pipeline saved before credentials were refused as advanced properties may still hold one; preflight, the Config view and change summaries now show its value as `(hidden)` instead of in plain text (the pipeline keeps working).
- **Review settles with advanced properties in any order** - the server stores advanced properties shorter key first; Review compared them in the order they were typed, so some orders never matched and it kept saving. It now builds them in the stored order.
- **Dependency advisories** - Go modules updated past new advisories: `github.com/andybalholm/brotli` 1.2.8 (GO-2026-6888, critical), `software.sslmate.com/src/go-pkcs12` 0.7.4 (GHSA-mpwr-8vm7-h73f) and `golang.org/x/crypto` at the commit that fixes GO-2026-5932 (no tagged release has it yet).

## [v0.3.0] - 2026-11-05

### Added
- **Flink CDC engine** - pipelines into Iceberg, StarRocks, Doris and Fluss can run on Flink CDC (a JobManager and TaskManagers per pipeline on Docker or Kubernetes), with parallel first copies, schema changes applied to the destination tables and saved positions kept by BeziSync. Debezium stays the engine for every other destination; each pipeline shows its engine. Transforms on Flink CDC are filters built from rules, renames and added fields; value formats, the outbox router, flattening and custom steps stay Debezium options.
- **StarRocks, Apache Doris and Apache Fluss destinations** - on Flink CDC: one primary-key table per source table, created and kept in step with the source. StarRocks and Doris are checked, read back in the Events tab and dropped on delete, and get no source column defaults (they refuse them); Fluss is checked for reachability and its tables are kept on delete. None of the three loads over TLS: keep them on a private network.
- **Iceberg on Flink CDC** - Iceberg pipelines from MySQL, MariaDB, PostgreSQL or SQL Server can choose Flink CDC in the wizard (Debezium stays the default) over the same REST and Glue catalog connections.
- **Flink CDC settings in the wizard** - the review step sets what schema changes and new columns do, how often the position is saved (and Iceberg commits), how fresh StarRocks and Doris loads are, and in Expert mode Flink settings from a reviewed list.
- **Engine versions** - Settings → Debezium versions is now Settings → Engine versions, with a Flink CDC tab. Flink CDC stays off until an Admin registers an image they build (BeziSync publishes none; the guide lists what it holds). MySQL/MariaDB sources need MySQL Connector/J added to it.
- **Saved positions** - a Flink CDC pipeline's Positions tab lists its saved positions (encrypted in the state database) and, while paused, restores one or starts over: copy every table again, read from now, or read since a time (MySQL, SQL Server).
- **Flink CDC from scripts and agents** - manifests take `spec.engine`, `flink_cdc` settings and `flinkCdcImage`; `bezisync remote pipelines positions|restore|start-over` and the ENGINE column in `remote get`; MCP tools `list_engines`, `list_saved_positions`, `restore_saved_position`, and `from_time` on `reset_pipeline_offsets`.

### Changed
- **Helm charts 0.2.0** - the control-plane and agent charts' Roles allow Services, which a Flink CDC pipeline's TaskManagers use to reach its JobManager on Kubernetes.
