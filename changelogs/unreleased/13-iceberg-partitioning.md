type: minor

### Added
- **Partition by on Debezium** - Iceberg tables on Debezium can now be partitioned per table in the Destination step, as on Flink CDC: a column, the year/month/day/hour of a date or timestamp, buckets of a hash or the leading part, up to four fields, plus Debezium's time of the change for change logs. Tables Partition by doesn't list keep the automatic partitioning (bucket by key, day of the change), compiled as before (a pipeline with no Route step keeps its configuration).

### Changed
- **Upserted Iceberg tables are partitioned only by key columns** - rows are upserted by writing deletes on the key, and Iceberg applies a delete only to rows in its own partition, so a table partitioned by a column outside its key (an `updated_at` day, a `status`) kept the old row whenever an update changed that column. Preflight now blocks it (`iceberg_partition_key`), and the editor shows such columns disabled; for time-like layout partition by the leading part of an increasing key (`truncate[100000](id)`). **Flink CDC pipelines partitioned that way are blocked on their next deploy** (they keep running); their tables may already hold duplicate rows: find them with `SELECT <key>, count(*) FROM <table> GROUP BY <key> HAVING count(*) > 1`, and recreate the table with Start over, dropping destinations. The same check covers existing tables partitioned off their own identifier fields, on both engines.
- **Partition checks use the type the engine writes** - buckets of a true/false or floating-point value, truncating a UUID, two time transforms of one column, and columns written as lists or structures (on Debezium also PostgreSQL arrays, user-defined types and NUMERIC) are refused before the deploy instead of failing when the table is created. Decimals sent as double or text, binary sent as text and a time of day (a number on Debezium) are judged by what is written. Truncate widths go up to 1,000,000.

### Fixed
- **Routed Debezium Iceberg tables get their automatic partitioning** - the automatic partitioning (buckets of the key, the day of the change) was set under the table's name before its route, which the Iceberg build never looks up, so a table a Route step sends elsewhere was always created unpartitioned. It now follows the route; tables routed to one destination share it when they agree. **Routed Debezium Iceberg pipelines restart once on upgrade**; tables they create afterwards are partitioned, existing ones keep their partitioning.
- **Iceberg checks no longer pass when the catalog can't be read** - an access or network error reading a destination table counted as "the table doesn't exist yet", so the existing-table partitioning check passed; it now warns.
- **Renamed or left-out key columns on Debezium Iceberg upserts** - Debezium's Iceberg build keys a table only by key columns its rows carry under the same name, so a key column renamed or left out narrowed the table's identity and upserts replaced rows sharing the rest of the key. Preflight blocks it (`iceberg_key_columns`), and warns when no key column is left (the table is appended).

Rollback: an older BeziSync refuses Partition by on Debezium and its controller skips such a pipeline; remove Partition by from Debezium pipelines before rolling back.
